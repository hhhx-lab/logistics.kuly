# 《一张单据的旅程》｜剪辑、界面合成与首页交付规范

> 上游文件：[创意总案与统一提示词](01_创意总案与统一提示词.md)；[28 秒分镜与逐镜提示词](02_28秒分镜与逐镜提示词.md)；[角色道具参考帧与界面合成提示词](04_角色道具参考帧与界面合成提示词.md)。本文把 7 段生成人像与实景素材变成能在首页播放的广告短片。现阶段仍是制作方案，没有生成或嵌入视频。

## 1. 推荐制作顺序

1. **锁故事板与样票**：确认路线、货物、角色、蓝折角、七镜动作。制作一份完全虚构的商业发票样稿，以及与其一致的装箱单/运输资料外观；所有实际可读编号、公司名和联系方式都用虚构数据。单据样稿要能支持录制产品界面中的疑点和复核结果。
2. **先做连续性参考图**：按 04 文件的提示词锁定发票、汉堡桌面、货运办公室、海面、上海审核桌、道路和苏州收货台；文字卡记录演员服装、纸张折角与光线方向。只使用自制的无真人脸参考物料，不把真实员工照片作为 AI 生成输入。
3. **逐镜生成**：直接复制 02 文件各镜的自包含英文提示词，每镜 4 秒、16:9 独立生成。人物镜先确认脸和手，再做船、车辆环境镜；每镜首帧和末帧对照 04 文件的交接表。只保留同一光色和纸张锚点可靠的版本；发现单一错误时用逐镜单点修复指令重做。
4. **录制真实产品 UI**：使用虚构测试账号、虚构样票，在当前项目真实页面录制对话、上传、原文译文对照、疑点处理、复核完成、管理台查阅。若某个 UI 动作尚未真实可用，重写该镜头，不画一个看似上线的假按钮。
5. **先剪无字版**：7 段按时间轴拼接，检查方向和动作匹配；只使用直切、轻量纸边擦镜，确定 28 秒观感后再加入屏幕、字幕、音乐和结尾卡。
6. **合成与调色**：屏幕跟踪到笔记本/平板四角，轻微反光与真实暗角保留；字幕和 Logo 单独作为平面图层。做统一肤色与港口海蓝，声音不盖过旁白。
7. **导出并看两遍**：一次静音看能否独立理解，另一次有声看旁白、转场和字幕是否抢时；在浏览器真实首页尺寸检查裁切、加载、循环与停播。

## 2. UI 合成表：每镜究竟出现什么

产品界面必须来自项目真实可运行页面或准确复刻其视觉系统的后期图层，不直接让视频模型生成文字。画面只保留观众 1–2 秒能读完的信息。

| 镜头 | 可叠加的 UI／字幕 | 故事事实与操作约束 |
| --- | --- | --- |
| 01 | 对话输入：`请把这票商业发票译成中文，并核对收货人和数量`；附件卡一张 | 只展示上传与发起，清楚是**已有样稿**；不要一点击就出现“已正式导出”。 |
| 02 | 左侧识别原文、右侧纯中文译文；疑点 `收货人地址待核对` → 点击核对 → `已人工确认` | 同一虚构样票数据；红黄问题只由真实复核流程变更状态。鼠标操作位置要与产品按钮一致。 |
| 03 | 对话问题 `这票货发往哪里？`；摘要 `汉堡 → 上海 → 苏州`；来源入口 `商业发票／装箱单` | Lin 在自己有权的业务空间查看被传递的资料；不表示跨组织账户自动共享上下文。可用更真实的授权文件导入画面替代跨账户传递。 |
| 04 | 后期路线线条 `汉堡 → 上海`；不显示产品界面 | 线路示意不伪装为实时追踪；航线位置可为示意。 |
| 05 | 平板 `原文与译文`、`疑点`、`已人工确认`、`复核完成`；地点小标签 `上海口岸 · 单证核验（情景演示）` | Mei 看到的是口岸岗位有权取得的资料，在独立审核记录单上签名。仅展示单证辅助审核，不展示“海关已批准”的产品消息。 |
| 06 | 字幕 `流程向前，记录可追。` | 货车正常出港的转场；不要给软件加审批或放行能力。 |
| 07 | `商业发票 · 中文译本`、`原件／译本／处理记录`；结束卡文案和 CTA | Zhou 在独立纸质收货单上签字；应用里没有“自动代签”动作。 |

**屏幕合成工艺**：生成素材中的屏幕用低对比中性占位；后期采用四点透视追踪贴入竖/横对应的真实录屏，不放长篇正文。保留约 10–15% 环境反光与屏幕边框，不做悬浮卡片跳出实体设备。红色只给确需处理的疑点，黄色给提醒，蓝色给选中来源。中文小字先按设计稿渲染再进视频，不用生成器输出。

**关于权限和多岗位**：故事表达“同一份业务资料能在不同节点被理解”，不是宣称产品已经支持跨公司 Case 自动共享。各镜头使用各组织各自有权的工作空间、收取的资料副本或脱敏演示账号；片中不能出现货运员一键读到发货人私有会话历史的画面。

## 3. 逐秒声音与字幕节奏

| 时间 | 主声轨建议 | 画面字幕／声音处理 |
| --- | --- | --- |
| 00:00–00:04 | 纸张摩擦、触控板轻点；旁白：`一张单据，从发货人的桌前出发。` | 0.8 秒后入字，3.5 秒前退字。 |
| 00:04–00:08 | 一下轻微确认提示音，笔和文件夹声；旁白停顿 | `识别疑点，人工确认。` 置于不遮挡纸面的安全区。 |
| 00:08–00:12 | 远处港区低声环境；旁白：`识别、翻译、核对，让交接更明白。` | `交接的人，读懂同一票。`；产品回答不要整屏铺满。 |
| 00:12–00:16 | 音乐扩展、海风、远处船声；不说话 | `跨越语言，也跨越海洋。` |
| 00:16–00:20 | 室内笔尖落纸与港口低频；旁白：`抵达口岸，人工复核有据可查。` | `原文、译文、疑点，逐项可查。` |
| 00:20–00:24 | 车辆轻驶、音乐向结束和声；旁白停顿 | `流程向前，记录可追。` |
| 00:24–00:28 | 签收纸张声；旁白：`收货时，来龙去脉也看得清楚。` | 26.7 秒起出最终品牌卡；音乐 27.5 秒自然收束。 |

若 28 秒内完整旁白读得过快，**优先删掉画面字幕的一部分重复信息或缩短旁白**，不加速人声。旁白与字幕不必逐字相同；静音版必须只靠画面和短字幕读懂。背景音乐需原创或取得可用于网站和广告的授权，不沿用生成工具默认的受版权限制音乐。

## 4. 首页播放和最终资产

| 资产 | 建议规格 | 用途 |
| --- | --- | --- |
| 主视频 | 28 秒；16:9；1920×1080；24 fps；H.264 MP4；音频单独混入有声版 | 宣发、展示页与线下播放。必要时导出 WebM 兼容版本。 |
| 首页轻量视频 | 同片 1280×720；H.264 MP4；建议通过内容感知压缩后控制约 8 MB 以内，以实测画质为准 | 首页首屏静音自动播放，低带宽优先取此版。 |
| 竖屏安全裁切 | 1080×1920 单独重排字幕和 UI；不直接把 16:9 中间裁成竖屏 | 后续社媒渠道。原片所有关键人脸和单据应尽量保留在中心安全区域。 |
| 海报帧 | 从镜头 05 或 07 选清晰实拍帧，16:9；压缩 WebP/JPEG | 首屏加载前显示，不能把生成图伪装为真实产品功能。 |
| 字幕与旁白稿 | 可编辑字幕文件、配音文本与时间码 | 便于修改文案和做静音首页版本。 |
| 源素材 | 每镜原始视频、真实产品录屏、UI 图层、音效、音乐授权证明、剪辑工程 | 后续版本可改字、换界面、重调色，不必重新生成全片。 |

**首页交互建议**：视频默认静音、行内播放、可暂停、可重播；浏览器拒绝自动播放时保持海报帧。循环播放时结尾卡与开场之间做短暂颜色与纸张形状呼应，避免突然黑场。为 `prefers-reduced-motion` 用户默认展示海报和主动播放按钮。封面区域有可读标题和普通 HTML CTA，按钮可去产品实际的对话工作台；视频字幕不承担唯一的信息表达。移动窄屏优先展示海报、点击播放完整视频，不让首屏被 28 秒素材阻塞。

**首屏文案建议**：标题 `让单据流转更清楚`；副文案 `对话发起识别与翻译，逐项复核后再交付。`；按钮 `体验单据翻译与校验`。不要写“自动通关”“零错误”“替代人工审单”“官方指定工具”。

## 5. 验收清单

### 叙事与连续性

- [ ] 七镜合计 28 秒；德国到中国的方向、光线和货物类型一致。
- [ ] 蓝折角、A4 比例、透明夹在每个关键镜头可以辨认为同一份样稿；没有纸张无支撑悬浮。
- [ ] 四个人物角色、服装、动作各自稳定；每镜手部和纸张没有畸变或多余重复件。
- [ ] 发货人复核疑点、运输人读懂单票、口岸人员对照并人工记录、收货人签独立收货单都在画面中发生。
- [ ] 货车出港是独立的正常通关业务转场，画面和字幕都没有表达“AI 自动放行”。

### 画面与产品真实性

- [ ] 电脑／平板显示真实项目的对话、原译对照、疑点、复核、历史查阅；透视、手指点击位置、状态顺序正确。
- [ ] 任一角色只看到自己有权的资料副本；不演示尚未上线的跨企业自动记忆共享。
- [ ] 文字、编号、品牌和 UI 均为后期可编辑图层，无乱码、伪造海关标识、真实个人信息或真实商业敏感数据。
- [ ] 中文译文侧只有目标语言文本；“双语”作为可切换预览而不充当正式译本；疑点解决后才展示复核完成。
- [ ] 没有官方合作、认证、保证通关、自动签发原件或产品内电子签收的误导暗示。

### 首页体验

- [ ] 静音播放首看能理解四段接力，字幕不会在窄屏被裁掉。
- [ ] 视频未加载时有海报，自动播放失败有显式播放入口，暂停和重播可用。
- [ ] 减少动态效果模式不自动播放，主标题和 CTA 不依赖视频可访问。
- [ ] MP4 在目标浏览器播放流畅，循环没有黑帧和明显声音跳变；网页实际加载与清晰度满足团队验收。

## 6. 素材命名与版本管理建议

仅在开始实际生产后建立 `source/`、`ui/`、`audio/`、`edit/`、`deliver/` 子目录；现在先保持本文件夹只存可编辑 Markdown。每镜素材建议采用 `shot01_hamburg_exporter_v01.mp4` 这种名称；后期 UI 录屏另存，成片以 `document-journey_home_28s_16x9_v01.mp4` 命名。改人物、道具或镜头时递增素材版；只改字幕、界面或声音时递增剪辑版，避免把不同版本混用。
