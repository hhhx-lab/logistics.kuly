日期：2026-10-14。用途：X0–X6开发与独立验收；样本已经生成，整套样本的业务验收与准确率评测尚未完成。逐票真实执行的最新结果以[专项实施台账](../开发记录/后端/同票核对专项实施台账_X0至X6.md)为准，单票进入待复核状态不等于已成功导出。本文件不能作为供应商OCR精度、官方单证版式或法律审核完成的证明。

## 1. 材料与真值

[样本目录](assets/同票多单证合成样本)共有12票、36份主材料，覆盖商业发票、装箱单、提单、报关单及公路运单；中、英、法、西、俄五语；原生PDF、扫描图片、DOCX和混合多页PDF。PDF包含网格、框式抬头、横线布局三种基本版式；DOCX有真实货物表格。36份全部是项目自行构造的合成资料，无官方签发、真实客户或业务信息。

[sample_set.json](assets/同票多单证合成样本/sample_set.json)保存类型、语言、字段、货物行、scope、源位置、文件SHA256与集合划分。C01–C08为开发集，C09–C12为保留验收集。开发时不要针对验收集的固定值写特殊判断；调试使用过保留集时必须在结果中说明，后续另补真正独立样本。

PDF期望位置来自生成时页面坐标；图片采用同一页面无旋转渲染，保留页面归一坐标；DOCX只有段落／表格单元格位置，不编造页码。扫描模糊程度是人为扰动，OCR实际识别结果要通过真实服务再记录。`expected_anchors`是人工可核对的输入真值，不是系统已生成锚点。

每张主要单证均有明确SKU、规格、批号和运输参考，数据采用值默认未人工确认。测试关联时需要按各场景显式确认货物、阶段和范围；上传不代表这些关系已获证实。

## 4. 可重复生成与输入检查

使用项目既有Python环境与已安装的字体，不安装任何新依赖：

```bash
src/backend/.venv/bin/python scripts/generate-consignment-samples.py \
  --font '/Library/Fonts/Arial Unicode.ttf'
```

维护工具在[scripts/generate-consignment-samples.py](../../scripts/generate-consignment-samples.py)。`--font`可指向本机已有且覆盖中文／西里尔字形的TTF。重新生成后必须核验文件SHA、PDF可读性、页数、表格结构、DOCX单元格和PNG尺寸。工具不发网络请求，不运行OCR或模型。

## 5. 正式规则发布门槛

本轮已实现`ReviewedRulePublication`本地证据一致性发布门禁。目前仅注册`kind=hs_description_candidate`，用于已审核窄词组范围内的黄色HS核对候选，不代表证书义务规则已正式发布。只有`publication_status=approved`、尚未到期、来源HTTPS主机精确匹配管理员配置的`RULE_OFFICIAL_DOMAINS`时，才在`RULE_EVIDENCE_DIRECTORY`内读取原文及审核JSON；路径须在目录内、文件非空且有界。原文SHA与审核JSON的SHA都要匹配声明。

审核JSON必须是对象，并逐项绑定`version`、`kind`、`reviewed_by`、`review_reference`、`source_url`、`source_sha256`、`destination_country`、`commodity`、`valid_from`、`valid_before`、`descriptions`、`allowed_six_digit_codes`和`decision=approved`，且含非空字符串`reviewer_qualification_reference`。规则白名单不能在已审核原文／记录不变时偷换。资料缺失、pending／withdrawn、过期、错误SHA、范围或定义不一致均不会进入新Run的发布冻结列表。冻结仅保留版本、摘要等可核对声明，移除两个服务器证据文件路径。

该门禁证明本地文件、哈希、审核声明和规则定义一致，不自动证明原文确实从该官网取得、审核人身份／资格真实、审核意见正确或具有法律效力；没有在线原文比对与专业资格认证。官方主机列表是管理员配置，不是系统自动认定。测试使用`tmp_path`及明确合成证据，不配置为生产规则。

撤回阻止后续任务冻结，导出前检也检查运行时配置中明确撤回的同版本规则及冻结依据的到期日：出现撤回或到期时须以当前依据新建任务再交付。这是技术依赖门禁，不把黄色法律风险变成假红项。历史快照和旧Run输入保留原样；目前没有跨进程实时撤回广播，修改部署配置后需重启服务才能生效。

正式发布至少要有：已核验官方来源原文、对应内容摘要／哈希或可复核快照、版本／生效与撤回日期、精确目的国／货类／批次适用条件、真实专业审核人的审核记录、修改／撤回记录。无此输入保持未发布／pending；默认空发布列表不能替换成假审核示例。法律审核不能由模型或本组合成样本代替。

鲜苹果试行包的2026-10-15是项目复核窗口，不能直接当法律有效期，也不能仅延长日期继续宣传已生效。X5法律范围验收仍需真实专业审核资料。

## 6. 实际已做与限制

2026-10-14已完成文件生成、固定真值和场景清单。输入检查通过：26份PDF共28页全部有可抽取文本和合成标识，检出29张实际表格；8份DOCX均含真实表格；2份PNG尺寸符合检查；36份SHA及全部期望坐标范围一致。C11本地原生解析已确认为发票／箱单两份逻辑单据，并人工检查其第二页预览无明显缺字或越界。材料结构检查与真实业务联调分开记录。此前X1纯函数及解析定向测试45项通过，后续Worker抽取闭包／扩展字段保存5项定向测试通过。发布与审计定向测试20项通过，覆盖合法一致证据、来源／审核SHA篡改、未审定规则白名单修改、目录越界、错误JSON、资格引用类型和pending／withdrawn／过期等；这些结果不等于官方原文真实性或专业资格认证，也不等于36份材料的OCR、模型、关联和导出全链路通过。

该最小合成集未覆盖所有官方版式、危险品许可、能源计量、签章与条码，也不代表生产95%准确率。公布准确率必须逐字段、逐版式区分原生／扫描样本，记录错误／拒判和数据来源。无错样本数不等于生产100%正确。

格式覆盖也不等于全部类型／格式交叉组合经过验收：当前主材料包含14份发票类、9份箱单类、9份提单、3份报关单和1份公路运单；混合PDF内的逻辑单据另按解析结果核对。尚无空运或快递实际样本，也没有每种核心类型的三份独立官方版式。C09–C12是计划保留的合成验收集，仍须逐项真实运行并说明是否曾用于开发调试。

X6的EDI模块仅在代码层提供单个不含`UNG/UNE`功能组的interchange、单个`IFTMIN:D:01B:UN`、`UNOA/UNOB/UNOC`语法版本3的有界原始段阅读，以及转义、消息／交换计数和引用检查。原始段与字符范围必须直接对应输入切片，段结束符前的空白仍保留在原始段中；本次修复该空白情况下的定位偏差后，EDI定向6项通过，其他18项未重复运行。定位是字符范围，尚无原始字节范围、元素定位对象、`NAD/LOC/RFF/GID/MEA`业务限定符映射或阅读视图。字符集标识已限范围，但尚未完成对应字符集字符表和全部服务字符语义的官方核验；不得称为完整标准合法性验证。该模块没有注册上传MIME、解析选路、工作流、API或导出，因此不能用语法单测代替A18要求的跨格式业务闭环。
