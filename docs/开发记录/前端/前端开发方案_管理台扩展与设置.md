2026-10-08 导出契约：交付物是当前确认版本的纯目标语言译本（所选 DOCX/PDF），可选各原件的识别稿 PDF；不生成复核报告。识别稿从冻结 ParseArtifact 的原文与布局生成，不冒充 MinerU 供应商原始 PDF。一个 Run 对应一个目标语言；其他语言使用各自 Run/确认/快照独立导出，当前不提供多语言一键批量翻译或导出。旧成功快照含报告只作接口兼容，不再展示报告下载；旧失败报告清单在原 Attempt 安全重试时升级为译本与识别稿，历史失败事件保留。

## 1. 文件组织、路由与共同数据规则

保留 `/documents`、`/extensions`，在 `App.tsx` 增加 `/documents/cases/:case_id`、`/settings`、`/settings/memory`；`/review` 仍由方案二统一承载。`pages/ManagementPage.tsx` 拼装 `features/management/{StatusTabs,FilterBar,RunList,RunDetails,CaseOverview,CaseDeletionDialog,UploadDrafts,DeliveryGroup,OpsRunDrawer}`；`pages/ExtensionsPage.tsx` 拼装 `features/extensions/{ExtensionList,SkillEditor,McpConnectionWizard,ToolGrantList,CallHistory}`；`pages/SettingsPage.tsx` 拼装 `features/settings/{PreferenceForm,MemoryList,MemorySuggestionList,DataBoundaryCards}`。`api/management.ts`、`api/ops.ts`、`api/extensions.ts`、`api/preferences.ts` 只封装生成类型的请求，不自行解释权限或构造业务状态。运行核查是管理台当前 Run 时间线上的抽屉，不增加主导航或第六个页面。通用 `openEvidence`、`UploadWizard`、`Idempotency-Key`、受控下载和身份清理直接复用前两方案，不再复制实现。

这三个页面只把查询响应存 TanStack Query，页面局部存筛选草稿、当前展开 Run ID、浮层开合、滚动锚点与未提交表单。查询键包含身份世代、精确筛选、Case/Run ID 和被查看的 Snapshot ID。列表旧页不能被新筛选的慢响应覆盖；切身份先取消请求、清 Query/表单/Blob，再渲染新身份骨架屏。URL 只允许受控 ID、页签、排序和非敏感筛选键；用户在搜索框输入的姓名、地址、文件名或单号可能敏感，保留在当前身份内存，不写持久浏览器存储、分析日志或可分享 URL。所有导出、原件、摘要、扩展调用记录即使前端曾缓存，也要在每次服务端读取时重新鉴权。

## 2. 管理台：一 Run 一行与历史版本固定

`ManagementPage` 的标题、状态页签、筛选、表头固定，列表独立滚动。1440 px 主区按[管理页面设计](前端页面设计_单据管理台.md)第 6 节的 1144 px 表格基线排；不足先折导航，再改一列批次卡，不隐藏风险、版本和“查看本次”。每行绑定一个 `ManagedRunRow.run_id`，**绝不按文件数或 ExecutionEpoch 展成多条 Run 行**。`displayed_snapshot_id` 是该行这次查询实际显示的成功快照，可能不是最新成功快照；`current_work_status`、`has_successful_snapshot` 与 `latest_export_attempt_*` 分开显示。最近 Attempt 失败而 Run 已回 `ready_to_export` 时，主行仍写“上次导出失败／可按服务端许可重试”，不能只在展开区才发现；成功快照卡只从 R16 渲染，未有成功快照的 Run 不生成假“转换后文件”。

| 控件和行为 | 查询／命令 | 前端需要保持的语义 |
| --- | --- | --- |
| 页签与计数 | M02 授权 facets；“上传草稿”改读 U03，其余读 M01 | 默认“已导出”；同 Run 可同时在“已导出”和“待复核”出现。最近 Attempt 失败且 Run 为 `ready_to_export` 时还在“失败与取消”页签可发现，也可在“待复核与可导出”出现；计数不互斥，U03 槽不是 Run。 |
| 标题“新建处理” | C01 新会话，再复用方案一 UploadWizard | 只打开归票与上传入口，不直接建 Run；取消向导不会留下假处理记录。 |
| 手动刷新／更新提示 | M01/M02/M03/M04/M05 按当前可见资源重取；可见 Run 的 W04 事件只提示“有更新” | 保留筛选、cursor 和滚动锚点，用户主动刷新后再重新排序；不能在第 3 页自动插入新行。 |
| 批次箭头或空白 | 只改变本地展开 ID；首次展开取 M04/M05、必要时 R16 | 展开和“查看本次”是两个可访问性目标；行身不隐式开校验。 |

| “查看交付”／“查看当前版” | 前者展开该行 R16 成功快照产物分组；后者明确以 W04 当前版重开 R01/R02 | 交付只列成功 Snapshot；切当前版不改主行 `displayed_snapshot_id` 或历史筛选结果。 |
| “重新处理” | 预选 Case 和用户明确勾选的 SourceVersion，进 W02 | 目标语言／范围／格式重新确认后 W03 建新 Run；不会复用旧 Run 的冻结 Task Spec。 |

| 时间线“运行核查” | M05 授权事件或 W04 给受控 `step_execution_id/ops_reconcile_step_id` 时开放 O01 核查分区；O02 迁移分区使用当前行的真实 Run ID，先 GET 选项 | 仅 `ops_reconcile` 可见有受控步骤 ID 的核查入口；仅 `ops_migrate_model` 可见 Run 级迁移入口。普通用户只看待核查说明，不显示步骤 ID、操作按钮或迁移配置。 |

`RunDetails` 的“参与原件”一份物理 `DocumentVersion` 一行，文件行左箭头展开 `LogicalDocument → DocumentSection`，文件名／“查看原件”才开方案二快速侧板。混合 PDF 可以有发票与箱单两个内部逻辑单据，但交付区仍只按这一份物理文件列所选格式的译本。M04 返回本次 Run 及 `Run × DocumentVersion` 简短摘要，逐文件显示 `ready/stale/failed`、版本、来源和最多三行概况；`stale` 显“更新中／过期”，不可作为当前事实。摘要字段可点击时带来源目标经 R01/R03 回查，不能从摘要直接生成已核验答复。若主行是历史快照，先用 R16 所示原件／解析／业务／译文冻结版画文件和交付，**仅当 M04 摘要的版本与所示快照一致才显示该摘要**；否则显示“当前摘要不适用于这份历史交付”并给只读来源入口，不把当前新字段写进旧行。

文件行“询问这张单据”在新会话同时表达固定原件和该历史行快照：C01 `initial_reference_selections[]` 一次预置 fixed Snapshot 与其中的 fixed DocumentVersion 两枚同票标签，服务端持久保存，刷新后从 C01/C02 恢复；输入区旁写“历史版本：该快照；默认只问这张物理源文件”。Snapshot 确定版本上下文，Document 标签收窄默认事实范围；只有用户明确要求同票对比时，才可在该冻结快照内查看其他参与文件。C04 发送时再按两个 `ReferenceSelection` 重新鉴权、冻结，并核对原件确在快照内。未导出行预置 fixed DocumentVersion，若用户明确要问本次处理可同时预置同票 Run 当前指针；这不会暗示已有交付。不能用文件名或最新快照代替所示版本。打开文件原件时带当前行的 `displayed_snapshot_id` 与 Snapshot manifest 对应解析版；未解析文件最低传 Case＋DocumentVersion，R01 返回 `source_only`。

文件行“复制文件信息”只调用浏览器剪贴板 API 复制当前授权可见的文件名、DocumentVersion 和 Run 短号；拒绝权限时原位提示，绝不复制原文全文、对象存储路径或签名 URL。表头排序按钮只在 M01 支持的字段显示，点击把排序键和方向交给服务端并清 cursor；前端不对当前游标页做局部排序冒充全局顺序。日期快捷键“近 7 天／近 30 天”只填本地日期草稿，提交时仍只发送本地日期字符串，由服务端按 P01 时区解释。

交付分组以 R16 的 `source_artifacts[]` 逐原件列 DOCX/PDF、哈希短值、生成时间、冻结版本，最后**一次**列 `case_report_artifact`。预览历史正式文件只能以受控 artifact/R01 快照只读打开；下载用同源 `GET /export-artifacts/{artifact_id}/content` 原生下载或 Range，每次鉴权，不把 MinIO 地址、永久对象存储 URL 或临时文件放进 HTML。`snapshots` 列表从 R16 分页读取，历史旧版靠显式“查看该快照”切目标；筛选命中的快照仍是主行默认展示，不因展开、悬停或下载被改。失败导出尝试由展开行 W04 的 `latest_export_attempt_id` 再读 R15 attempt，只有 `allowed_actions` 允许才显示“重试这次导出”；Run 回 `ready_to_export` 不等于失败尝试消失，也不能重新发一次 `/exports` 绕开旧尝试。`Timeline` 用 M05 的 RunEvent seq 分页，上传人、Run 发起人、复核确认人、导出确认人及各时间来自相应记录，不把单证上的 Shipper/Consignee 当系统处理人；收费外部请求待核查对普通用户只展示受控说明，获授权操作者在同条时间线打开第 2.3 节抽屉。

### 2.1 筛选状态与请求编排

`FilterBar` 维护类型化 `ManagementFilter`（页签、日期角色及本地起止日、来源地角色和值、收件人角色和值、处理人角色和值、单据类型／物理格式、语言、风险、版本范围、匹配范围、仅确认值、排序、搜索字串）。提交后将其规范化为 M01/M02 的 `date_type + local_date_from/local_date_to`（闭区间，`YYYY-MM-DD`）及其他查询参数，维度之间 AND、同维多选 OR；任何条件变化清 cursor、取消前一请求、重新拉 M02 授权选项与 M01 首页。**前端不换算 UTC 边界**：服务端按当前本人 P01 时区统一转为 UTC 左闭右开区间。切时区后保留日期输入值、立刻重新查询并提示匹配口径已变。短防抖搜索结果只显示当前查询标识对应响应；旧响应可留作灰色“正在更新”占位但不能冒充新匹配。长列表只用服务端游标和稳定排序，前端不在当前页对全量数据自行二次筛选。

| 筛选项 | UI 值、服务端匹配与结果解释 |
| --- | --- |
| 状态、时间 | 默认已导出、按**最新成功快照**导出时间倒序；日期可切上传／发起／最近活动／复核，表头写明命中时刻。仅切“包含历史快照”后才按条件取最近**命中** Snapshot，此时可能不是最新成功；“失败与取消”包含最近 ExportAttempt 失败而当前 Run `ready_to_export` 的记录，页签非互斥。 |
| 来源地 | 先选“起运地／承运人接货地／装货港／原产国地区”角色再填值；不从发货人地址推断，结果列角色、原文／规范值与区段。 |
| 收件人、处理人 | Consignee／Buyer／Notify Party 与发起人／复核人／导出确认人两组独立下拉；处理人只匹配登录身份，不查正文姓名。 |
| 类型、格式、语言、风险 | LogicalDocument 类型与物理 MIME 分层；语言属 Run／Snapshot，风险属所选版；多选同维 OR。未覆盖／无法判断不作为“无风险”吞掉。 |
| 版本范围 | 默认当前结果；“包含历史快照”允许旧版命中，M01 给 `displayed_snapshot_id`，点击、询问、原件与下载全沿该版。 |
| 匹配范围 | 默认“同一逻辑单据”；地点、收件人、类型及相关文件名／上传日期须同一 LogicalDocument 及其源文件满足。用户显式切“同一批次任意文件”才可分文件命中。 |
| 仅已确认值、模糊搜索 | 开启时服务端仅取已确认字段；关闭时可命中候选但标“候选／待复核”。文件名、编号、短摘要只在授权与结构化过滤后模糊匹配，摘要不作答案事实。 |

M01 的 `matched_sources[]` 渲染在命中说明弹层：逐条件列文件版、逻辑单据／区段、字段角色、候选或确认状态和 R01 目标。前端不自己把文件 A 的地点与文件 B 的收件人拼成“同一单据匹配”。搜索建议来自 C08 的有权候选与 M01 已授权结果，先精确 Case／单号／文件，再短摘要；建议最多显示页面设计约定的 8 条，迟到响应必须丢弃。筛选清除键逐条件删除，重置回默认页签口径；“从未有记录”“当前筛选无结果”“摘要索引更新中”分别用 U01/W01 入口、清条件和元数据列表说明。所有总数由 M02，不能显示另一用户记录数。

“上传草稿”页签独立 U03：按 UploadSession 显示每文件 `pending/uploading/received/verified/failed/cancelled`、持久确认字节、错误和归票 Case；可见会话先读 `last_seq` 再订 U04。刷新丢失本地 File 对象时仅显示“待核验／请重新选择”，不恢复旧 XHR 百分比；失败槽用 U06 retry 领取新签名 PUT、重新选择文件传字节，再用 U05 验收，取消仅取消上传槽，不删除已有原件。需要开始处理时显式选择 verified 文件回 W02；U03 永不改写成一条虚构 Run。

### 2.2 单票概览、缓存和返回

`CaseOverview` 先 M03 读原件目录、当前业务版、所有 Run 时间线索引、Issue 和成功快照；深层文件、Issue、RunEvent 分别按 R03/M05/R16 分页。右侧“在新对话询问”用 C01 预置 Case 当前指针；从具体快照点“询问这版”预置 fixed Snapshot。原件不同 Run 仅引用同一 SourceVersion，不复制文件数据。新旧业务版、不同目标语言 Run 和成功快照分别成组，不能把新字段放进旧译本卡。对话“查看管理记录”带 Case／Run／Snapshot 受控 ID；若当前筛选不包含该 Run，直接落单票概览并高亮其时间线条目，给“清筛选后在列表显示”入口，不以文件名查错行。

M03 的 `retention_expires_at` 按 P01 时区格式化，标“保留至”，不以本地时间延长期限。仅 `allowed_actions` 含 `delete_case` 时显示“更多 → 删除这票”；打开 `CaseDeletionDialog` 才 GET M06 预览，让用户核对这票的原件版、Run 和成功快照数量，并输入 Case 短号。提交 M06 带预览的 `expected_case_version` 与稳定幂等键；网络未知结果用同键重试或凭回执查询，不能换键再次提交。`CASE_CHANGED` 时保留弹层、清空确认输入并重新 GET 预览；`202` 后立即移除该 Case 的列表／概览／侧栏／对话引用 Query，清对应 Composer 标签与 Blob，返回列表并以 `deletion_id` 查询不含内容的清理状态。后端在 `deleting` 即拒绝旧 Range、SSE 与深链，前端不拿旧缓存兜底；清理失败仍显示受限状态，不恢复票据。到期自动删除使同一 Case 从列表消失；正在编辑的复核或对话页面收到受限错误后丢弃该票本地正文草稿并返回安全空态，其他票与已确认的通用用户偏好不受影响。

`ManagementViewState` 只在当前身份内存保存 filter、cursor 路径、展开 Run/文件、当前所示快照和首个可见行 ID；从复核侧板／对话返回按 ID 与锚点恢复，不靠旧像素偏移。版本事件只使当前 Run 行与 M04 摘要失效；已打开的历史快照查询继续以 Snapshot ID 命名，若权限撤销或留存终止，清缓存并在原位给受限占位。`403/404` 不从旧 Query 显示姓名、摘要或计数；M01 分页断流可重试该页，下载失败只重读 artifact，不调用 R15。定向验收：一票三文件一行、多语言第二 Run、修订后历史快照仍固定、同逻辑单据和同批次筛选差异可解释、未解析原件可开、另一用户同名文件不在建议/计数/Blob 中。

### 2.3 Run 时间线的运行核查抽屉

`OpsRunDrawer` 只附着在管理台当前 Run 的 M05 时间线，不进入左导航，也不改列表路由、筛选或历史快照。时间线读到 `paused_reconcile` 时，普通用户只见“外部请求待核查”、发生时间和可公开的处理说明；不接收或显示步骤 ID、请求键、外部任务详情、四种裁决与模型配置。操作者须有 S03 `permissions` 中的相应权限：O01 还必须从 W04/M05 授权响应取得受控 `ops_reconcile_step_id/step_execution_id`，O02 使用该时间线所在的真实 `run_id` 并重新由服务端判定能否迁移。前端权限只控制呈现，O01/O02 每次 GET/POST 仍由服务端重验；403 后立即关闭抽屉、清除该 Run 的运营 Query 与未提交表单，不回显旧数据。

入口位于时间线：待核查事件右端的“运行核查”按钮只供有 `ops_reconcile` 权限且拿到受控步骤 ID 者；Run 时间线标题行的“迁移模型”按钮只供有 `ops_migrate_model` 权限者，打开后默认迁移分区。两者共用宽 520–600 px 的右侧抽屉，标题固定显示 Run 短号、当前阶段和“运营操作”，内容独立滚动，底部固定提交区。窄屏改全屏层，Esc 先关闭确认层，再处理未保存表单提示，最后关闭抽屉；关闭后焦点回对应入口，列表筛选、展开行和滚动不动。有两种权限时用“外部请求核查／迁移模型”两个标签；仅有一种权限时只显示有权分区，另一分区及其 API 不预取。颜色沿管理台状态 token，风险裁决同时附文字，不以红黄颜色替代结果。任一分区的数据都只在打开后按需 GET，切身份立即取消请求并清理。

## 3. Skill/MCP 仓库：受控版本、真实连接与对话调用

`ExtensionsPage` 按页面设计用标题操作、类型/状态/搜索筛选、列表和约 440 px 详情板；约 560 px 向导层放新建/导入。详情、列表分别滚动，窄屏详情全屏。E01 读本人有权的内置 Skill、自建 Skill、MCP 连接和脱敏调用记录；条目行点主体仅开详情，行尾按钮才发启停命令。内置“单据任务路由”只读，编辑、停用、归档控件不渲染；自建条目不能占用内置标识。`/ ` 的实际候选只从 C09 读，不把 E01 列表或浏览器本地开关推成“可调用”。任何启停、工具 grant、schema 变化后失效 C09；既插入 Composer 的标签按返回版本／schema 哈希变不可用，但用户原问题文本和 `@ `标签保持。

### 3.3 与 `/ `、`@ ` 和一次性外发卡的联动

启用后 C09 按“内置／自建 Skill／MCP 工具”给注册 ID、版本、schema hash、作用范围、连接状态和不可用原因；方案一的 Lexical 标签保存这些稳定字段。用户再通过 `@ `选择 Case/Run/文件/快照时，C04 服务端先鉴权并冻结该票版本，再验证扩展授权；前端仅显示这个顺序，不能自行扩大引用范围。没有授权目标的历史单证问题不能由扩展按文件名猜票。内置路由始终走项目 W02/W03，外部工具不可替代校验、修订与 R14/R15 门禁。

若本次 MCP 调用需外发敏感本票字段，C05 工具状态给 challenge ID 后由方案一的对话页 E10 取一次性授权卡：服务目标、工具、参数摘要、文件／片段、用途、数据级别、有效期与“同意本次／拒绝”。用户确认前该工具不能收到数据；确认时服务端重验所选 `@ `范围、用户、Case、连接版和 schema，拒绝只终止辅助调用，不取消核心 Run。E10 结果仍属于原 `parent_turn_id` 的续消息／调用记录，不额外造用户轮次。外部返回显示“外部资料”，若要回答本票事实必须回查结构化字段与原文来源，再生成证据卡；不能将 MCP 回复当成已审核事实。

扩展页对每个写动作和连接测试显示服务端错误类别。`403/404` 清详情和凭证占位；`409` 保留本地表单并显示配置／schema 差异；`429/503` 说明可重试时机而不自旋；对话中已选扩展变不可用时保留输入和 `@ `，阻止该调用并给“更换能力／移除标签”。只测试扩展模块对应状态机、真实握手、只读样本、schema 变化和停用联动；不为这页改动全量跑翻译端到端。

## 4. 设置与我的记忆：只管理本人确认的偏好

`SettingsPage` 顶部从 S03 显示本人身份，“界面偏好／我的记忆／会话与数据说明”作为二级导航；1440 px 用约 200 px 二级栏＋680–800 px 内容列，窄于 900 px 改顶部标签，不把敏感设置藏在悬停菜单。`/settings/memory` 直接聚焦记忆区，但仍先按身份读取。三块分别独立保留未保存表单草稿；离开页、退出或切换身份时若草稿未保存，先按本人的草稿给保留／丢弃确认；**切用户后不得把旧草稿延续到新用户**。系统策略只显示策略版本和作用边界的只读说明，完整系统 Prompt、Key、工具白名单与审核规则没有用户编辑入口。

### 4.1 界面偏好与布局联动

`PreferenceForm` 由 P01 GET 加载服务端版本；本地 `formDraft` 仅含界面说明语言、IANA 时区、快速定位侧板宽度 520–900 px、动效模式。默认值来自服务端；未返回前显示骨架屏，不用前一个用户的本地值。宽度滑块在拖动时即时预览、键盘每次 32 px，松开只更新**本地待保存值**；“恢复默认 620 px”同样只改草稿，按“保存界面设置”才 P01 PUT `expected_version`＋幂等键。取消恢复本用户最近已保存值。方案二完整复核仍按最小 832 px 与剩余主区计算，不能因保存 520 px 把双栏缩成不可读。

时区变化后管理台保留用户所选本地起止日，以相同的 `date_type + local_date_from/local_date_to` 重新查询，服务端按新 P01 时区换算 UTC 左闭右开边界；页面提示“筛选时间口径已更新”。前端只格式化展示时间，不自行换算查询边界；数据库时间、历史 Run 和 Export Snapshot 都不改。界面说明语言影响后续辅助文案与新回合回答偏好，本轮明确指令仍优先；它**不是**目标翻译语言，也不能令未说明语言的 W02 草稿自动 `ready`。动效选择遵从“跟随系统／始终减少／标准过渡”，减少时关闭侧板滑入与定位动画但保留文字状态和焦点转移。P01 保存成功只失效当前身份 preferences、必要管理台日期查询和对话后续回合偏好来源；已开始的 C05 回合、冻结的 Task Spec、旧译文不回写。`409` 显示服务端版与本地草稿差异，复制草稿／重载后再存；网络失败保留草稿，不能先把未保存值标已同步。

### 4.2 记忆建议、手动添加、编辑与删除

`MemoryList` 从 P02 GET 分页读取本人**已确认**的长期偏好；类别只有表达语言与术语解释、常用目标语言建议、输出呈现、获确认术语偏好等服务端允许类别。行显示完整可展开内容、适用条件、创建来源、确认状态、更新时间、版本和“编辑／删除”；长文本折叠不能截掉限制条件。“查看来源”只展开确认时间、来源类型和版本，源会话已无权限时给受限说明，不显示那段聊天原文。没有记忆时明确写“不影响正常对话”，不推荐把旧聊天自动导入。Case 金额、收件人、地址、单号、原件全文、客户姓名和秘密都不保存为 UserMemory；用户要问这些事实时引导管理台或对话 `@ `当前有权单票。

| “添加偏好” | 选类别、内容和可选适用条件；先 P02 `POST /me/memories/preview` | 预览列未来回合可能怎样表达、不会改变什么；只读、不调用模型、不保存。字段错误定位具体输入。 |
| “保存并确认” | 用户再看完整文字、当前身份和影响范围后 P02 `POST /me/memories`，幂等键稳定 | 服务端写本人新记忆版本；后续新 C04 回合装配，正在运行回合与旧消息不改。失败留表单草稿且不显示“已确认”。 |
| “编辑” | 以 P02 当前项版本打开，P03 PATCH 带预期版本 | 创建新的偏好版本，仅之后的新回合读；多端冲突展示差异，不静默覆盖。 |
| “删除” | 具体卡片上明确影响的确认层，P03 `POST /me/memories/{id}/delete` | 从有效列表去除，之后的新回合不再读；历史审计按留存规则保留且他人不可见。失败不先从 UI 删除。 |
| “确认／忽略建议” | P04 GET 待确认建议；对应 P04 confirm/ignore，发送建议 ID 和幂等键 | 未确认建议从不进上下文；confirm 才创建 UserMemory，ignore 只关闭建议。“本次译成英文”不自动变长期语言偏好。 |

对话中“记住这个偏好？”卡和设置页建议列表消费同一 P04 状态，确认或忽略后两处按同一身份 Query 刷新。Memory 建议来源若已撤权，只显示可读的建议类别与受限说明，不回显旧票据原文。前端预检空值、长度和明显密钥仅供即时反馈，敏感内容和单票事实最终由 P02/P03 服务端拒绝；不得用前端 regex 代替业务隔离。用户保存“常用英文译本”后，W02 只把英文作为**可点选建议**，缺明确目标语言仍须澄清，不自动启动 Run。删除后当前 C05 已冻结的上下文不改，下一个新回合才读取新版本。

### 4.3 会话与数据说明、权限反馈

三张只读说明卡分别解释“系统策略由项目版本化且不可编辑”“我的长期偏好只对本人新回合生效”“单票事实与会话摘要按 Case/Conversation 隔离”。卡上“了解如何关联历史单据”只跳对话并提示 `@ `操作，“查看单据管理台”只导航；不自动把某票、旧聊天或摘要塞进新会话。会话近 20 轮压缩与旧轮次摘要由服务端 C06/C04 实现，设置页不读取其他会话正文，也不提供“系统记忆编辑器”。

退出 S02 或 S03 身份改变时，先清 preferences、memories、suggestions、管理筛选、扩展详情和对话标签缓存，再读新用户。403/404 不显示旧个人内容；P01/P03 版本冲突有草稿对照；P02 拒绝敏感事实时说明去单票页面查看；P04 失败建议仍“未确认”，不能在界面先移到已确认列表。定向验收：建议未确认不进新会话；确认后只读个人偏好；常用语言只给建议；删除后下一回合失效；另一用户看不到偏好或建议；换时区后管理台筛选与显示同口径；侧板宽度刷新后恢复且窄屏仍全屏；系统策略始终只读。

## 5. 跨页面接口交接与错误映射

| 起点 → 目标 | 传递的受控对象 | 前端调用顺序与返回行为 |
| --- | --- | --- |
| 管理台批次／文件 → 校验 | Case/Run、实际 `displayed_snapshot_id`，再到 DocumentVersion/ParseArtifact/Section | R16 或 M01 确定所示版本 → R01 核对 → R02 展示；历史只读。关闭还原行、筛选、滚动与焦点。 |
| 管理台批次／文件 → 新对话 | 固定 Snapshot 或当前 Run；文件入口另带固定 DocumentVersion | C01 创建并持久预置同票结构化选择；C04 发送时重新冻结，旧会话摘要不携带。未发草稿仍显示标签版本。 |
| 对话 → 管理台 | Case、Run、成功 Snapshot ID | 优先 M01 受控行；当前筛选挡住时 M03 单票概览定位，不按名称搜索。 |
| 校验修订／确认／导出 → 管理台 | 新业务／译文版、RunEvent、成功 Snapshot ID | W04 同源状态使 M01/M04/M05 当前版刷新；旧 Snapshot 查询不变，正式文件只从 R16 取。 |
| 待核查 Run → 运营抽屉 | 授权 W04/M05 的 Run ID 与可选受控 StepExecution ID | 只在管理台时间线按 S03 权限开放：O01 先 GET 步骤再提交裁决；O02 先 GET 非秘密迁移选项再提交。普通用户仅看待核查说明，关闭抽屉恢复该行焦点。 |
| 仓库 → 对话 | 扩展 ID、版本、schema 哈希和 grant 状态 | E05/E09 成功后重取 C09；旧标签失效标不可用，C04 服务端最终核验。 |
| 对话 → 仓库 | E01 脱敏调用审计 ID | 工具卡可打开能力详情／最近调用；不在 URL 带工具参数、原文或凭证。 |
| 设置 → 对话／校验／管理台 | 本人偏好版本、时区、面板宽度、动效 | P01/P02/P03/P04 写成功后相应 Query 刷新；新回合读新偏好，管理台重算日期，校验区下次打开用保存宽度。 |

`401` 触发方案一登录门禁和身份清理；`403/404` 清目标敏感缓存；`409` 仅在版本对应表单显示差异，管理台列表不替用户切历史；`413/415` 交给上传槽；`429/503` 保存可恢复草稿和当前幂等键，显示服务不可用与下一步。`EVENT_GAP` 用快照补齐，新的 RunEvent 不直接改 R16 旧快照。不能用“前端按钮禁用”代替任何服务端归属、字段角色、外发范围或确认门禁检查。

## 6. 实施顺序、最小测试与需求对应

1. 先接方案一身份／Query 与 P01 时区、视图偏好；统一日期转换、路由、ID 深链和清身份逻辑。只验证偏好版本冲突、切身份与日期边界。
2. 再接 M01/M02 主列表、U03 上传草稿、M03 概览、M04 摘要、M05 时间线和 R16 交付；时间线稳定后接仅授权的 O01/O02 运行核查抽屉。用一票三原件、第二语言、历史旧快照与多角色筛选测列表与复核联动；运营抽屉只做第 2.3 节的权限、版本与失败定向验证。
3. 完成 E01–E05 Skill 草稿／导入／验证／启用，再接 E06–E09 MCP 真测试和逐工具 grant；从 C09 选择后以 C04/C05/E10 验证授权、失效标签与外部返回低信任显示。公共只读联调不能用客户单据数据。
4. 接 P02–P04 记忆列表、建议、确认、编辑和删除；验证确认前后新回合装配、当次任务语言与长期偏好隔离、切用户无缓存泄漏。
5. 最后走第 5 节的跨页代表路径：上传→翻译→复核→导出→管理台历史询问，另做只读索引续答与扩展一次性授权。优先模块类型检查、接口契约检查和改动点的交互测试；只在共享契约改变或联动风险出现时扩大回归范围。

验收映射：[总规范](前端页面总规范与联动契约.md) F17–F26、F33 对应本文件的管理、扩展和设置；F05、F08、F10、F21、F24、F27、F28 与[方案一](前端开发方案_基础架构与对话工作台.md)、[方案二](前端开发方案_单证校验工作台.md)共同验收。三份方案均只规定待实现代码；只有真实接口、权限和代表样本接通后才能标完成。
