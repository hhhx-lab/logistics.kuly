## 2. 开发演示模拟层

`src/frontend/src/mock/`，由 `VITE_API_MOCK=1` 启用（`.env` 放在 `赛题二-行业智能体/` 根目录，即 Vite 的 `envDir`）。

- 覆盖契约里的全部端点，按用户隔离，ID 确定性生成，因此刷新后深链仍然有效。
- 幂等键按 `方法 + 路径 + Idempotency-Key` 缓存，并比对请求体摘要：**同键不同参数按契约返回 409**，而不是静默返回上一次结果。
- 三条事件流（UploadSession、Run、ConversationTurn）各自独立 seq，支持 `after_seq` 续订与缺号重取快照。
- 注入点四个：`installTransport`／`installStreamFactory`／`installUploader`／`installContentFetcher`，接后端时逐个摘掉即可。
- 种子覆盖各分支场景：导出后又修订、红黄项待复核、实时推进且首次导出失败、待补货描范围、已导出、外部请求待核查、可重试失败、跨用户隔离。
- 调试句柄：`window.__mockPeek.{runs, probe, bumpBusinessRevision}`。

**已知限制**：内存实现，刷新页面即重置数据。这是演示层的取舍，不影响接后端后的行为。

## 3. 各页面的关键实现取舍

### 3.1 对话工作台

- 输入区用 Lexical。`/ ` 与 `@ ` 只在**正文开头或空白边界的半角字符紧跟半角空格**时触发；单独一个字符、URL、路径、粘贴内容都不触发；中文输入法组词中（`isComposing`）不发送、不选择候选。Esc 关闭浮层后，同一段文字不会反复弹出。
- 发送载荷由纯文本、引用选择、能力选择三部分组成，标签携带稳定 ID 与版本，**不从可见标签名反解析**。引用或能力失效时阻止这次调用并保留用户输入。
- 上传严格分六态：本地选择 → 接受数据流向告知 → 建上传会话 → 传输字节 → 服务端校验 → 已验收／失败／取消。XHR 的 100% 只表示本连接已发送字节；只有 U05 返回 SourceVersion 才算已验收。**任何字节传输前必须先接受告知**，点返回只保留本地选择。
- 上传完成后**不预设工作流**，由用户明确选择「先识别以回答文件内容」或「翻译并校验」。只问文件内容走只读识别，不追问目标语言。
- 任务卡状态为显式映射表，未知状态写「状态待支持」并记录非敏感日志，不默认归为成功。翻译阶段没有可靠分母，只显示阶段文字，不画百分比。
- `awaiting_input`（处理必要输入）与 `awaiting_review`（结果出来后的人工复核）是两张不同的卡，不复用同一个确认按钮。
- 用户阅读旧消息时，Run 事件只更新任务卡并显示「有新进度」，不抢滚动。

### 3.2 Skill 与 MCP 仓库

- 行状态由服务端下发 `row_state`，区分「可用（已启用）」与「已校验，待启用」——校验通过但未启用的条目不显示成可用，也不排进可用分组。
- 曾被启用的版本不可原位修改，编辑一律新建版本草稿，保证历史调用可复现。已存在未启用草稿时复用它，不会点一次就多一个孤立版本。
- 工具权限分 `read_only`／`write`／`egress` 三类，首版只有只读工具可授权，写入与外发由服务端拒绝而非仅靠前端禁用。
- MCP 连接测试按契约返回三段：`initialize` → `tools/list` → schema 校验，各段带起止时间与耗时。
- 导入只解析不执行；差异表判定「可用／未知动作／越权／不支持脚本／不支持的传输／低信任指令」，「忽略系统规则」这类诱导文字明确标注不可生效。

### 3.3 设置与我的记忆

- 时区偏好通过 `setDisplayTimezone` 驱动全局时间显示，**只影响显示**；日期筛选一律把本地日交给服务端按 P01 时区解释，前端不自行换算 UTC 边界。
- 记忆的适用条件在折叠状态下也始终可见——截掉它会改变偏好含义。
- 单票事实与凭证不进长期记忆：金额、收发货人、地址、单号、密钥样式由服务端拒绝，并在字段下给出「打开单据管理台」「在新对话中 @ 该票」两个入口。
- 预览影响只读，不写库也不调用模型，且同时写明「会改变什么」和「不会改变什么」。
- 切换身份时整块内容按 `generation` 重新挂载，前一身份的草稿不会延续给新用户。
