四个视觉方向，选一个再动代码

下面每个样例都是同一块产品截面：左侧导航、单据管理台的整票列表、状态标签和对话输入框。它们用的是同一份内容，只换了图标、配色、圆角和选中态，方便直接对比。所有方向都只改视觉，现有功能入口和「图标 + 文字」成对出现的规则都保留。

不管选哪个方向，都会做的基础改动

这四项是质感提升的主要来源，和配色方向无关。

统一图标集

把手绘路径换成 Lucide 的路径数据（ISC 协议），线条端点、圆角和视觉重量一致。保留现有 <Icon name> 接口，不新增依赖。

尺寸收敛到三档

现在混用 15、16、17、18、22px，改成 14 / 16 / 20px。描边随尺寸补偿，小图标不发虚，大图标不显粗。

图标默认灰色

未选中的图标用三级文字色，悬停变深，只有状态图标（风险、待复核、通过）带颜色。

重画 Logo

从通用文档图标换成「两张单据叠放 + 校验勾」，直接表达单证校验。favicon 和对话头像同步替换。

现状

按当前代码的颜色、圆角和图标路径还原，作为对比基线。

Logo 是通用图标蓝色方块加文档图形，出现在导航、登录页和对话头像等 5 处，最拉低质感。

蓝色铺得太满Logo、头像、选中态、主按钮都是同一种饱和蓝，强调失去层次。

图标粗细不一齿轮、拼图、大脑等手绘形状偏粗糙，小数坐标在小尺寸下边缘发虚。

状态标签偏重每个标签都有底色加描边，列表里一多就显得杂。

怎么选

直接回复字母即可，也可以混搭，比如「B 的配色 + D 的文件图标」或「A，但主按钮保留蓝色」。定下来之后按这个顺序改：

  1. 改 styles.css 的颜色 token 和 tailwind.config.js 的圆角、阴影
  2. 替换 Icon.tsx 的路径数据，调用处不动
  3. 重画 Logo 和 favicon.svg
  4. 同步更新 docs/ 里的页面设计文档和索引
  5. 五个页面逐一实际跑一遍，再交给子代理对照设计文档检验
