## 1. 交付范围、现状和实施边界

本部分交付登录与应用壳、本人隔离的 API/事件基础、对话会话生命周期、头像消息流、可编辑输入框、精确 `/ ` 与 `@ ` 结构化选择、多文件上传、任务澄清与启动、真实进度、证据卡、异步识别续答、结束服务卡，以及通往复核/管理台/扩展区/设置页的入口。复核、管理台和扩展管理的组件细节分别见[方案二](前端开发方案_单证校验工作台.md)和[方案三](前端开发方案_管理台扩展与设置.md)。

当前 `src/frontend` 只有 React/TypeScript/Vite/React Router 依赖，`App.tsx` 及四个页面为占位布局，`api/health.ts` 的 `phase=scaffold` 只表示骨架联通；没有认证、业务 API、SSE、输入编辑器、文件上传或设置页。实施时在现有目录扩展，不在计划中声称现有业务功能可用，也不安装依赖。进入编码时根据工程方案锁定 TanStack Query、Zustand、Lexical、PDF.js、Radix UI 和 Tailwind 的具体版本并生成锁文件；未获依赖安装授权前只维护方案与代码骨架。React Router 已存在，保留。

首版按`读服务端事实、保留少量本地交互状态`分工：Case、Run、消息、版本、Issue、扩展和用户偏好只从服务端 API 读取；前端本地只保留未发送文字、选择器开合、焦点、面板宽度即时预览、折叠和滚动。不能把 Redux 式第二套业务状态、OCR/模型调用或原件全文塞进浏览器。页面职责与接口动作的对应表如下：

| --- | --- | --- |
| 应用导航、本人头像、登录 | `App.tsx`、`features/auth`、`features/home`（首页与登录弹窗） | S01–S03；登录后工作流可用性与禁用原因读 W01，O03 仅作部署探针，不以 `health/live` 代表可处理单据 |

| 管理台、仓库、设置导航 | `pages/ManagementPage.tsx`、`pages/ExtensionsPage.tsx`、新增 `pages/SettingsPage.tsx` | 方案三的 M/E/P 接口 |

### 1.1 建议的最小文件组织和依赖方向

`src/frontend/src/App.tsx` 继续承载路由和主壳；`main.tsx` 增加 Query Provider、身份边界 Provider 和全局弹层宿主。`src/api/client.ts` 只有一个带 Cookie/CSRF/错误归一化的请求器；`src/api/generated/` 放由 FastAPI OpenAPI 生成且不可手改的 TypeScript 类型；`src/api/events.ts` 管理三类 SSE。`features/auth/` 放登录门禁和身份切换清理；`features/conversation/` 放消息、主卡、任务卡、结束卡和 `Composer`；`features/conversation/editor/` 放 Lexical 的 Skill/Reference 节点与触发插件；`features/upload/` 放向导、文件行、XHR；`features/tasks/` 放 TaskDraft 与 Run 卡；`features/evidence/` 只放统一 EvidenceTarget 打开函数。页面文件只拼装功能组件，不直接写 fetch 或业务状态机。共用的弹层、按钮、状态徽标、空态、加载态与错误态放 `components/`；不要为每个按钮造一个抽象层。

路由保持骨架地址可到达：`/conversation` 是没有旧上下文的欢迎入口；显式新建或首次实际提交后 C01 创建持久会话并进入 `/conversation/:conversation_id`，避免仅刷新欢迎页反复产生空会话。`/documents`、`/extensions` 保持；新增 `/settings` 和 `/settings/memory`；`/review` 保留为同一 ReviewWorkspace 的全屏深链，桌面浮层不另造一份页面逻辑。管理台从行进入对话时直接用 C01 的 `initial_reference_selections[]` 建新会话，同票历史文件可同时预置固定 Snapshot 与其中的 DocumentVersion，刷新仍能恢复，不先打开旧会话。未知路径与过期 ID 有可返回的错误态。

页面视觉通过 `styles.css`/Tailwind token 实现[总规范](前端页面总规范与联动契约.md)的 8 px 网格、左导航 232/64 px、阅读列最多 760 px、主文字 `#111418`、主操作 `#CF460F`（集装箱橙，见[视觉改版方案](前端视觉改版方案_集装箱橙.md)） 与红黄风险色；Radix 只承担对话框/菜单/可访问性，不叠加第二套随机颜色。复核尺寸切换由方案二负责。CSS 的响应式、焦点环、减少动态效果优先按页面设计落版，不在组件中用状态色推断业务状态。

## 2. API、身份、缓存与事件底座

### 2.1 同源请求器与类型

实现 `api/client.ts` 时统一前缀 `/api/v1`，`credentials: "include"`，GET 禁缓存，写请求附 S03 的 `X-CSRF-Token`；所有业务命令生成 UUID `Idempotency-Key` 并随一次用户意图稳定保存，网络重试沿用同一个键，用户修改参数后必须换键。金额/精确数量保持后端十进制字符串，UTC 时间只在展示时用 P01 的时区格式化；不让 JavaScript Number 承担金额事实。把契约第 2 节的错误结构转为 `ApiError{status,code,message,details,current,traceId}`，页面按稳定 `code` 分流，不从任意错误文本猜权限或版本。

FastAPI/Pydantic schema 定稿后生成类型到 `api/generated/`，Feature API 文件仅做薄封装，例如 `conversationApi`、`uploadApi`、`reviewApi`。OpenAPI 差异先同步共享契约再改生成文件。请求体只传用户可控制的字段和已选 ID，绝不传 `tenant_id`、对象存储键、长期 URL、系统 Prompt 或模型 Key。浏览器直传 U02 返回的签名 PUT 地址仅限当前文件，不向对象存储发送业务 Cookie/CSRF，提交 U05 才把验收结果算成 SourceVersion。

### 2.2 身份、Query 与本地状态

启动先 S03，未登录进入首页（宣传片循环播放，右上角「登录 / 注册」打开登录弹窗，调用 S01）；成功后刷新 S03 再渲染业务页面。头像菜单的退出 S02 成功或身份失效时同步关闭 EventSource、取消 XHR/Fetch、撤销 Blob URL、清 Query 缓存、Zustand 草稿、证据视图和上一个用户的本地折叠/滚动，再回到首页。切换身份不能先渲染旧用户名、旧消息或上一个用户的搜索数量。`IdentityView.permissions` 仅用于按钮提示；每个读取、下载和写入仍依赖服务端再次鉴权。

TanStack Query 负责业务查询。Query key 至少含身份世代、资源 ID 和读到的业务/译文/快照版；例如当前 Run 与固定历史 Snapshot 使用不同 key。W04、C03、R02、M01 的响应不能被 Zustand 复制为可写业务真值。一个写命令成功后只按其返回 `affected_*`/版本影响刷新相应 Query：修订刷新当前 Run、复核、Issue、译文与管理摘要；旧 Snapshot 固定 key 保留但再次打开仍经 API 鉴权。身份改变时新建 QueryClient 或立即 clear 并取消旧请求，防止慢响应把旧用户内容写回新界面。敏感消息、原文和文件 Blob 不进入 `localStorage`/IndexedDB；输入草稿只存在当前页面内存，打开侧栏和返回时保留，刷新不承诺恢复未发送原文。

Zustand 只持有当前身份下的导航展开、当前会话未发送编辑器内容、打开复核的 EvidenceTarget、触发控件焦点令牌、管理台行展开和各阅读区滚动锚点。长期的面板宽度、动效和时区以 P01 为准；快速定位侧板拖动时只即时改变 UI，释放后由方案二保存 P01；完整复核的临时宽度不覆盖偏好。设置页滑块须点“保存界面设置”才提交 P01。状态树必须有 `resetForIdentityChange`，不以文件名作任何缓存键。

### 2.3 三条真实事件流

`api/events.ts` 仅维护 UploadSession、Run、ConversationTurn 三种流。组件先读 U03/W04/C05 快照的 `last_seq`，再订阅对应 `events?after_seq=last_seq`；自动重连沿用 SSE `Last-Event-ID`。SSE `id` 是操作内序号，不跨操作复用。事件处理先检 `seq <= lastApplied` 去重，`seq > lastApplied+1` 或 `EVENT_GAP` 时停用猜测状态，重新取快照并续订。心跳不计进度；离线保留最后持久状态与时间，显示“正在恢复连接”，不展示虚假的新阶段。事件只在相关可见 Run/上传/回合订阅，管理台列表用轻量刷新提示，避免为几十行各开一条 SSE。

每个 RunEvent 先更新同源 Run 查询或使其失效，再触发任务卡、复核区和管理台可见记录刷新；不能三个组件分别维护 `isExported`。有可靠 `completed/total/unit` 才显示百分比。用户正读旧消息时只出现“有新进度”，不抢滚动。C05 的 `message_delta` 是后端已校验并持久化的段，`evidence_card` 只渲染后端给的来源对象；`message_final` 后用 C03 对账完整消息。中断轮次以 C05 状态显示“生成已中断”，不在前端拼接半截模型 token。

## 3. 对话页面骨架与会话生命周期

`ConversationPage` 使用设计文档的一屏布局：左导航与本人头像、56 px 顶栏、独立滚动消息列、输入区上方主卡/活动任务卡、固定输入框；复核宿主默认收起。主体宽度上限 760 px。消息文本、任务卡、证据卡与工具卡分层，头像 32 px；系统进度附着到任务卡，不伪装成第三个发言人。以下每个控件必须同时有数据来源、命令、失败和刷新口径：

| 控件/状态 | 读取与动作 | 实现与失败/刷新/权限处理 |
| --- | --- | --- |
| “＋ 新对话” | C01 POST 空会话；旧输入未发时先确认留在旧会话或放弃 | `ConversationSidebar` 记录当前草稿所属 conversation ID；不复制旧 Case、引用或摘要。创建失败仍留当前页并保留草稿。 |
| 最近会话、搜索与行 | C01 GET 游标分页；行点 C02/C03 恢复本人会话 | `ConversationSidebar` 只搜索标题/时间；结束会话只读。401/403 清旧缓存并显示受限占位，不泄露历史摘录；列表不加载 Case 正文。 |
| 会话更多/重命名 | C02 PATCH 带预期会话版本；“在新对话继续”用 C01 新会话预置原 Case 选择 | `ConversationHeader` 版本冲突原位展示当前标题与本地草稿；新会话不带旧摘要或消息。 |
| 左导航折叠、头像/设置 | S03/P01；折叠只改 UI，头像点设置/退出 S02 | 折叠不清消息；切用户先清状态再读新用户。导航到管理台/仓库/设置不取消后台 Run。 |
| 顶栏 Case 标签 | C02 返回绑定 Case/业务版；点击去 M03 单票概览或管理记录 | 一个会话一 Case；无票显示“未关联单票”；跨票引用 C04 返回冲突并给“新建会话查看该票”。 |
| Run 状态与时间线入口 | C02 的活动 Run ID、W04 快照/事件；点开最近事件 | 顶栏 `RunBadge` 分开显示当前工作状态和历史成功快照；`awaiting_input` 显待补确认，`awaiting_review` 才显示译文待复核。 |
| “查看校验”/“收起” | 以当前 Case/Run 组 EvidenceTarget，先 R01 再 R02；无显式目标才恢复本 Case 上次位置 | 无 Case/原件禁用并写明原因；关闭复核回原消息/输入焦点。完整复核宽度规则在方案二。 |
| “本轮上下文来源” | C06 GET | 只读 `ContextPopover` 展示系统策略版本、本人偏好、固定标签、近 20 轮与摘要存在状态；不暴露系统 Prompt、原件全文或旧会话摘要。 |
| 结束对话/结束卡 | C07 POST；结束状态由服务端返回真实 Run/快照 | 结束后输入区只读并给“在新对话继续”；后台 Run 仍继续。重发同键返回同一结果，C07 失败不假装结束。 |

会话列表与消息分页读取 C03，加载更多时保持首条可见消息的锚点，长答复可折叠但首段结论、风险与证据入口常显。用户消息右侧显示本人的头像和发送时间，Agent 左侧固定“单证助手”；消息状态直接取 C03/C05。旧消息正文不可因后来修订被改写；“基于历史版本”是服务端当前对照后给的提示，点击仍带原消息冻结的 EvidenceTarget 打开 R01 历史版。`read_index` 的异步续答按 `parent_turn_id` 放在原问题的续答槽，若用户在读别处仅提示“原问题已有补答”；它不制造一个新的用户轮次，也不阻断已经完成的首轮之后的新提问。

### 3.1 单一对话回合与异步识别续答

发送按钮调用 C04，提交文字、结构化引用、能力标签、**U05 已验收**文件 ID 和可选 TaskDraft ID。请求期间同一 `turn_id` 的按钮禁重复；网络未知时沿用同一幂等键重试或 C05 查询，不另建回合。C04 返回 `409 TURN_BUSY` 时保留全部草稿并提示上一条回复仍在生成；后台 W04 的识别/翻译 Run 不占用这个对话回合，仍可继续问状态。C04 接受后清输入草稿；若 C05 显示发送失败而消息未持久化，可从原发送载荷恢复，不把已成功的写工具重复发出。

若文件内容问题触发 `read_index@1`，首轮 C05 的经验证消息按实际 Run 状态说明“正在识别”或“识别已完成，正在核验来源”，并标 `continuation_pending`；初始回合完成释放锁。服务端把待续答登记、首轮消息及事件、回合完成在同一事务提交；W04 到 `indexed` 后由 AssistantContinuation 重新鉴权、冻结新 ParseArtifact/业务版/证据，C05 在**原 parent turn** 发 `continuation_final` 与证据卡。前端为该 parent turn 保持可恢复订阅（离页后由 C03/C05 重新补），不自行看到 `indexed` 后拼答案或再发送一次用户请求。C05 的持久 `continuation_status` 把 `running/awaiting_retry/awaiting_reconcile` 和允许的下一步显示在原问题下；`continuation_final` 对完成、失败、取消、受限、会话关闭都给终态，不让失败识别永远显示旋转中的 `continuation_pending`。已结束会话只显示真实终态和新会话追问入口；权限撤销时不显示续答正文。若用户期间发了新消息，续答仍归原问题且不借新消息的目标语言或另一票内容。


## 4. Composer、结构化标签与辅助能力

用 Lexical 替换现有禁用 `textarea`。`Composer.tsx` 管输入框 88–240 px、高度内滚动、附件托盘、发送按钮和快捷键；`editor/TriggerPlugin.tsx` 管触发词和候选弹层；`editor/CapabilityNode.tsx`、`ReferenceNode.tsx` 管可删除的结构化节点。发送载荷由 Lexical 文档提取纯文本、引用选择和能力选择三部分，绝不从可见标签名称反解析 ID。编辑器回显已发送消息时只读展示，不把用户输入的 HTML 当可执行页面。

| 控件/动作 | 数据与触发 | 组件逻辑、失败与验收 |
| --- | --- | --- |
| 文本输入、Enter/Shift+Enter | 本地编辑状态；Enter 无候选时 C04，Shift+Enter 换行 | 中文输入法组合中 `isComposing` 为真时不触发发送/选择；空白且无可提交操作时发送禁用。服务端拒绝时保留文本、附件和标签。 |
| `/ ` 候选 | 仅正文开头或空白边界处的半角 `/` 紧接半角空格；C09 GET | 光标附近 420 px 浮层，内置/自建/MCP 分组，名称、版本、用途、权限与连接状态；单独 `/`、URL、路径、粘贴文本与代码块不触发。输入筛选防抖且取消旧请求；Enter 选中、Esc 只关浮层。 |
| `@ ` 候选 | 同样仅半角 `@`＋空格；C08 GET | 搜索框支持文件名、单票号、上传／处理／导出日期、类型、语言、来源地角色、收件人角色、处理人和短摘要；日期按 DateFilter 只送本地日，由服务端按 P01 时区解释。筛选、防抖和取消旧请求均交 C08，不在浏览器扫旧 Case 缓存。按 Case/Run/DocumentVersion/Section/成功 Snapshot 分组，行示版本、摘要状态和命中来源；跨 Case 候选标不可加入，给 C01 新会话入口；纯文字 `@ ` 不构成引用。Section 候选必须来自确定的解析版，缺所属文件版、解析版或逻辑单据 ID 时只显示为不可选择的搜索线索。 |
| 结构化标签 | C08/C09 的稳定 ID、版本、selection mode、权限摘要 | 插入 28 px 标签，点开可读完整对象及“当前指针/固定历史”含义；×/Backspace 删除，文本光标和焦点回编辑器。Document 可选 `current` 或 `fixed`；成功 Snapshot 只能 `fixed`；Section 首版只能 `fixed`，并完整携带所属 `document_id + document_version + parse_artifact_id + logical_document_id + section_id`。Section 重解析后旧节仅作为历史只读标签，绝不按同名节自动映射到新解析；旧解析仍有权可读时保留该固定引用的询问能力。能力停用／版本失效、引用撤权或旧解析不可读时标不可用，阻止该调用并保留原问题，发送前 C04 最终复核。 |
| 同时 `/ ` 与 `@ ` | 两类标签共同进入 C04 | 浮层互斥；后端先冻结引用再核对能力范围。前端不因 Skill 描述而扩大票据范围，也不允许多个 Case。 |
| MCP 一次性授权卡 | C05 工具事件给 challenge ID 后 E10 GET；按钮 E10 approve/reject | 列目的地、工具、冻结 Case/文件/片段范围、用途、有效期；同意仅本次且不扩大 `@`。批准或拒绝沿原 `parent_turn_id` 收 C05 后续，不新建用户回合。公开只读联调不传单证数据时不弹虚假的敏感外发确认。 |
| 附件图标、拖放 | 选择多文件后进入第 5 节统一上传向导 | 拖出取消覆盖层，非文件拖放忽略；上传中可继续写消息但尚未验收的文件不能进 C04/W02。 |
| 示例按钮与主卡 | `WorkflowView` W01 决定可显示能力；点击示例只填可编辑文字 | “查看处理流程”仅展开四步说明；未接通或无 Key 时显示禁用原因，不创建 TaskDraft/Run。 |

`@` 固定原件只固定原字节；译文问答中的 Run/目标语言与有效版本由 C04 服务端冻结。多语言有效且没有活动目标时，渲染 Agent 的澄清选项，不由前端按时间挑译文。混合源文件有多个逻辑单据且问句不唯一时也显示具体节的澄清。Section 标签发送前保留所选解析版全链 ID，旧节因重解析失效时显示“历史区段”，允许按旧版只读询问或由用户重新选当前区段，不自动替换。`@` 标签引用旧快照时，消息和证据卡持续带旧 `ReferenceSnapshot`；后续版本变化只加“历史”提示，不换原始目标。Skill 的说明和 MCP 结果用低信任显示块，前端不把外部文本渲染成系统通知或本票证据。

管理台“询问这张单据”预置的 **fixed Snapshot＋其中 fixed DocumentVersion** 双标签在 Composer 中显示“历史版本：该快照；默认询问范围：这张物理源文件”。Snapshot 负责确定历史上下文版本，Document 标签将默认事实范围收窄到这张原件；仅当用户明确提出“与同票其他材料对比”之类问题时，后端才可在同一冻结快照内读取其他参与文件。前端不因出现 Snapshot 标签而把其他文件自动呈为当前问答范围，也不因仅看见一张原件就丢弃历史版约束；发送仍交 C04 校验同票关系与实际范围。

长答复超过设计阈值折叠，但首段结论、风险和来源入口始终可见；来源默认收起，展开后按源文件/译文与稳定版本归成紧凑文件列表；文件内引用可折叠、限高滚动，点击打开对应锚点，不按摘录铺大卡。消息列表滚动、任务卡时间线和候选列表各自独立。新 SSE 到来只更新当前卡，若用户离底部则显示“回到最新”而不强滚；点击源卡是明确定位，关闭后恢复原消息位置。

消息正文使用禁用原始 HTML 的 Markdown 渲染，外链只允许受控 `https` 并明示目标；用户上传内容、Skill 说明与 MCP 返回不能作为 React HTML 注入或伪装系统级提示。复制按钮只复制当前实际可见且有权的文本；证据卡按钮由服务端结构化数据生成，不从模型输出的 Markdown 链接猜 EvidenceTarget。


## 5. 多文件上传与归票的唯一流程

文件选择器、主卡、拖拽和管理台“新建处理”共用 `UploadWizard`；只有入口标记不同。流程状态严格分为 `local_selected → disclosure_accepted → upload_session_created → bytes_transferring → server_verifying → verified/failed/cancelled`。前端不把 XHR `100%` 叫“已接收”，U05 成功返回 `SourceVersion(document_id,document_version)` 才标“已验收”。**W02 提交已验收 SourceVersion 集合，C04 附件才提交对应的 `upload_file_id`**；两类 ID 不互换，更不能把未验收槽传给任一接口。选择的多份文件若不确定同票，先让用户明确分组；一个活动会话仍只绑定一 Case，另一组通过新会话/新 Case 上传，不暗中混票。

| 步骤/按钮 | 调用与状态源 | 必须处理的细节 |
| --- | --- | --- |
| 选择/拖入文件 | W01 的 accepted MIME 和后端限制做本地预检 | PDF、图片、DOCX 的可用范围来自注册表；EDI/可执行文件明确“不支持”。本地检查只是即时反馈，U02/U05 仍做魔数、大小、哈希和页数真校验。 |
| 上传配置版本 | 点击“开始上传”时S04 GET，把当前 `disclosure_version_ack` 给U02 | 不设上传告知确认页，不列服务节点或合成提示。版本字段兼容既有契约，仅核对部署政策版本，并非用户逐项同意记录；失配提示重试。数据流向、留存/删除与部署材料限制统一见隐私文档。部署不允许上传时仍禁用并解释实际原因，取消本地选择不创建上传会话。 |
| 新建/加入单票 | 新票 U01 POST，已有票读 U01 GET；C02 绑定情况 | 顶部显示当前 Case；已绑定另一票时必须新会话。归票不确定先暂停 TaskDraft，用户选定后再 U02。 |
| 创建上传会话 | U02 POST 给每文件名、MIME、大小、可选 SHA-256、替换目标和告知版本 | 返回每文件短期仅写 PUT 地址和 upload_file ID；地址须浏览器可达，不在 UI/日志/路由保存完整签名。U02 报不支持/超限时逐文件呈错，其他文件继续。 |
| 上传文件行 | 对每槽 XHR PUT；本地显示当前连接字节；U03/U04 显示已持久化状态 | 取消上传 abort 当前 XHR 再 U06 cancel；刷新后查询 U03，无本地 File 对象时提示“待核验/重新选择”，不恢复已丢失的百分比。文件名可展开全文。 |
| 完成验收 | PUT 成功后 U05 POST ETag/哈希，等待 `verified` SourceVersion | U05 失败逐文件显示原因和“重试/移除”。重复点击沿用幂等键；只有已验收文件计入参与数。相同用户范围的重复文件提示“保留/移除”，不能跨用户泄露哈希是否存在。 |
| 重试/仅处理成功部分 | U06 retry 为失败槽取新临时对象，重选本地文件；从成功列表显式勾选 W02 输入 | 部分失败不可静默跳过；“只处理已成功 N 份”须让用户看见被排除文件名。全部失败无 Run，保留可重试的 UploadSession。 |
| 删除待启动草稿 | W02 `DELETE /task-drafts/{id}`，只对尚未启动的 TaskDraft，显式带 `expected_draft_version` 和稳定 `Idempotency-Key` | 204 后清本地卡；同键重试仍 204。版本冲突重读 TaskDraft，不拿旧版撤销；网络失败保留卡与输入；`TASK_DRAFT_ALREADY_STARTED` 时读取已有 Run，不能假称已删；已撤销草稿 GET 为 404、W03 为 `TASK_DRAFT_DISCARDED`。Case 与已验收原件不删。 |

上传的本地字节进度与 U04 的持久事件分别有文字：“正在传输”和“服务器已验收”。若签名 PUT 的公开主机不可达，原位给连接错误和 U06 重试；不让用户手改内部 `minio:9000`。关闭托盘不终止已验收原件；离开页面或结束聊天不取消后台 Run。发送前附件在托盘中呈现；已发送用户消息只保留具名 @／能力标签，不生成空标签或重复附件按钮。助手回复的来源卡按固定源版本经 R01 进入只读原件。

## 6. TaskDraft、Run 状态与待输入表单

`TaskWizard` 从 W01 读取 `read_index@1` 和 `translate_review@1`，不同工作流共用上传源集合和状态卡，但只在注册且 `enabled` 时给可启动操作。W02 `POST/PATCH/GET` 的 `TaskDraftView.draft_parameters` 是表单唯一可恢复的结构化值：只读任务的 `index_scope`，翻译任务的 `target_language、translation_scope、selected_section_refs[]、output_formats、glossary_version、rule_pack_version`；每项选区带 `document_id/document_version + parse_artifact_id + logical_document_id + section_id`。另显示参与 SourceVersion、固定所选逐源识别稿 PDF 和 `missing_fields/questions`。`selected_sections` 尚无当前有效 ParseArtifact 时先引导只读识别，不能只传节名。刷新或 `409` 冲突时从 GET 的 `draft_parameters` 重建控件并展示差异，`task_summary` 只作人读摘要，不从自然语言反解析字段或选区。翻译目标语言未说明时提示中/英文快捷选项；用户长期偏好只能作为点选建议。`ready` 且至少一份文件验收后，明确按钮调用 W03；自然语言已完全明确时受控 Agent 也可通过同一 W02/W03 路由自动启动，页面以返回的 Run ID 合并为一张任务卡，不能再重复手动启动。W03 请求只送 `draft_task_id + expected_draft_version` 和幂等键，服务端据草稿锁定所选区段的解析基线；若草稿版或 ParseArtifact 已变化，保留表单并重取 W02 让用户核对，不让前端造图节点或推算 Task Spec 哈希。

| 向导动作 | 真值/命令 | 状态和错误 |
| --- | --- | --- |

任务卡状态映射必须是显式映射，未知未来工作流状态显示“状态待支持，查看记录”并记录非敏感错误，不默认归类为成功：

| --- | --- | --- |

| `awaiting_review` | 红、黄从 W04，无法判断从同版本 R02 的复核摘要读取；“查看并校验” | 草稿可阅，R02 尚未返回时写“正在读取”而不编造 0，不能称正式导出。 |
| `ready_to_export` | 从 W04 的有效 `current_review_confirmation_id` 和 `confirmation_status=valid` 恢复 ReviewConfirmation；打开清单再读 R13 核对有效 ID 与 Run 范围 `review_fingerprint`。若 W04 有最近失败 ExportAttempt，同时显示“上次导出失败”和该 Attempt 入口 | 首次导出带当前有效确认 ID、所见版及本次 R13 的 `expected_review_fingerprint` 走 R15；R14 成功时以返回的 `ReviewConfirmationView` 更新显示并刷新 W04/R13，不只保存浏览器内 ID。刷新后也由 W04/R13 重新取得有效 ID。失败尝试按 `latest_export_attempt_id/status` 与 `allowed_actions` 走 R15 同 Attempt retry，不能再次新建 `/exports` 或改走 W06。R13/R14/R15 仍复验。 |
| `exporting` | R15 ExportAttempt 逐文件与识别稿 PDF 回检；“查看导出进度” | 暂存产物没有正式下载。 |
| `exported` | R16 快照逐源文件与 所选识别稿 PDF；“查看交付/结束本次服务” | 若后来又修订，当前状态与 `has_successful_snapshot` 分开显示。 |
| `paused_reconcile` | “外部请求待核查”、最后时间与联系/有权运营入口 | 普通用户不能直接重投收费步骤。 |
| `failed_retryable` / `failed_final` / `cancelled` | 非导出步骤失败/取消原因、W04 `allowed_actions` 允许的重试或新任务路径；历史快照单独显示 | 不把失败导出误作一般 W06 retry，不把暂存文件放正式交付。 |

`RunEvent` 只从 W04 推动阶段和数值；`InputRequest` 是处理必要输入，`awaiting_review` 是处理结果出来后的人工复核，两者不复用同一个“确认”按钮。用户修改当前 Case 字段时，对话任务卡按同一 W04 事件/Run 快照立即呈译文与预览待重算；旧消息仍留旧版。


## 7. 完成卡、跨页面定位与返回

`CompletionCard` 只在 C07/W04/R16 的真实结果基础上出现。已导出时显示 Case、Run、语言、Export Snapshot 编号/时间，每份参与 SourceVersion 下列本次所选的目标语言 DOCX/PDF，各原件下列所选识别稿 PDF；下载按钮走 R16 鉴权 Range，失败只重试同一 artifact 下载。未导出但用户结束时，卡写“等待复核/待补确认/失败/仍在运行”的真实状态和“后台任务仍可在管理台查看”，绝不写“本次已完成交付”。“结束本次服务”先确认后 C07；“在新对话继续”由 C01 显式预置该 Case 的结构化引用，不携旧会话摘要；“新对话”不自动预置任何历史票据。

| 起点 | 使用的目标/接口 | 返回与过期行为 |
| --- | --- | --- |
| 消息附件、原文/译段/Issue 卡 | 后端 C03/C05 给 `EvidenceTarget`，R01 解析，再由共享 ReviewWorkspace 以快速定位或完整复核打开 | 关闭恢复消息锚点、输入草稿和焦点。历史版只读；旧预览不存在时停在原文，显式提供当前版入口。 |
| 对话任务卡“查看并校验” | 当前 W04 Run、R01/R02；完整复核，优先首个未处理红项 | 1440 px 宽按页面规范进入全屏双栏，返回原任务卡。不以保存的上次位置覆盖显式 Issue。 |
| “查看管理记录”/Case 标签 | 带 Case/Run/成功快照 ID 到 `/documents`/Case 概览，M01/M03 按 ID 定位 | 不按文件名猜行；管理台旧筛选不会改变本次引用的 Snapshot。 |
| `/ ` 能力管理入口 | 导航 `/extensions`，E01/C09 | 返回输入框时重读 C09；已停用标签不可用，保留原问题。 |
| “设置/我的记忆” | `/settings`、`/settings/memory`，P01–P04 | 偏好保存只影响之后的新回合，已冻结 Run 与旧消息不改；退出账户清本地草稿。 |

统一 `openEvidence(target, intent, returnFocus)` 函数只传受控 ID/版本，不传原件 URL、长原文或模型数据。打开时 R01 先鉴权和归一，再请求 R02 与按需内容；R01 返回 `source_only` 的未解析文件也可查看原件。任何 403/404 都清目标相关的 Query/Blob 缓存并显示受限占位。复核侧栏的组件和交互见[方案二](前端开发方案_单证校验工作台.md)。

## 8. 错误、权限、空状态与无障碍

| 场景 | 页面必须给出的反馈 | 恢复路径 |
| --- | --- | --- |
| API 首屏不可用或能力未就绪 | 登录态读 S03，登录后各工作流的可用性与禁用原因读 W01；总体服务不可用可显示部署探针 O03 的非敏感结果 | 已有消息可按权限阅读，禁止提交注定失败的任务；不把 `health/live` 绿灯或 O03 总体状态当成某工作流可用。 |
| 上传部分失败/刷新中断 | 每文件错误/最后验收状态，本地字节进度作废 | U03/U04 回补；失败文件 U06 重传或显式排除，只成功文件进 W02。 |
| C04 网络失败/`TURN_BUSY` | 原输入、标签和已验收附件不丢 | 同幂等键查询/重试；忙时等待原回合完成后再发，不隐式排第二轮。 |
| C05 SSE 断线、回合中断或续答待重试 | 最后已持久化段与时间、恢复连接；`continuation_status` 恢复 `running/awaiting_retry/awaiting_reconcile`，终态以 `continuation_final` 显示 | 按序补事件并重读 C05；失败识别不留无限加载。只有服务端允许的下一步才可操作，若须新回合重问也不重复已成功写动作。 |
| W04 断流/任务失败/收费请求待核查 | 最后真实事件、失败步骤和可做动作 | 重新读 W04；只在允许时 W06 retry；`paused_reconcile` 不给普通重试。 |
| 引用越权或版本不匹配 | 标签/卡片标“无权/历史/已过期”，不显示旧缓存正文 | R01 返回后只读旧版或显式切当前；跨 Case 新建会话。 |
| MCP/Skill 失效或外发拒绝 | 能力卡显失败与原因，原问题仍可编辑 | 重取 C09 或移除能力；E10 拒绝只终止辅助调用，不取消核心 Run。 |
| 新会话无 Case/无记忆 | 主卡、示例和正常输入区；上下文来源不显示旧会话 | 用户上传/`@ ` 后才加载本票资料；设置 P02 空态不影响对话。 |
| 明确无关请求或证据不足 | 展示简短范围引导或“无法核实”，不清空原会话 | 不按学科词拒答；技术、合同、财务及公式等材料补充知识允许解释。前端不自行判领域或造证据。 |

Dialog/Menu/Popover 使用可见标题、读屏名称和焦点返回；Esc 只关最上层，未保存草稿先确认。上传、任务、Issue 颜色须带文字和图标；焦点环至少 2 px，按钮可触范围至少 40×40 px。消息和进度实时播报节制，不能把每个细粒度事件读给屏幕阅读器。键盘操作与 1440×900、1920×1080、1280/1024 px 的布局检查按[页面总规范](前端页面总规范与联动契约.md)第 2、3、6、7 节完成。

## 9. 分段实现与定向验收

按接口可用顺序开发，不能先堆静态假卡片再把错误业务口径嵌进组件：

1. **底座。** S01–S03、路由、Query/请求器、错误结构、身份清理、视觉 token、三流 SSE 工具；用一用户和另一用户的隔离数据验证列表/缓存切换。只做本模块类型检查与请求/SSE reducer 的定向测试。
2. **对话与上传。** C01–C07 的会话与消息，S04/U01–U06 逐文件上传，W01/W02 任务澄清；一份成功、一份失败、重复点击 U05 的场景走通。再接 W03/W04 与只读索引。
3. **结构化输入与来源。** Lexical 的 `/ `/`@ ` 精确触发、C08/C09、R01 打开共享复核；只读识别的 `AssistantContinuation` 由 parent turn 回补。对触发 parser、IME、单 Case 标签和历史引用做小范围交互测试。
4. **翻译与交付。** W05 待输入、任务卡、R16 完成卡和 C07 结束卡，联同方案二的复核与导出做一票三文件端到端检查；禁止把尚无后端能力的按钮标为可用。
5. **跨页与扩展。** 接入管理台/扩展/设置后验证新会话预置、失效能力标签和用户偏好仅后续回合生效。公共 API 契约变化才扩展测试范围；样式局部调整只做相关屏幕复核。

定向验收清单必须覆盖：主卡与拖拽同一 U02 流；未说明目标语言只有 `TaskDraft.needs_clarification` 而无翻译 Run；上传后只问文件内容会产生 `read_index` 并在原 parent turn 获证据续答；`/`/`@` 单字符不弹而加空格触发；双标签先鉴权、跨票拒绝；`awaiting_input` 与 `awaiting_review` 两张不同卡；SSE 刷新补序不重复、无可靠分母不显示百分比；旧消息仍指原版本；完成卡只在 R16 成功快照后列逐原件产物；结束会话后的新会话不带旧摘要；另一用户看不到原用户会话、文件、候选、Blob 和记忆。上述验收以已实现接口为前提，不把当前骨架的占位文本或健康检查当作通过结果。
