# 前端页面设计：对话工作台

2026-10-08 导出契约：交付物是当前确认版本的纯目标语言译本（所选 DOCX/PDF），可选各原件的识别稿 PDF；不生成复核报告。识别稿从冻结 ParseArtifact 的原文与布局生成，不冒充 MinerU 供应商原始 PDF。一个 Run 对应一个目标语言；其他语言使用各自 Run/确认/快照独立导出，当前不提供多语言一键批量翻译或导出。旧成功快照含报告只作接口兼容，不再展示报告下载；旧失败报告清单在原 Attempt 安全重试时升级为译本与识别稿，历史失败事件保留。

2026-10-05：会话行尾更多菜单增加归档，确认说明隐藏最近列表、设置中恢复/删除、单据任务独立；归档当前对话后回欢迎页，草稿留原会话。归档深链只读，顶部“已归档·在设置中管理”导航到/settings/conversations，不显示重命名、结束/启动任务和上传卡片。普通领域问答直接一次模型生成；仅翻译任务补齐语言/文件，知识型翻译提问不追问目标语言。

## 1. 页面骨架与区域位置

桌面默认三块：左导航 232 px、居中消息与输入列最多 760 px、默认收起的右侧复核面板。1440 px 内容区里消息列不横跨空白屏幕；来源快速侧板打开后保证中央可读宽度至少 560 px，完整复核按总规范在空间不足时进入全屏双语对照。顶部栏 56 px 固定在对话内容区顶部，消息流独立滚动，输入区固定在底部且不覆盖最后一条消息。消息列上下留 24 px 滚动缓冲。窄屏左导航可收起为 64 px；输入框和选项弹层不因打开复核而清空。左导航、顶部栏、输入区的背景与分隔线使用总规范令牌；高风险红色只给真实 Issue，不给尚未提交的任务草稿。

| 区域 | 从上到下／从左到右的具体内容 | 默认行为 |
| --- | --- | --- |
| 左导航顶端 | 产品图标、产品名、折叠／展开按钮；其下白底描边的“＋ 新对话” | “新对话”创建新的空会话；不自动关联上一票。折叠后保留图标、可读名称和快捷入口。 |
| 左导航中段 | “最近会话”标题、搜索图标／输入框、只显示有权的会话行、单据管理台、Skill / MCP | 最近会话按更新时间排序，长标题省略但可读全名；行尾更多菜单只对当前会话有权操作。 |
| 左导航底部 | 当前用户头像／姓名、设置菜单与“我的记忆” | 头像只能显示本人身份；切换用户须清理会话候选和文件缓存。 |
| 顶部栏 | 会话标题、可编辑标题按钮、当前 Case 标签、活动 Run 状态、右端“打开／收起校验区”和更多菜单 | 无 Case 显示“未关联单票”；无可读原件时复核按钮禁用并解释原因。 |
| 消息流 | 用户消息右对齐，单证助手左对齐；消息下方可有具名引用、任务、事件、证据和工具卡，不重复展示附件按钮 | 时间、状态与头像相邻；历史回答保留当时版本，不被新版本覆盖。 |
| 输入区上缘 | 空闲时单据转换主卡；有活动任务时同位替换为当前任务卡 | 卡片不是另一个任务状态源；展开时间线只读取真实事件。 |
| 输入区 | 附件托盘、结构化标签、多行文本框、上传按钮、发送按钮和错误提示 | Enter 发送，Shift+Enter 换行；发送前核对上传与标签状态。 |

## 2. 左导航、顶部栏与会话控件

| 控件／卡片 | 位置与外观 | 点击／键盘动作 | 禁用、异常、折叠 |
| --- | --- | --- | --- |
| 新对话 | 左导航顶部，40 px 白底描边次要按钮（主操作留给主卡“上传单据”），折叠后显示“＋” | 新建未绑定会话并聚焦输入框；当前未发送草稿先弹“留在旧会话／放弃草稿” | 选保留时草稿只留在旧会话，绝不复制文本、附件、Case 或标签到新会话；已有后台 Run 继续。 |
| 最近会话搜索 | 最近会话标题右侧放大镜；展开为单行输入 | 按本人有权标题／时间检索；Esc 清空并返回标题 | 不搜索单据正文，也不把历史会话摘要用于新会话。 |
| 会话行 | 标题第一行、最近时间与可选 Case 状态第二行；当前行中性深灰底 | 点击恢复该会话原消息和滚动；已结束会话只读 | 旧会话权限撤销时为受限占位，不显示旧文件摘录。 |
| 会话更多菜单 | 行右侧省略号，聚焦／悬停可见 | “重命名”“结束对话”“在新对话继续”按状态显示；结束需确认后台任务不受影响 | 不提供“把历史消息加入新上下文”动作。 |
| 导航折叠键 | 品牌行右侧，常显；含方向图标 | 展开 ↔ 64 px 折叠，保留当前会话和消息位置 | 点击不改变右侧复核状态；窄窗口自动折叠但用户可暂时展开抽屉。 |
| 会话标题／编辑 | 顶栏左侧，标题 16 px；旁小铅笔 | 点铅笔原位编辑、Enter 保存、Esc 取消 | 标题仅供导航，不能变成业务事实或文件搜索权。 |
| Case 标签 | 顶栏标题后，品牌橙浅底描边；显示单票名／当前业务版 | 点击展开小菜单：单票概览、查看管理记录 | 单会话只能绑定一票；切换另一票必须新建会话。 |
| Run 状态胶囊 | Case 标签后，文字＋图标＋状态色 | 点击展开当前 Run 的最近事件与时间线入口 | 有历史导出但当前版待复核时显示两行状态，不显示笼统“已完成”。 |
| 校验区切换 | 顶栏最右，面板图标＋“查看校验” | 以快速定位意图打开同一校验容器；已打开则收起；无显式目标时恢复该 Case 上次位置，用户可从面板“展开双语对照”进入完整复核 | 无 Case 或无可查看文件时禁用并提示“先上传或关联单据”。 |
| 顶栏更多 | 右侧省略号 | 重命名、查看本轮上下文、结束对话、复制会话链接等有权动作 | 不提供修改系统提示词入口。 |

## 3. 消息、头像与卡片逐项规格

用户头像位于自己气泡右侧，显示本人照片或姓名首字；Agent 头像位于回复左侧，为固定“单证助手”图标与名称。系统进度不伪装为第三个人：它挂在相关 Agent 回复或任务卡下。气泡最大宽度不超过阅读列 85%，文件名和路径按词断行。每条回复右下仅有复制、来源／版本查看和错误时重试；重试不会重发已成功的写命令。

| 类型 | 内容顺序和颜色 | 可点击目标与结果 |
| --- | --- | --- |
| 用户文字 | 文本、有名称的结构化 / 能力标签和 @ 引用标签、发送时间；空名称及隐式引用不显示标签框，消息下不重复显示附件图标 | 引用标签悬停显示绑定范围与版本；助手回复的来源入口按冻结版本打开只读复核预览，不自动改目标。 |
| Agent 普通答复 | 自然语言段落、需要时的知识来源、时间与完成状态 | 完全离开物流领域时简短说明范围；按完成证据检查的段落逐块追加，未核实的原始模型 token 不直接展示。 |
| 单票事实答复 | 结论或“无法确认”、相邻的原文摘录与状态、下方一到多张证据卡 | 每张卡显示文件／逻辑单据／页或段落／原件与解析及业务版；点击“在原件中查看”打开相同版本。 |
| 人工采用值卡 | “原文写的是”与“复核后采用”分列；显示处理人、时间、理由及补充依据 | 原文卡只证明原文；采用值点开复核记录，不把原文锚点当采用值证据。 |
| 译文卡 | 原文／译文、目标语言、Run、译文版与预览版、草稿／有效／历史标签 | 点击译段可双向定位；旧预览不可用时回原文并说明失效，不用旧坐标指向新译文。 |
| 问题卡 | 类型、红／黄／无法判断、规则名、两侧原值、未决动作 | 多来源按 A／B 卡片并列；“查看问题”进入校验区，颜色始终配文字。 |
| 能力调用小卡 | Skill/MCP 名称、版本、目的、执行中／成功／失败、必要的外部来源 | 展开看脱敏参数和错误；MCP 失败不能生成“工具已经成功”的答复。 |
| 系统错误条 | 明确“消息未发送／生成中断／事件连接中断／权限变化” | 重试消息保留原输入；业务 Run 仍从持久状态读取。 |

答案中一个关键数字对应一张来源或一组相关来源；来源默认一个收起入口，展开后按稳定文件/版本和源文件/翻译文件分组；文件内引用限高滚动、随时收起，展开不抢消息滚动。长答复超过约 12 行可折叠为“展开全文”，但首段结论、风险与证据入口始终可见。旧答复所引字段改变后，在原消息上加“此回答基于历史版本”，点击只读查看旧依据或显式切当前；不得改写旧答复。

## 4. 单据主卡、上传托盘与要求向导

空会话时主卡位于欢迎语下、输入区上方，宽度与输入框一致，白底细框，左侧品牌浅底文档图标、标题“单据翻译与转换”、副文案“上传同票材料，识别、翻译并核对；复核后导出”。右侧主按钮“上传单据”（带附件图标），下方文字按钮“查看处理流程”。流程展开为四步“上传 → 识别与核对 → 人工复核 → 导出”，不说自动通关。发送过首条消息后卡片压缩为输入框上方单行入口；有活动 Run 时替换为任务卡。

欢迎语下另有三枚能力示例按钮：“翻译这票发票和箱单”“解释提单中的 Shipper”“查看待确认问题”。点击只把示例放进可编辑输入框并聚焦，不发送消息、不上传文件、不创建收费任务；没有活动 Case 时“查看待确认问题”变成可编辑的领域提问示例，不暗中搜索历史票据。示例下方不显示动作说明小字；最近会话标题或搜索框下方不显示搜索范围说明，搜索行为仍限定为有权会话标题与时间。

| 控件 | 位置与动作 | 条件和反馈 |
| --- | --- | --- |
| 上传单据 | 主卡右侧和输入框左下回形针，共用同一多选文件选择器 | 支持经验证的 PDF、图片和 DOCX；选择不等于已上传成功。首版 EDI、可执行文件或其他未接通格式在文件行原位写“不支持此格式”与支持列表，不创建可处理 Run。 |
| 上传操作 | 选择或拖入文件后直接显示文件托盘与“开始上传” | 不展示服务节点、合成材料提示或额外告知确认。数据处理规则统一维护在[隐私与数据处理说明](../../使用交付/隐私与数据处理说明.md)。开始上传前读取S04当前政策版本，U02记录版本与非秘密政策快照，保留部署可用性、权限及文件限制检查；失败原位重试。取消只关闭未传输的本地选择。 |
| 拖拽覆盖层 | 文件拖入消息列／输入区时出现浅橙虚线框和“松开以添加文件” | 拖出恢复；非文件拖拽不触发；多文件按选择顺序显示。 |
| 文件托盘 | 输入框上方逐文件行：名称、格式、大小、字节进度、状态与行尾操作 | 上传中有真实百分比；成功显示绿色“已接收”；失败显示原因和“重试／移除”；部分成功列明仅哪些文件可参与。 |
| 取消上传 | 每条上传中行尾“取消” | 只取消尚未完成的上传；已接收原件不因关闭托盘被删除。 |
| 重复文件提示 | 文件行下方黄色提示 | 提供“仍保留／移除此份”明确选择；不静默丢弃或跨用户提示去重。 |
| 归票选择 | 文件托盘底部浅底卡，显示当前 Case 与“新建单票／加入当前单票” | 不确定两份是否同票时暂停处理并请用户分组；跨票不能在同会话暗中混合。 |
| 要求摘要 | 文件列表下：任务类型、目标语言、翻译范围、参与文件、译本格式、可选术语 | 每项有“修改”；未启动 Run 可编辑，启动后修改文件／语言／范围必须提示创建新 Run。 |
| 目标语言选项 | 要求卡中的“中文／英文”单选和自由说明 | 用户未说明目标语言时明确追问；用户记忆的常用语言只作建议，点选后才成为本次要求。 |
| 放弃待启动草稿 | 要求卡右上文字按钮“删除草稿”，仅在尚未建立 Run 时出现 | 先确认要放弃的任务要求与文件关联；只清除待启动 Task Spec 草稿，不暗删已接收原件或 Case。首版已验收原件随所属整票删除，入口在管理台 Case 概览，不在此卡提供单文件删除。 |
| 源语言与混排确认 | 要求卡中只读显示检测来源、源语言与“不确定／混排”角标；有疑问时展开文件／区段选择和“确认需翻译部分” | 检测结果不冒充用户指定。解析阶段才发现混排时，翻译步骤暂停并在任务卡显示待确认；若确认仅核对检测结果，不改 Task Spec，则继续；若要改变已启动 Run 的翻译范围，展示新旧范围并创建新 Run，不暗改旧任务。 |
| “只翻货描”范围确认 | 解析后货描候选不明时，任务卡显示“待确认货描范围”，点开校验侧栏并排查看候选原文、所属文件和明细行 | 用户只在有来源的货描候选中选择本次必译片段；无候选或要增加非货描区段时回新任务向导，不凭相似标题扩展原 Run。 |
| 格式选择 | DOCX、PDF 复选；默认两者勾选，识别稿 PDF 在导出确认层可选 | 至少保留一种译本格式；不提供尚未实现的单语模板或“原版式复刻”选项。 |
| 开始翻译 | 要求摘要底部主按钮；自然语言已明确时可直接由受控路由启动 | 至少一份已接收原件、归票及语言明确、权限通过；缺项显示具体原因。幂等提交防双击。 |
| 仅问文件内容 | 用户提问如“总金额是多少”时出现“先识别以回答”说明卡 | 启动 read_index，只需已接收文件，不问目标语言，不显示译文或导出入口。 |

“查看处理流程”只展开说明，不建立 Run。上传中用户可以继续写要求；发送文本与上传成功是两个状态。只上传且未说明要做什么时，Agent 问“识别内容还是翻译”；只提出翻译但缺语言时保留草稿并询问，不显示“处理中”。对已启动任务点“修改范围”展示新旧范围和“创建新任务”提示，不直接改旧 Task Spec。

## 5. 输入框、/ 选择器与 @ 选择器

输入框正文区域白底 1 px 浅灰边框，点击正文或底栏不出现外围彩色光晕；按钮仍保留键盘焦点。正文编辑区独立relative定位，占位文字只能显示在正文内，附件托盘在其上方正常文档流排列，大小使用上传返回的实际文件字节数，不显示伪造的0 B；高度由 88 px 增至最多 240 px，超出后输入框内滚动。左下回形针和已选文件数，右下字数／状态与蓝色“发送”。发送为空且无可用操作时禁用；请求中显示“发送中”并禁重复提交。网络失败保留文字、文件引用和标签，给“重试发送”。Enter 发送、Shift+Enter 换行；选择器展开时 Enter 先选候选。粘贴的普通斜杠文本、URL 或代码不触发选择器。

| 选择器 | 触发与位置 | 行内容、选择、取消 |
| --- | --- | --- |
| / 能力选择器 | 在正文开头或空白边界键入半角斜杠紧跟半角空格；浮层锚定当前光标附近，空间不足向上展开。单独“/”不触发 | 按“内置 Skill／已启用 Skill／可用 MCP 工具”分组，每行名称、用途、版本、只读／外发权限与连接状态；键入关键字筛选，方向键、Enter、Esc 和点击可用。选中插入可删除的结构化能力标签。 |

## 6. 进度卡与结束服务卡

顶栏“查看本轮上下文”打开只读小面板，依次列系统策略版本标识、本人已确认偏好数、当前 Case 与本轮固定的原件／Run／快照标签、当前上传状态、直接进入模型上下文的本会话轮次范围，以及是否使用本会话旧轮次摘要。它只解释来源，不展示系统提示词全文、密钥、原件全文或别人的记忆；点击有权文件标签按固定版本开校验区。聊天记录仍可完整滚动阅读，但第 21 轮起更早内容只以本会话摘要参与后续上下文，受 token 预算时还可提前压缩。新会话面板初始不出现任何旧会话或其摘要，只有本人的已确认偏好。

进度卡固定在输入区上方，左侧状态图标与阶段文字，右侧主动作按状态变化；下方仅显示当前业务阶段，展开后按真实RunEvent合并为每阶段一行；解析、抽取、翻译、译文校验不按文件或批次重复，活动阶段显示“中”，进入后续阶段才显示前阶段完成。暂停或失败显示真实原因，人工确认和重试仍可见。刷新读取完整分页持久事件，以seq合并实时事件；完整批次审计保留在管理台。草稿与Run卡不显示费用预估、模型/OCR费用或冻结条件的重复摘要，条件仍在准备表单及复核/管理记录中查看。上传时展示逐文件进度，Run 排队只显示“等待处理”；解析有页数时显示已完成／总页。抽取、校验、翻译无可靠总量时只显示阶段，绝不编百分比。事件断流时显示最后真实时间和“正在恢复连接”；重连补齐并去重。用户阅读旧消息时，卡片更新但不滚动消息列，只出现“有新进度”。

## 7. 联动、异常和验收

从证据／疑点卡到校验区的顺序固定：先鉴权与核对版本 → 展开右侧或全屏容器 → 选原件／逻辑单据／区段 → 页面渲染 → 滚动来源到视区中部 → 同步标出对应译段与字段。连续点击复用容器；旧预览失效时只读旧稿或回原文，绝不按新稿相似位置跳转。关闭后回到触发的那张卡，保留消息滚动和输入草稿。到管理台使用 Case／Run／快照 ID；Skill/MCP 启停后刷新 / 候选；“保存我的偏好”经确认后只影响后续回合，系统记忆不可编辑。

## 8. 可直接落版的屏幕与状态规格

1440 × 900 桌面基准下，左导航展开为 232 px，剩余工作区顶部为 56 px 会话栏，消息与输入列最大宽 760 px 并水平居中。消息列左右各留 24 px 内边距；单条消息左／右对齐但不跨越整列，头像 32 px、头像与气泡间距 12 px、正文卡片宽度上限 620 px。空会话欢迎语距顶栏 72 px，主卡距欢迎语 24 px，主卡内边距 20 px、最小高 128 px；三个能力示例在卡片下方 16 px 处横排，放不下时换行，不缩小字号。主卡左侧 40 px 文档图标、中间标题和副文案、右侧 40 px 高蓝色“上传单据”；“查看处理流程”占下一行左下，不与主按钮争夺视觉重点。

### 2026-10-03 候选键盘与引用子项补修约定

候选仍按原420px/360px布局。每行提供option及选中状态，输入区通过aria-controls/aria-activedescendant指向当前候选，读屏可听到类型、文件/票名、版本、状态及跨票原因；无候选上下键不产生负索引，Enter不发消息。原件含逻辑区段时在行名朗读展开状态，右方向键展开、左方向键收起，子项左键回父项；鼠标箭头只为同一展开动作的视觉入口，不嵌套另一个不可达按钮。Esc关闭后在DOM更新下一帧返回编辑器焦点，保留正文。高级筛选控件使用原生Enter/方向键，不能误触候选选择；重试按钮也使用原生Enter。

引用换关键词/条件先显示读取中并撤旧列表，取消的旧响应不得写回；失败显示重试，不以“没有结果”替代错误。后端默认原件候选应返回同原件版本、同固定解析/快照的真实逻辑区段子项，不能拼入同票最新解析冒充旧引用。本轮C08已生成真实子项，PG4项及Chrome默认原件/固定历史区段、左右展开、子项收起回父通过；详细证据见F矩阵，不推导全部业务质量已验。键盘跳过disabled能力；鼠标只有实际移动才更新高亮，候选增减或滚动不能抢走当前键盘项。


### 2026-10-05 类型/边界确认联动修正

### 2026-10-14 上传后同票核对入口与任务卡联动（X4）

上传成功只表明文件验收通过；“已验收 N 份原件，要做什么？”卡并列三个真实按钮：“先识别以回答文件内容”“同票多单证核对”“翻译并校验”。按钮各自创建对应草稿，不共用固定翻译问句。识别与问答使用 `read_index@1`，同票核对使用 `consignment_check@1`；新翻译任务从可用工作流目录选最新版本，当前为 `translate_review@2`。已经存在的 @1 草稿和 Run 保持其冻结版本，修改类型／规则包也按该草稿版本请求，不能静默升级旧定义。

同票核对草稿标题和启动按钮明确写核对，要求明确后发送真实启动命令；不显示目标语言，也不向用户追问翻译语言。翻译草稿仍显示五种语言下拉和必要澄清。@2 翻译把“本次翻译文件”与“同票核对材料范围”分开展示：本次翻译只产出选中的文件，核对可以引用范围内其他同票材料；材料名称由有权管理概览读取，缺失时写未加载，不猜文件名。范围和输入版本在草稿保存／启动时冻结。
