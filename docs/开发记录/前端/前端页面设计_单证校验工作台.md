# 前端页面设计：单证校验工作台

2026-10-08 导出契约：交付物是当前确认版本的纯目标语言译本（所选 DOCX/PDF），可选各原件的识别稿 PDF；不生成复核报告。识别稿从冻结 ParseArtifact 的原文与布局生成，不冒充 MinerU 供应商原始 PDF。一个 Run 对应一个目标语言；其他语言使用各自 Run/确认/快照独立导出，当前不提供多语言一键批量翻译或导出。旧成功快照含报告只作接口兼容，不再展示报告下载；旧失败报告清单在原 Attempt 安全重试时升级为译本与识别稿，历史失败事件保留。

版本：v0.1｜2026 年 9 月 28 日｜状态：前端目标设计；真实交付与未验范围见前端实施记录及后端逐条核验第12节

上位依据：[翻译校验工作台与工作流产品设计](../../需求设计/单证翻译校验工作台与工作流_产品设计.md)第 2—10 节、[对话产品设计](../../需求设计/对话工作台与对话Agent_产品设计.md)第 6、9、10 节、[管理台产品设计](../../需求设计/单据管理台_产品设计.md)第 2、6 节。共用颜色、尺寸、联动与状态见[前端页面总规范](前端页面总规范与联动契约.md)。本工作台只有一套数据和交互：桌面右侧是可调宽面板，空间不足时全屏展示，绝不因切换容器而换业务版本。

## 1. 打开方式、外层尺寸和关闭行为

工作台默认关闭。对话任务卡“查看并校验”、证据卡“在原件中查看”、疑点卡“查看问题”、管理台批次／原件／疑点／快照，以及疑点列表中的问题入口，均使用同一工作台与深链契约，但带有“完整复核”或“快速定位”打开意图。入参可以只有 Case＋原件版本；解析、业务、译文、预览、Issue 等 ID 仅在实际存在时传入。打开前先验证身份和版本归属，不能让前端以文件名、页码或坐标猜到另一份材料。

面板靠应用内容区右边，左缘有 12 px 可抓握拖拽柄；快速定位初次宽 620 px，完整复核初次宽至少 832 px，用户可拖 520–900 px，且须给底层页面留下 560 px。按总规范的计算，1440 px 窗口从 Run 卡进入完整复核时直接从右展开全屏双栏；点来源卡则先开 620 px 快速侧板，顶部常显“展开双语对照”，点击后保留所选来源并全屏。宽屏完整复核可在 832 px 以上以右侧面板呈现；用户手动缩窄到无法容纳双栏时转为标签视图，按钮提示“展开对照”。拖拽时只变布局，不重新请求 OCR、清空修订草稿或修改所选锚点。拖拽柄可用左右箭头键每次调 32 px，双击恢复该意图的初始宽度；旁有“缩小／放大”按钮供无拖拽用户。全屏显示“返回对话／返回管理台”，返回后原页筛选、滚动和焦点都在原处。复核内部三栏仅在全屏或内部足够宽时同时展示；中宽用双栏与可收起问题抽屉，窄宽用标签切换。

| 入口 | 初始所选视图 | 返回点 |
| --- | --- | --- |
| 对话 Run 卡 | 完整复核；当前有效配对；优先第一条未处理高风险 Issue，无红项则总览 | 原任务卡；保留聊天滚动和输入草稿。 |
| 对话来源／译段卡 | 快速定位；卡片冻结的原件／解析／业务／译文版本和具体锚点 | 原来源卡；旧引用只读，可展开双语对照。 |
| 管理台已导出批次／Issue | 完整复核；当前行实际展示的 Export Snapshot，可能是历史命中快照 | 原批次或问题行；筛选、展开项、页码和列表滚动不变。 |
| 管理台文件原件 | 快速定位；该行展示的原件、解析版本及锚点 | 原文件行；可展开双语对照，历史快照仍只读。 |
| 管理台未导出行 | Run 当前已持久化工作版 | 原行；不假装已有正式文件。 |
| 未解析原件 | 只读原件及上传／解析状态 | 原入口；不要求不存在的 parse artifact。 |
| 疑点 Issue | 该快照或工作版的 Issue，跨文件时显示全部来源 | 原疑点列表位置。 |

关闭按钮在顶栏右端，Esc 在没有更上层弹窗时等同关闭；有未保存修订时先出现“继续编辑／丢弃未保存更改”对话。历史只读视图没有编辑草稿。显式深链定位优先于上次选中位置；无目标时按当前用户＋Case 恢复文件、Issue、视图、缩放与位置。若上次位置的版本已更新，先显示历史标识，不自动切当前。关闭后焦点回触发控件；若触发控件已卸载，回原列表行或消息区域标题。

## 2. 视觉结构与所有固定区

| 区块 | 精确位置、内容、颜色 | 按键／折叠 |
| --- | --- | --- |
| 顶部固定栏 | 左起 Case 名／短号及必要任务信息，标题不附目标语言，也不显示“当前工作版”徽标；历史只读、版本过期等需要采取行动的状态仍明确显示 | 右端依次为“查看记录”、快速定位时“展开双语对照”、全屏／收起、关闭。版本与目标语言仍由实际请求固定，并可在对应译文、记录与确认清单中查看。 |
| 统计横条 | 不展示原件数、解析页数、红项、黄项和无法判断数的独立统计横条 | 疑点筛选和检查清单继续使用当前选定版本的服务端结果；删除统计呈现不改变门禁或计数依据。 |
| 文件树／文件切换 | 左侧 200–240 px 或上方下拉；层级为物理源文件 → LogicalDocument → DocumentSection | 每层左箭头展开／收起；行显示文件名、类型、页／区段范围、原语言、待办数。未解析文件只有源文件行。 |
| 视图标签 | 固定操作区下：“总览”“原文与译文”“字段”“同票对比”“疑点”“处理记录” | 选中为墨色文字加品牌橙底线；切换只改变视图，不修改版本；不存在译文版本时显示可点击的“原件阅读”，原件查看与下载仍可用。 |
| 自适应布局 | 不展示“原译并排／字段与证据／三栏同屏”三段布局按钮；保留“源译片段”入口 | 根据可用宽度自动选择双栏或窄屏标签；字段定位可进入字段与证据视图。布局变化不清空当前字段、修订草稿或来源锚点。 |
| 主工作区 | 宽屏可排疑点列表｜原件｜译文三栏；中宽问题抽屉＋原译双栏；窄屏原件／译文／字段标签 | 每个阅读区独立滚动；原文和译文不按像素强制同步。 |
| 顶部固定操作栏 | 标题栏下方，左侧当前业务／译文配对与阻断说明；右侧“保存草稿”“复核完成”“导出”，窄宽可换行 | 三个按钮分别有前置条件，不能用一个“完成”同时保存、确认和导出。操作栏在工作区外，不被展开字段或底部视口遮挡；历史只读版显示禁用原因，不能从此改历史。 |

文件树可折叠以让原文更宽；隐藏后顶部仍有当前文件名与切换按钮。类型不确定的区段显示“未分类／待确认”徽标和“确认类型或区段”按钮，不能用文件级类型替它作判断。风险级别与当前门禁继续从当前版本读取，不把模型置信低直接映射为已判定事实冲突。字段正常值默认收起，有疑点、人工修改和与导出相关的组默认展开；用户展开状态按当前用户＋Case 保存。长表的行号和字段名在横向滚动时固定；长译段显示前几行与“展开全文”。

## 3. 原件区、译文区、字段区和问题区

### 3.1 原件阅读区

工具条从左到右为“源文件切换”“逻辑单据／区段”“页或段落定位”“缩小”“缩放百分比”“放大”“适宽”“搜索原文”。PDF／图片显示原件页数与可信矩形锚点；DOCX 显示段落、表格、单元格位置，不编造固定原件页码。若是某次渲染后的页码，旁注明渲染版本。搜索只在当前有权源版本中进行，命中列表显示页／段和当前选中，不能搜另一票。

来源框红＝未解决高风险、黄＝待确认、蓝＝当前点击、绿＝已确认；角标写风险文字。普通阅读默认不显示所有框，用户选择字段或风险后才短时强化相关区域。坐标为 page_only 或 paragraph_only 时跳到该页／段落并显示“无法精确框选”，不画虚构的矩形。旋转、裁切、缩放后框坐标需映射到当前渲染视图；尚未解析或渲染失败时显示受控原件预览／错误，不用 Markdown 假装原件。

双栏工作区在 832 px 面板里不能把两张整页 A4 缩成窄缩略图后要求用户判读。默认按当前锚点显示可缩放的**原件局部区域／段落**与对应译段，原件页号及周边上下文始终可见；“查看整页”切到完整原件渲染并允许局部缩放与平移，必要时点“展开双语对照”进入全屏。无可靠矩形锚点时显示带明确“识别阅读副本”标签的可读转写，并给同一页／段原件入口；转写不能代替原件证据。全屏双栏可在空间允许时以整页适宽作概览，用户放大后允许各栏独立滚动，不强迫两份文件按像素同步。

### 3.2 译文与预览区

工具条显示目标语言、Run、translation revision、preview version、草稿／待确认／有效／历史标签；右侧有“源译并排”“仅译文”“同步定位”三个显式视图动作。草稿预览盖浅灰“待确认草稿”标识，但不得盖住文字；历史快照为只读并显示快照编号。译段在被选中时出现蓝框和对应源 segment；数字、编号、金额保护异常附红／黄 Issue 角标。一个原段对应多译段时显示关联组，不按行号强行一一对应。

预览必须与所请求的业务／译文有效配对及 preview version 一致。工具条另有“下载带草稿标识的预览”文字按钮，仅在预览文件已生成且当前用户有下载权限时显示；点击前说明它供讨论、未通过复核、不进入成功交付列表，下载文件本身带“待确认／草稿”标记。旧预览有保留时可以打开历史只读预览；没有保留时显示“该预览已过期”，仍定位固定原文，并提供“查看当前译段”但只有经校验的映射存在才启用。保存字段或译文修订后，受影响预览立即标过期，导出按钮随之禁用；重算完成并产生新有效预览后才恢复定位。

部分翻译任务在译文工具条和正式交付卡常显“仅翻译指定范围”蓝灰信息条，点开列出实际选中的文件／区段和未译区段。右栏的未选内容以灰边“原文保留／未翻译”块呈现，不使用目标语言译文高亮，也不出现“修订译文”按钮；工作台与快照范围说明同样写明范围；识别稿保留全部原文，不标记为全文已翻译。复核清单只把冻结范围内缺译列为覆盖阻断，但未译区域仍有原文来源入口，不能让用户误以为整份物理文件已翻译。

### 3.3 字段与明细区

顶部信息卡显示文件名、Document Version、Parse Artifact、当前逻辑单据与区段、原语言、目标语言、页／区域、OCR 质量和缺页说明。字段按“主体与联系”“单号与引用”“运输与日期”“货物与包装”“金额与贸易条件”“翻译与质量”分组。每组标题右侧显示字段数／疑点数和展开箭头；只展示当前 LogicalDocument 适用的字段，不把 Seller、Shipper、Consignee 强行当同一角色。

每个字段行固定顺序为：带角色的中文字段标题 → 原文转写／识别候选 → 规范值与单位 → 人工采用值（如有） → 目标译文 → 状态与来源。Seller 地址为“售出方地址”，Buyer 地址为“买入方地址”，Shipper／Consignee 为“发货人／收货人”；电话、邮箱、名称、税号同样按原件实际角色命名，不根据贸易方向推定收发身份。行尾操作为“定位原文”“定位译文”“确认无误”，更多菜单为“修订识别值／标记无法判断”。确认按钮读服务端 `confirm_blocked_reason` 和当前 `confirm_field` 权限；有可靠原文、非空识别值且无阻断字段确认的实际字段问题即可确认，旧疑点 ID、整票提示或译文问题不能使按钮永久禁用。仅当字段真正关联未解决问题时显示折叠疑点明细，已处置及无关问题不在该行展示。字段确认只登记当前业务／解析版的复核人和时间，不自动处理译文问题。数值保留前导零、货币精度，净重和毛重不合并；多个来源并列不自动选择真值。明细按原有来源及行匹配关系展示。

点击“定位原文／定位译文”保持“字段”标签。宽屏右侧阅读栏切换到对应原文／译文，栏顶仅有“原文／译文”切换；窄屏分为上方字段列表与下方阅读区，两区独立滚动。命中段落、单元格或真实矩形用蓝色边框与浅蓝底标记；每次明确点击都重新定位，即便点击的是同一个锚点。合并段以真实 source／translation segment ID 数组精确匹配，不通过相似文字猜位置；定位失败在工作台显示具体错误。

### 3.4 校验矩阵在界面的逐组落点

每个已运行检查在“疑点”或“处理记录 → 检查清单”保留规则名、适用条件、输入来源、比较口径、规则版本、时间与结论。“未运行”“不适用”“未覆盖”“无法判断”和“已核验通过”是不同状态；尚未实现或未运行的检查不可显示为通过。首版实际启用的检查以已发布规则包及样本验收为准，下表说明完整目标清单在页面的展示位置，不声称算法已接通。

| 检查组 | 用户看见的卡片／来源 | 特殊反馈 |
| --- | --- | --- |
| 材料完整性 | 文件树页数徽标、原件页眉的缺页／重复页／遮挡提示、问题卡 | 区分原件疑似不完整与解析遗漏；关键页不可读红项，不能凭文件名猜缺页。 |
| 必填与形式 | 字段组空值／格式角标、规则详情 | 单证类型与模板决定必填；电话、邮箱、币种、单位、编号和 HS 长度各按适用规则显示。 |
| 发票算术 | 金额组的行金额、合计、费用口径与计算展开卡 | 数量 × 单价及容差的每个输入可回原文；货值与含运保费总额不盲比。 |
| 箱单计量 | 货物组件／箱／托盘、净重／毛重汇总卡 | 包装层级和同口径先说明；范围不明时“无法判断”。 |
| 同票行项目 | 两张逻辑单据的明细行匹配卡，A／B 来源按钮 | 一对多／多对一匹配显示依据与人工确认状态；未匹配不自动说原件错误。 |
| 跨单证运输 | 运输组的箱数、毛重、柜号、起讫地／参考号并列卡 | 标明同一批次与包装口径；毛重和净重不要求相等。 |
| 主体与联系 | Seller、Buyer、Shipper、Consignee、Notify Party 角色并列卡 | 先确认角色映射，不能因名称不同直接报冲突。 |
| 日期与地点 | 日期用途、起运地／接货地／装卸港／原产国分列卡 | 未知规则前提写“无法判断”，不把不同用途日期或地点硬判相等。 |
| HS／证书小规则包 | 规则依据、适用线路／货类／时效和证书缺失卡 | 明确“适用且缺证”“不适用”“未覆盖”三态；HS 只提示风险，不做最终归类或合规放行。 |
| 翻译保护与完整性 | 源译片段、数字／金额／编号保护差异、空译与漏行卡 | 关键标识变动红项；原文 OCR 自身不可靠时译文同时标待确认。 |
| 术语与语义 | 术语库版本、同票术语差异与角色错译卡 | 语义模型只生成待核查候选；不能自动把“意思接近”当合格。 |
| 输出回检 | 导出进度中的逐文件字段覆盖、明细、版面、文本层回检 | 任一必需文件或所选识别稿 PDF 失败就阻断整组快照，失败暂存不进入正式文件列。 |

### 3.5 疑点列表

问题区顶部是“未解决／阻断红项／待确认黄项／无法判断／已处置／全部记录”标签和文件筛选，默认未解决；卡片正文只按“问题说明／可能影响／推荐处理”三个明确区块排版，长文本自然换行。移除正文中重复的 `rule_name · rule_version` 和重复 `conclusion`；规则依据、原始结论与处置链仍在检查清单和处理记录中保留。风险、当前处置状态和来源入口按需要显示。每卡底部统一按顺序显示“修订译文／忽略并记录／Agent处理／应用推荐修改／补充上传”五按钮；两列或三列自然换行。按钮适用性由 `guidance.actions`、当前权限、版本和处理状态共同决定；不在每个灰按钮下重复展开长原因，受限原因留在按钮提示或实际操作反馈中。不再显示修订字段、裁定事实、接受提示、稍后处理等额外入口。已解决卡在历史筛选可查看，五按钮保留但禁用。

“修订译文”打开唯一对应译段的人工作业表单；“忽略并记录”理由选填，仍登记人员、时间及问题版本；“Agent处理”允许每种问题提交具体意见，译文问题修订对应译段，识别或资料问题按已存证据形成建议，不能凭空补全事实。“应用推荐修改”对当前有编辑权限、状态为 `open` 且推荐处理非空的疑点开放：唯一授权译段的完整替换内容直接追加译文修订版本；其他推荐冻结本次所见建议，交给已有 Agent 流程执行或分析。受理、分析结果、仍需补充材料与实际修复分别显示，不能把提交或生成建议伪装成问题已解决；历史只读、已处置、权限撤销、版本过期与重复请求的限制保持。“补充上传”预置同票与相关 Issue ID／所见问题版。Agent 队列、结果、失败或外部待核查在该问题卡显示。上传加入同票并登记关联，不改旧 Run 的固定输入，也不因完成上传自动解决疑点。

跨文件冲突卡同时显示来源 A／B 的原文、单位、角色和“跳转 A／跳转 B”；切换来源不改变当前事实。点击 A／B 前保存本疑点的筛选、文件筛选、列表滚动及选中 Issue；原件阅读区提供“返回本疑点”，返回后恢复同一列表位置与选中项。该返回点按用户、Run 与所见版本隔离，外部来源深链、切 Run／版本或身份变化不得复用旧返回点。规则“不适用”和“未覆盖”分别有解释与依据；未覆盖不计为规则通过。零疑点页仍列“执行了哪些检查／哪些规则未覆盖／检查时间与规则包版本”。

## 4. 定位、滑动与焦点的完整动作序列

1. 用户点对话来源卡或管理台疑点：先锁定 Case、原件版本、解析版本、业务版和可用译文配对，确认当前用户有权；失败留在原页显示具体原因。
2. 打开右侧面板／全屏容器后，先设置标题与所选版本；显式目标覆盖本地恢复位置，历史目标进入只读。键盘焦点移到工作台标题或目标问题。
3. 展开文件树的正确源文件、逻辑单据、区段；原件页面按需渲染完成后，滚动对应页／段落到阅读区中部。原件边框与字段行同时加同一“当前选中”标记。
4. 若译段存在且 preview version 匹配，译文阅读区再定位到关联片段；有多个关联片段时作为一组高亮。问题涉及两份原件时先开 A，另一来源保持可见切换标签，不能自动轮流跳页。
5. 程序只执行这一次定位滚动，动画至多 240 ms；新点击立即取消旧动画。用户滚动原文、译文或表格时停止自动跟随；下次明确点“同步定位”或新来源才重新联动。减少动态效果时无动画直接定位。
6. 点击原文框时优先处理关联译段：只有一个可靠译段就直接切到译文并定位，即便该框同时关联多个字段，也不强制出现字段／译段混合选择横条；确有多个译段时才提供译段选择。没有译段时保留字段定位，唯一字段直接选中，多个字段供明确选择。点击译段反向定位来源；无可靠对齐时显示 Issue，不硬连附近文字。点击字段行仅定位，不等于确认它正确。
7. 缩放、切页、切文件只改变当前阅读状态；重新渲染后按稳定锚点恢复选择，而非复用上次像素坐标。关闭工作台恢复原页滚动与触发控件焦点。

## 6. 复核确认、整组导出与下载

顶部操作栏“保存草稿”仅对当前打开的编辑器有效；没有修改时禁用。“复核完成”在规则与译文 QA、版本有效配对、未解决红项处置完成后可按；候选字段无需逐项确认，黄色及其他疑点不阻断；点击打开检查清单，不立即导出。清单逐项列 Task Spec 的目标语言、范围与参与源文件、逻辑单据、红黄项、无法判断／未覆盖、人工采用值、业务与逐文件译文版本、兼容配对依据、输出格式及确认人。仅未解决红项、译文／预览过期、QA 未完成或权限不足时，清单对应行有红／黄说明与“前往问题”按钮，底部确认键禁用且可读原因。用户点“确认复核”后由服务端事务创建 ReviewConfirmation；顶部操作栏才显示“已确认 v…”。

“导出”按钮仅在有效 ReviewConfirmation 对应当前版本时启用。点击后导出确认层列每份参与原件的译本格式、文件名预览、原件／解析／业务／译文配对，每份原件下可选识别稿 PDF；主按钮为“生成确认稿”，次按钮“返回”。服务端在渲染前和登记快照前再验版本与确认摘要；有新修订则原位显示冲突并返回复核，不使用旧 ready_to_export 标签放行。处理中显示逐文件与识别稿 PDF 的真实渲染／回检状态，无成功文件入口。全部通过才显示 Export Snapshot、逐源文件 DOCX／PDF 下载、识别稿 PDF 下载和“查看管理记录”。任一必需文件失败不生成“部分成功快照”；历史成功快照仍在只读历史区可下载。下载中断仅重试下载同一快照，不重新执行翻译或导出。

历史快照顶栏标“历史版本，只读”，字段、Issue、译本与识别稿均用该冻结配对。“切换当前工作版”明确请求当前版本并重新鉴权，不能自动把旧来源锚点投到新解析结果；可能出现“当前版待重算”。只读识别 Run 没有译文和确认／导出按钮，原文、字段候选及来源仍可阅读。

## 7. 异常、联动与验收

| 情形 | 工作台准确反馈 |
| --- | --- |
| 文件未解析 | 只读原件预览＋上传／解析状态；字段和译文写“尚未形成”，不伪造版本。 |
| OCR 无精确坐标 | 页／段落级定位与“无法精确框选”；不猜红框。 |
| 当前译文与业务版不成有效配对 | 译文与预览标过期，导出禁用；等待局部重算或人工检查。 |
| 权限撤销／深链错误 | 停止加载敏感内容，保留不含原文的受限说明；不从旧缓存显示文件。 |
| 事件流断开 | 保留最后持久状态与时间，显示重连；不把未知阶段当成功。 |
| 外部请求待核查 | 顶部状态“外部请求待核查”；普通用户只读，核查角色按审计流程处理。 |
| 导出失败 | 失败文件与原因可见，暂存不入正式文件列；既有成功快照保留。 |

同一 Run 的事件驱动对话任务卡与管理台状态；修订产生业务／译文版本事件，旧回答只加历史提示，不重写文本。工作台可从管理台的历史筛选行打开恰好该行显示的快照，关闭后原筛选和滚动不变。验收至少验证：三份原件中混合 PDF 的两种逻辑单据可独立定位但仅一组源文件译本；A／B 冲突不自动选真值；字段修订与译文修订只影响各自版本；旧预览不能跳到新版相似坐标；确认和导出分离；任一产物失败不形成整组快照；历史版本只读；键盘、减少动效和手动滚动均不破坏定位。

## 8. 可直接落版的对照视图与操作密度

1440 × 900 窗口从 Run 卡进入时使用全屏容器：顶部标题、操作区与视图标签按实际内容紧凑排列，不预留统计横条高度，剩余高度全部给独立滚动的工作区，目标可读高度至少 540 px。全屏左右各留 24 px 内边距；文件树默认 200 px，可折叠为 40 px 文件切换钮，工作区与文件树间距 16 px。默认“原译并排”时剩余宽度均分给原件和译文，中缝 16 px；从疑点跳来源后，阅读区常显“返回本疑点”，不让整张问题卡长期挤压阅读区。疑点列表在 1440 px 下为左侧 320 px 可收起抽屉，点击某项后关闭抽屉并定位；1920 px 且空间充足时可固定为第三栏。三栏模式只有在原件与译文各自仍能保有至少 480 px 阅读宽度时启用，否则自动降为双栏或窄屏标签，不提供三栏切换按钮。

832 px 的完整复核侧板两侧各留 24 px，文件树改顶部下拉，内宽约 784 px；原件局部／识别阅读副本与译段两列各约 384 px，中缝 16 px。此尺寸不同时展示两张整页缩小的 PDF；点“查看整页”只改变原件阅读方式，必要时全屏。快速定位的 620 px 侧板默认一栏原件＋顶部字段／问题摘要，用“原件／译文／字段”标签切换；“展开双语对照”提升到完整复核，保留选中文件、版本和锚点。用户拖窄完整复核侧板时，列切换取代双栏，顶部确认和导出按钮仍在固定操作区，窄宽可换行。面板由右侧 180 ms 滑入，定位动画至多 240 ms；减少动态效果时直接出现并定位。

| 元素 | 尺寸、颜色与内容 | 主动作及反馈 |
| --- | --- | --- |
| 文件树行 | 最小高 44 px，类型图标、文件／逻辑单据名、页段范围与风险数；选中中性深灰底 | 箭头只展开，文件名切换；待确认类型用黄徽标而不是红色假冲突。 |
| 原文工具条 | 高 44 px，缩放、页／段定位、搜索与“查看整页”；按钮可触达 40 × 40 px | 缩放 25%–300%，超出禁用；适宽仅改变视图，不改变源锚点。 |
| 译文工具条 | 高 44 px，语言、Run、译文版和预览版在左，视图／草稿下载在右 | 过期显示紫灰只读条，当前版入口独立；不可在旧坐标上继续编辑。 |
| 来源框与译段 | 1–2 px 边框、角标写“高风险／待确认／已确认”；选中另加 2 px 蓝外框 | 点击后两侧按稳定片段关联定位；无精确框时显示页／段级说明。 |

## 2026-10-14 同票多单证对比视图（X4 实际实现口径）

本节依据[同票多单证专项工程方案](../../技术方案/同票多单证交叉核对与格式适配_专项工程方案.md)，说明新增页面的实际组件与联动；涉及既有标签和入口时以本节为准。规则是否执行、适用范围和比较结果由服务端提供，页面不把“没有差异行”解释为全票检查通过。

### 1. 入口与布局

- 主标签顺序增加“同票对比”，与“字段”“疑点”独立。`consignment_check` 任务进入工作台时默认此标签；翻译作业可切到此标签查看绑定的核对批次。切标签不启动任务，不改源材料或业务事实。
- 此标签隐藏通用文件树和文件选择条，避免在矩阵之外再重复列出源文件。顶部核对工具条内边距 8 px：左侧为真实核对状态和批次时间，右侧依次“上传补充材料”“重新核对”。上传复用同票上传入口；重新核对发送版本化命令并建立新 Run。
- 顶部状态区分“解析中”“核对未执行”“正在关联单证”“关联不明”“正在核对”“核对完成”“当前批次失败”“无可比较对象”“新版本待重算”。新材料未纳入旧批次时下方单独提示，旧结果仍可读；未执行或失败不展示伪造矩阵。
- 有多个可读批次时工具条下出现最大宽 320 px 的批次下拉框，显示时间、状态及当前／历史。更多批次和更多比较行分别使用真实分页按钮；不通过前端拼造批次。
- “材料与核对范围”默认折叠，展开区最高 160 px 并独立纵向滚动，列原件版本、是否排除和完整性。当前工作版可展开“修改核对范围”；历史快照不出现该写入入口。
- 筛选条内边距 8 px，左侧依次“未解决差异”“全部”“正常差异”“待关联”“历史已处理”，右侧为风险下拉“全部风险等级／红项／黄项／无法判断”。默认未解决差异；待关联读取候选关系及待判定对应组，不能把关联不明直接染成确定事实冲突。

### 2. 比较矩阵与阅读区

矩阵使用 12 px 正文、浅灰分隔线和白底。表头纵向固定，首列横向固定且宽 200 px；每个材料／逻辑单据列最小 190 px。矩阵在自身区域同时支持横、纵滚动，外层标题和筛选不随长表滚走。宽度至少 920 px 时最多同时展示四列材料；不足 920 px 时最多两列。超过可见列数才显示材料下拉选择器，不以缩小字号塞入全部文件；同一列不能重复选择。

每行左侧依次为核对项目、状态、比较口径和展开箭头；材料格显示来源值、单位、与来源不同的人工采用值以及“定位来源”。不参与某项的材料写“不参与此项”，空值不伪造成一致。行展开显示问题描述、比较口径、可读的计算项和关联 Issue 入口。风险红／黄来自服务端分类；正常差异、无法判断和已处理保留文字状态。点击来源后该行浅蓝选中，阅读区命中位置用蓝框／浅蓝底短时高亮两秒。

宽度至少 920 px 时证据栏位于矩阵右侧，占工作区 43%；窄宽证据栏在下方，占可用正文区 50%，与矩阵分开滚动。证据栏只显示被点材料，顶栏为文件名和“收起证据”。先走证据解析鉴权，再使用准确 DocumentVersion／ParseArtifact 阅读；材料在消费翻译 Run 的文件树之外时另取固定源版视图，不切换整个工作台 Run。只有服务端提供真实矩形坐标才画框；只有页／段位置时定位页／段，保留精度说明。重复点击同一来源也重新定位和高亮，失败原位显示英文错误。

### 4. 重核对、翻译绑定与导出

独立同票核对返回新 Run 时，侧栏仍使用原容器，但显式改为新 Run 的完整复核目标；全屏 `/review` 同步更新 URL，刷新能恢复新任务。新任务不继承旧来源选中目标或快照 ID。翻译工作台保持原翻译 Run，等待服务端为 `translate_review@2` 建立兼容的核对绑定后刷新核对／疑点／清单；不偷偷将它切成没有译文的独立核对任务。若不兼容，展示真实旧配对／过期状态，不复用旧问题通过新版本导出。历史快照只使用其冻结批次，没有冻结数据时明确提示，不读取当前批次补空。
