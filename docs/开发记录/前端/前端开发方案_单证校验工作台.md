# 前端开发方案（二）：单证校验工作台

2026-10-08 导出契约：交付物是当前确认版本的纯目标语言译本（所选 DOCX/PDF），可选各原件的识别稿 PDF；不生成复核报告。识别稿从冻结 ParseArtifact 的原文与布局生成，不冒充 MinerU 供应商原始 PDF。一个 Run 对应一个目标语言；其他语言使用各自 Run/确认/快照独立导出，当前不提供多语言一键批量翻译或导出。旧成功快照含报告只作接口兼容，不再展示报告下载；旧失败报告清单在原 Attempt 安全重试时升级为译本与识别稿，历史失败事件保留。

版本：v0.1｜2026 年 9 月 28 日｜状态：待实现的开发方案

依据：[翻译校验产品设计](../../需求设计/单证翻译校验工作台与工作流_产品设计.md)、[校验页面设计](前端页面设计_单证校验工作台.md)、[页面总规范](前端页面总规范与联动契约.md)、[对话开发方案](前端开发方案_基础架构与对话工作台.md)及[前后端接口与状态契约](../../技术方案/前后端接口与状态契约.md)。本文件只定义前端实现；Case、版本配对、Issue 门禁、ReviewConfirmation 与 Export Snapshot 的真值只来自共享契约 R01–R16、U07–U09 和 W04/W05。界面上的确认、导出禁用态是服务端允许动作的呈现，不能替代再次鉴权与版本比较。

## 1. 目标、组件边界与实现顺序

从对话证据/任务卡、管理台行/文件/快照和疑点记录 打开**同一个** `ReviewWorkspace`。桌面可为快速定位侧板或完整复核侧板；宽度不足时全屏，业务视图和所选 EvidenceTarget 不变。既有 `src/frontend/src/pages/ReviewPage.tsx` 改为全屏路由包装；新增 `features/review/ReviewHost.tsx` 负责侧板/全屏壳、焦点返回和宽度；`features/review/ReviewWorkspace.tsx` 负责共同的标题、顶部操作栏、文件树与视图。`SourceViewer.tsx` 管原件，`PreviewViewer.tsx` 管 R06 译后版面，`TranslationViewer.tsx` 管 R05 可编辑源译片段；`FieldsPanel.tsx`、`IssuesPanel.tsx`、`ReviewForms.tsx`、`ReviewExport.tsx` 分别承载字段、问题和动作。同一 API hook 和 UI 状态由侧板与全屏共用，不能复制两套字段表或 Issue 状态。

第一步做 R01 解析与 U07/U08 的只读原件定位，供 `read_index`；第二步接 R02–R06 的字段/疑点/译文和双向定位；第三步接 R07–R12 修订；最后接 R13–R16 复核确认与导出。每步都有真实版本来源后才打开对应按钮。文件内 LogicalDocument/DocumentSection 与物理 DocumentVersion 分层：文件树可有多条内部逻辑单据，但导出区只按物理源文件列所选格式，不能按节重复制造译本。

## 2. 打开意图、深链、布局和焦点

`openEvidence(target,intent,origin)` 的 target 必须来自 C03/C05、R03/R04/M01 等服务端数据或受控深链解析；URL 只存契约 `EvidenceTarget` 的 ID/版本，绝不存原件路径、敏感原文或带签名的下载链接。先 R01 `POST /evidence/resolve` 校验所属 Case/DocumentVersion/ParseArtifact/LogicalDocument/Section/业务版/译文版/快照，得到 `EvidenceResolution.normalized_target`、`mode`、`allowed_actions`、`anchor_precision`、`target_status`；R01 失败留在原触发页并清相关缓存。R01 成功才开壳并取 R02 轻量 `ReviewView`。未解析原件最低 target 为 Case＋DocumentVersion，`source_only` 只读可看；历史 Snapshot 必为 `historical` 只读。显式 target 优先于该用户＋Case 保存的上次视图位置。

| 打开入口 | `intent` 与初始焦点 | 选择/返回策略 |
| --- | --- | --- |
| 对话任务卡“查看并校验” | `full`；当前 Run，有未处理红项则首项，否则总览 | R01/R02 当前工作版，焦点到标题或问题；关闭回原任务卡并保留消息滚动/输入草稿。 |
| 原文/译段/Issue 证据卡 | `quick`；卡片固定 EvidenceTarget | 先侧板定位冻结版本；“展开双语对照”提升为 `full`，不改目标。关闭回原卡。 |
| 管理台已导出行/识别稿 | `full`；必须带该行 `displayed_snapshot_id` | 历史筛选命中旧快照时保持旧版只读；关闭恢复筛选、分页、展开和焦点。 |
| 管理台物理文件 | `quick`；带所示原件版、解析版和可用锚点 | 未解析 `source_only`，有快照时固定其版本；关闭回文件行。 |
| 直接打开 `/review` 深链 | 依 URL 的受控 target，R01 重新鉴权 | 没有来源页面时显示“返回对话/管理台”；无效 ID 不回退到另一个文件。 |

任务卡或管理台批次行本身未必携带 `EvidenceTarget` 必需的 `document_id + document_version`。当前 Run 总览先读 W04 的冻结 `source_versions`，历史批次先读 R16 的 `source_artifacts[]`，按 Task Spec／manifest 稳定顺序取第一份参与源版构造**最低原件目标**，R01 核对后 R02 展示整票树。随后 R03 找到首个未处理红项时，再以该 Issue 的精确 EvidenceTarget 经 R01 定位；若无红项停在总览。绝不拿 `case_id + run_id` 假装满足 R01，也不按文件名猜“第一张”。冻结源集合为空或快照 manifest 缺失时保留入口页并显示数据缺口。

`ReviewHost` 通过 ResizeObserver 读实际可用宽度，不靠设备名称猜断点。快速定位初次 620 px、可拖 520–900 px，主区至少保留 560 px 和 48 px 间隙；不足时临时将导航从 232 px 折为 64 px，仍不足就全屏。完整复核默认至少 832 px，无法同时留 560 px 主区就全屏；1440 px 完整复核必为全屏双语对照。宽度偏好来自 P01，只用于快速定位；完整复核使用 `max(832,偏好宽度)` 且上限 900。用户主动拖窄时切单栏标签并常显“展开对照”；不能把两张整页 A4 缩到不可辨字。拖拽柄支持键盘左右各 32 px、“缩小/放大”、双击重置；操作只改布局，绝不重跑 OCR、清编辑表单或改锚点。快速定位宽度在拖动时本地预览，释放后以 P01 `expected_version`＋幂等键保存；失败保留可见宽度并提示未同步、下次打开按服务端值恢复。完整复核拖窄只影响本次视图，不覆盖保存的快速宽度；设置页滑块仍需明确点保存。标准滑入 160–220 ms，定位不超过 240 ms；`prefers-reduced-motion` 或 P01 减少动效时瞬时切换。

顶部固定栏保留 Case／必要任务信息与最近保存时间，标题不附目标语言，不渲染“当前工作版”徽标；历史只读和版本过期仍明确显示。目标语言、版本与动作权限仍由请求和服务端结果固定，记录与确认清单继续可查。删除物理文件数、解析页数、红黄及无法判断数的独立统计横条；R02 风险数据仍用于疑点筛选和实际门禁，不在前端猜测。文件树层级为 SourceVersion → LogicalDocument → Section；左箭头只展开，文件名切换，未分类节显示待确认。视图标签“总览/原文与译文/字段/同票对比/疑点/处理记录”只改变本地视图，不写业务状态。工作区原文、译文、字段/疑点各自滚动；标题下方操作栏固定“保存草稿 → 复核完成 → 导出”，禁用原因仍来自 R02/R13/W04，灰按钮下不铺长说明，按钮提示、检查清单和请求错误保留。关闭时若当前编辑器有未提交内容，弹“继续编辑/丢弃未保存更改”；关闭后焦点回触发控件，不在多弹层中乱跳。

## 3. 轻量树、按需内容与来源双向定位

R02 只读抬头、文件树、风险/门禁摘要、版本指针、每份源文件的受控预览 ID 和允许动作，不能被前端当成原件全文。当前工作版的 R02 还给 `review_state_version` 和 `run_event_cursor={run_id,last_seq}`，历史 Snapshot／仅原件视图不给该游标；后者不得错误订阅当前 Run 事件后把历史字段刷新到旧快照。选中文件/区段后分开拉取：当前版 R03 字段/Issue 请求带 `run_id、business_revision_id、review_state_version`，R04 明细/检查带业务版和同一复核状态版；历史版 R03/R04 只带 `snapshot_id`，所有页都读被冻结的处置和检查。分页遇 `409 PAGE_STALE` 先丢弃当前页串、重取 R02 的复核状态版，再从第一页恢复所选字段／Issue ID，不能拼接新旧页。R05 分页译段；每份参与物理 SourceVersion 各有一份 R06 PreviewArtifact/preview_id，先按选中文件取 manifest，再只读当前区段的 `reading_html` 或预览／下载 `draft_pdf`。浏览器只为可见页读 U07 PDF/图片原件 Range 或 U09 页图，DOCX 用 U08 受控净化段表。长 PDF 用 PDF.js 按可见页渲染，长表仅加载可见分页；不要一次把整票 PDF/OCR JSON/译段送入 React 状态。U08 的 `query` 只查当前解析版/节的原文；搜索命中页/段 ID 后再用 R01 的目标精度定位。原件/预览/正式 artifact 访问每次经 API 鉴权并遵守 `no-store`，浏览器不拿 MinIO 管理凭据或永久 GET 地址。

R05 的当前工作版请求每次显式带 `business_revision_id、translation_revision_id、compatibility_id?、section_id?、cursor?`；历史版带 `snapshot_id、section_id?、cursor?`。当前 Query key 包含身份世代、`run_id`、`working`、业务版、译文版、可选兼容 ID、节和游标；历史 key 包含身份世代、`run_id`、`historical`、`snapshot_id`、节和游标。版本或模式变化立即取消旧页并从第一页重新读取，不能把旧译段拼入新配对。

| 阅读控件 | 读取接口与绘制 | 正确的降级/错误 |
| --- | --- | --- |
| 物理文件/逻辑单据/区段切换 | R02 树给稳定 `document_id/document_version/parse_artifact_id/logical_document_id/section_id` | 未解析文件只显示物理行；混合 PDF 两种逻辑单据独立筛选、独立来源，但仍一个物理文件。 |
| PDF/图片原件 | U07 支持 Range 给 PDF.js/图片；U09 给固定解析版页图，缩放 25–300%、适宽和旋转 | 页未加载先占位，加载失败保留文件/页和重试；不能以 Markdown 转写冒充原件。 |
| DOCX 原文阅读 | U08 净化段、表、单元格、阅读顺序和锚点 | 不在浏览器执行 DOCX 宏或外链；原件无稳定页码时只说段/表/单元格。若显示渲染页，标明渲染版本。 |
| 页/段跳转、原文搜索 | U08 `query` 或已授权 U07 页文本；R01 归一目标 | 无可靠坐标跳页/段并显示“无法精确框选”；不得凭相似文本自制红框。 |
| 译段与译后版面 | R05 给源/译 segment ID 与对齐 group 供编辑和定位；R06 manifest 给逐源文件 `preview_id/source_version/preview_version/status/representations[]` 及 section/segment 到预览位置映射 | 首版每份参与原件必须有净化双语 `reading_html`，它是原译对照和复核确认的前置；`draft_pdf` 为可选草稿产物。右侧默认显示 HTML“译后样子”，仅 PDF 可用时给切换入口。`read_index` 明确“尚无译文”，不渲染空的假稿。 |
| HTML／PDF 草稿阅读 | `GET /previews/{id}/content?representation=reading_html&section_id=...` 按需取所选节；仅 manifest 标 `draft_pdf.available=true` 时用 PDF.js Range 预览该 PDF | HTML 只在限制脚本、表单、外链和跨域资源的隔离容器展示，来源仍是左侧原件；segment 点击只通过 manifest 映射回 R05/R01。HTML 缺失或失效时显示真实失败原因并禁止复核确认，不能拿译段列表或 PDF 冒充完整译后页面。旧预览过期时只读历史稿若保留，否则回固定原文，不能套新稿坐标。 |
| 草稿下载 | R06 `content?representation=draft_pdf`，仅当 manifest 标 `available=true` 且 `allowed_actions` 含下载 | PDF 自身必须有“待确认/草稿”水印；未生成或失败时按钮禁用并显示 `disabled_reason`，不阻断已有 HTML 的校验。下载失败只重读本预览，不出现在成功交付列表。 |

`PreviewViewer` 对同一 `preview_id` 先检查 manifest 的 `source_version`、业务／译文配对、`preview_version` 和 `status` 是否与 R01/R02 所选目标一致，再选择 MIME 匹配的 representation；不接受“有同名文件就可复用预览”的推断。默认译后版面用同源受控 URL 装入 `sandbox="allow-same-origin"`、`referrerPolicy="no-referrer"` 的 iframe，明确**不**开启 scripts、forms 或 top-navigation；服务端还须净化 HTML 并用 CSP 禁外部脚本／资源。React 不接收 HTML 字符串，也不调用 `dangerouslySetInnerHTML`。父页面在 iframe 加载后拦截所有链接点击，只让 manifest 列出的稳定 section/segment 锚点触发来源定位，其他链接不导航；`draft_pdf` 可用时才以 PDF.js 按页读取，可切整页／局部缩放。切源文件先取消上一份预览请求，不能短暂展示 A 原件旁的 B 译稿。R05 译段列表仍用于查看原译文字、对齐组、术语、QA 和执行 R12；R06 是“转换后的页面样子”，两者互补而非互相替代。

R02/R06 若标 `translation_scope=goods_description/selected_sections`，译文区标题下和草稿下载旁常显“仅翻译指定范围”，展开列出已选区段及未译区段；未选内容在右栏只以“原文保留／未翻译”阅读块呈现，不染成目标译文色，也不出现译段修订键。正式 R16 交付卡同样带范围标识，不能因按物理源文件生成一份 DOCX/PDF 就写“全文已译”。R13 只核冻结必译范围覆盖，疑点和来源仍可定位未选原文。

`SourceViewer` 的锚点叠层只在 R01 `anchor_precision=rect` 且原始页坐标/旋转/裁切变换元数据与当前页一致时计算矩形；缩放或切页仅重算前端投影，不改变源 ID。`page_only/paragraph_only/cell/none` 分别用页、段、单元格或无法定位说明，不画猜测框。风险红/待确认黄/选中蓝/已确认绿须文字角标并存；选中蓝轮廓不覆盖红风险。普通阅读不把全页字段涂满框。

目标导航顺序为：R01 冻结目标并获取资源 → R02 展开正确文件/逻辑单据/节 → 对应 U07–U09 页或 R05/R06 译段渲染完成 → 原文滚到视区中部并短时高亮 → 有效配对时按 `segment_link_group` 定位一到多个译段。用递增 `navigationToken` 取消旧点击/滚动任务；新目标和用户手动滚动立即停止自动跟随。原译不按像素比例同步；只有用户显式点“同步定位”、字段/来源或译段时再按稳定 ID 做一次定位。源框反选先判断译段：只有一个可靠译段时直接进入译文并定位，多字段不能让该情形退化为强制选择横条；多个译段才显示译段选择，没有译段时再按唯一／多个字段处理。点击译段反向定位源 segment。无可靠映射时展示 Issue/“未可靠对齐”，不猜附近文字。缩放、文件切换、布局切换后仍以稳定 ID 恢复选择，不使用旧像素坐标。

## 4. 字段、检查、疑点与人工输入的代码落点

`FieldsPanel` 当前版以 R03 的 `run_id + business_revision_id + review_state_version + logical_document_id + cursor` 分页，历史版以 `snapshot_id + logical_document_id + cursor` 分页；按“主体与联系／单号与引用／运输与日期／货物与包装／金额与贸易条件／翻译与质量”分组。字段卡保留原件角色、原文候选、规范值、人工采用值、单位、来源、审核状态和译文入口。`LineItemsPanel` 从 R04 独立分页，以服务端行 ID 表示一对一、一对多和多对一关系；金额、数量不在浏览器浮点计算结论。当前逻辑单据不适用的字段不渲染为空字段，未提取、候选、无法判断、已人工确认必须有不同文字。字段组展开状态可按用户＋Case 保留；换身份立即清理。

`IssuesPanel` 对 R03 的 Issue 以“未处理阻断／待确认／无法判断／已处置”筛选，文件和规则过滤只改变服务端请求条件。卡片主体按“问题说明／可能影响／推荐处理”分块；移除重复的 `rule_name · rule_version` 和重复 `conclusion`，原规则结果、依据与处置链继续在检查清单和处理记录保留。风险级别、当前状态和来源 A/B 按需显示，不将已裁定冲突和已解除门禁合成绿色“通过”。点卡仅改变当前选中、调用 R01 定位；五动作才打开对应表单。两个来源都含受控 EvidenceTarget，A/B 切换只换阅读目标，不改事实；跳转前保存当前 Issue、筛选、文件筛选与列表滚动，阅读区提供“返回本疑点”，在列表重新渲染后恢复原位置与选中。返回状态按身份、Run 和所见版本隔离，外部深链、Run／版本或身份变化时清除，不存原文或下载地址。没有可靠锚点时说明只可定位到页／段。“处理记录”视图按需读 M05 Run 时间线与 R04 检查清单，不从前端事件缓存拼审计历史。没有 Issue 时仍可从 R04 展开检查清单，分别展示 `passed / failed / not_applicable / not_covered / undetermined / not_run`，每项列适用条件、输入来源、比较口径和规则包版本；规则包未覆盖的地区、货类和 HS／证书情形不能在 UI 推断合规通过。

`ReviewForms` 用一个表单壳承载具体命令组件，壳只负责焦点、未保存草稿、版本基线、幂等键和提交反馈，不把所有写操作合成一个万能保存 API。每次打开表单，读取 R02/R03/R05 所见的原件、解析、业务、译文、Issue 版本并冻结为 `baseVersions`，把原文来源设为只读。编辑中收到 W04 新事件，表单继续保留用户输入，但顶部显示“有新版本，保存前需重新核对”；不自动替换输入。提交前仍带 `edit_kind、target、proposed_value、baseVersions` 调 R07，保留版本校验和后台影响计算，但弹窗不展示受影响规则、译段、预览、摘要、Run 和费用的技术清单；**R07 只是影响预览**，正式命令仍自行重新算依赖。版本冲突进入差异界面，不能继续旧提交；保存后按真实结果反馈新版本、更新中或失败。

当 W04 为 `awaiting_input` 且有活动 W05 请求时，校验区文件树可读原件并给“处理必要确认”卡；卡由 W05 `GET /runs/{id}/input-requests` 取得 `kind=document_boundary|source_language|translation_scope`、来源、候选、推荐值、请求版、`expected_parse_artifact_id` 与可为空的 `expected_business_revision_id`。货描范围请求并列有来源的字段／行候选与原文短片段；零候选不能让用户勾一个不存在的段，禁用确认并给 R11 重识别、W02 新任务及 W06 取消旧 Run 入口。“提交确认”只走 W05 `resolve`，带所选候选、理由、两个所见版本、请求版本及稳定幂等键；首次抽取前业务版为空时仍须核对当前无业务版且解析版未变。服务端接受后同 Run 新 Epoch，W04 更新状态；这时 **R09 不可替代 W05**，即使用户绕过禁用点，`INPUT_REQUEST_ACTIVE` 也应打开该请求而非偷偷重试 R09。若回答会改变冻结的文件集合／翻译范围，服务端 `NEW_RUN_REQUIRED` 返回可预填草稿参数：向导列“旧范围／拟新范围”，用户明确启动新 Run，旧 Run 及其记录不改。`awaiting_review` 表示可复核译本已出现，开放工作版允许的修订与 R13；`indexed` 的只读识别结果若 R02 `allowed_actions` 许可，可复核已有字段，但绝不出现翻译确认／导出。两张状态卡和按钮文案不能复用。

W05 待输入表单同时保存 `schema_version` 和 `request_version`：前者只规定答案结构，后者才是请求并发版。`resolve` 提交 `expected_request_version=request_version`、所见 `expected_parse_artifact_id`、可空 `expected_business_revision_id`、所选候选、理由与稳定幂等键。首次抽取前业务版传 `null`，服务端仍须核对当前无业务版且解析版未变；请求版冲突时保留输入、重读 W05 并由用户核对新版，不盲重提。

“申请重识别”由文件工具条调用 R11，表单列原件版本、当前解析版、按**整份物理文件**重跑的收费／时延和理由；提交成功只出现新 ParseArtifact／ExecutionEpoch 的处理进度，旧版锚点和旧快照仍可读。解析版更新后 R01 重新核对当前目标，无法映射的原区段标待复核，不把旧像素框投到新结果。“上传补充材料”回到第一个方案的同票 UploadWizard；“替换此原件”先读 S04、U02、U05，以 `replace_document_id/expected_document_version` 得到新 DocumentVersion。两种操作都不改已有 Run 固定输入；需要纳入处理时重走 W02/W03 新 Run。重识别与替换的入口文案、结果卡和版本号必须分开。

所有 R08–R12 命令使用同一用户意图的稳定 `Idempotency-Key`、适用的 `expected_parse_artifact_id / expected_business_revision_id / expected_translation_revision_id / expected_issue_version`；R11 另传当前 Run、解析版和理由。响应成功后仅根据返回的新版本及影响 ID 更新 W04、R02–R06、R13、M04 的查询，旧 Snapshot key 保持冻结。`409` 统一进入 `VersionConflictDialog`：并排显示“服务端当前值／你的未保存草稿”，允许复制草稿、重新读取并手动重提；不得以最后写入覆盖。`403/404` 立即清该目标的原文、译文、Blob 与本地表单并显示受限占位；`429/503` 保留草稿和幂等键，按服务端可重试条件处理，不能无限循环请求。

顶部操作栏“保存草稿”只调用**当前已打开编辑器**的保存命令；无编辑器或无变化时禁用，显示“先选择字段／问题／译段进行修订”。它不创建新的通用草稿接口，不等于“复核完成”。关闭含未提交输入的侧板先弹“继续编辑／丢弃未保存更改”；普通视图切文件或切布局保留当前表单内容和来源锚点。历史 `snapshot_id` 的 R02 `allowed_actions` 不含编辑，全部上述表单入口隐藏或只读，不能通过保留的本地草稿改历史版。

## 5. 复核确认、整组导出与正式下载

`ReviewExport` 将“复核完成”和“导出”拆成两个命令流程；组件只显示 R13、R14、R15、R16 的结果。R02 轻量门禁摘要用于页面即时提示，真正打开确认弹层时**重新 GET R13**，不以旧 Query 或前端计数判断可否确认。R13 清单必须逐行展示冻结 Task Spec 的源文件及内部逻辑单据／区段、目标语言、业务／解析／逐文件译文有效配对、TranslationCompatibility、输出格式、红项处置、黄项接受、无法判断、未覆盖规则、人工采用值、翻译 QA、预览与确认人，并保存本次返回的 Run 范围 `review_fingerprint` 作为命令所见基线。缺项使用服务端 `confirmable=false` 和对应 EvidenceTarget 呈现“前往问题”，但未知检查不写成“已通过”。用户从缺项跳过去修订后，回清单时重新 R13，不沿用旧版或旧指纹。

R13 和 W04 均暴露当前有效的 `current_review_confirmation_id` 与 `confirmation_status`；刷新或切页后从服务端恢复，不能仅依赖组件内保存的确认 ID。R13 必须把逐源文件有效的 `reading_html` 纳入复核门禁，缺失即列缺口并禁止确认；可选 `draft_pdf` 的缺失只在预览工具条显示禁用原因，不充当确认缺口。R14 成功后使用返回的 `ReviewConfirmationView` 展示冻结配对与确认人，再刷新 W04/R13。R15 只接受此时服务端仍标为有效的确认 ID，并从新读的 R13 取当前 `review_fingerprint` 作本次 `expected_review_fingerprint`；不能凭上次 R14 的组件内值跨刷新发起导出。

## 6. 跨页面同步、异常与阅读手感

复核页只在 R02 返回**当前工作版** `run_event_cursor` 时维护一条 W04 SSE：先以其中 `last_seq` 补订阅，按 seq 去重；修订事件触发对应 Query 失效，不在 R02、对话卡、管理行各自推断新状态。历史 Snapshot 与 `source_only` 不订阅当前 Run，也不因当前事件改变冻结页；R01/R02 按目标版锁定查询键。切换文件时保留左树展开、缩放和各阅读区滚动锚点；显式跳来源覆盖该次位置。1440×900 完整复核全屏先保证原译阅读至少 540 px 高，问题列表为可收抽屉；832 px 面板双栏展示可放大的原件局部与译段，不能把两页 A4 缩成无法判读的整页。620 px 快速定位侧板为单栏，顶端有“展开双语对照”。宽度变化不重发解析／修订请求。历史只读和当前版的标题、颜色、按钮要明显不同，风险红黄及选中蓝均附文字。

| 异常 | 保留与恢复动作 |
| --- | --- |
| W04/R02 断线或阶段数据尚未持久化 | 保留最后持久状态与时间；显示“正在恢复连接／阶段尚未形成”，按 seq 补；不显示猜测进度。 |

| 当前业务版与译文不兼容 | 译文／预览显示“待重算／旧版”，R13 列缺口，确认／导出禁用；不把上一版译段拼当前字段。 |
| 规则包未覆盖或无法判断 | 显示来源与原因，并在清单及审核记录中保留；仅未解决红项阻断，黄色及其他提示不阻断；页面读取服务端当前门禁。 |

### 3. 状态、缓存与版本联动

范围／批次／矩阵／关系 Query key 包含身份 generation、Case、Run 或快照、范围／批次及复核版本，筛选和游标也进入列表 key。账号切换、票／Run／快照切换清选择和临时重算状态；分页 `PAGE_STALE` 只触发一次范围与工作视图刷新，不在渲染中循环重读。历史不轮询当前 Run，也不把现行范围填进历史快照。

显式重算或关系／明细裁决返回新 Run 后：独立 `consignment_check` 经 `onOpenRun` 修改宿主的有效 target，重新鉴权并读取新 Run；`ReviewPage` 以 replace 更新 URL。翻译消费者维持原 Run，并以 2.5 秒后备读取新核对 Run；终态使 consignment、review-view、issues、run/w-run 失效重读。兼容绑定是否建立由服务端决定，仅刷新不会擅自宣称已兼容。核对批次按旧业务版保留；新解析／新人工修订未纳入时显示 stale。

证据点击先 R01 resolve，再以固定文档与解析版本取必要阅读视图。消费翻译 Run 不包含比较材料时只为证据栏取该材料的固定视图，不更换翻译 Run。`navigationToken` 每次点击递增；SourceViewer／PreviewViewer 的可选 `highlightDuration=2000` 使 HTML／PDF 命中短时蓝色高亮，没有矩形不捏造坐标。

### 4. 门禁与验证

当前实际 IssueForm 仍调用五项真实业务动作，忽略理由选填；比较关联表单不是第六种疑点处理方式。清单确认使用服务端 fingerprint 和当前业务／译文 ID；前端不以全部黄项勾选或字段确认作为导出门禁。仅相关未解决红项硬阻断，实际产物、权限、版本、确认依然由服务端把关。独立核对只有结果和审计，没有译本导出。

定向验证已完成 canonical 类型接线后的 `npm run build`、后续 TypeScript 工程检查、五语字典键覆盖和 diff 空白检查；未新增依赖、未跑全量测试。浏览器的真实字段位置、滚动、重算后新 Run 和翻译绑定由主线专项台账记实，尚未验证的流程不能因构建通过写为通过。EDI／专门格式的解析适配和规则覆盖由后端专项实现及样本验收决定，前端目录可选不等于所有格式已获完整认证。



联调反馈补正：固定旧业务版可为只读 historical，但其 Run 类型仍需从指定 Run 元数据读取，不能以可编辑 mode 推断是否为翻译消费者。只有真实快照入口避免读取现行 Run；重核对终态另设独立核对新 Run 切换兜底。PDF 证据将持续 targetRect 与短时 anchors 分离，局部预览定位裁剪外壳；两秒后蓝框消退不触发整页 scrollIntoView，防止滚到裁剪区外成为白页。

管理概览的 CaseComparisonSummary 也以真实 W04 监测显式重核对 Run，终态停止轮询并刷新范围／批次；请求身份仍保持对应票及 generation。读取失败原位重试，不永久保持无解释的忙态。


历史矩阵 rows 与 batch detail 必须传 snapshot_id，历史 rows 不携带当前 review_state_version。rows 缓存键含 snapshot_id；同一冻结批次在不同交付快照中的处置状态不得互相替代。原文证据和候选关系来自不可变批次 calculation／manifest，仍逐次鉴权。
