## 2. 通用工作约定

- **环境**：`docker compose up -d` 起 PostgreSQL（5433）、Redis（6380）、S3/LocalStack（4566）；后端 Python 3.12 独立环境在 `src/backend/.venv`，依赖由 `uv.lock` 锁定。一键启动 `scripts/start-backend.sh`。
- **迁移**：只走 Alembic，每批建表同时建约束与 RLS；业务表 `ENABLE` + `FORCE ROW LEVEL SECURITY`，运行时角色 `logistics_app`／`logistics_worker` 均 NOBYPASSRLS。
- **租户上下文**：每个事务先 `SET LOCAL app.tenant_id`。该语句不支持参数绑定，只能内联经 `UUID()` 规范化的值（见 `app/api/dependencies.py`）。
- **路由管线**：`trace_id` → Cookie 解析主体 → 写请求校验 Origin 与 CSRF → 事务 + 租户上下文 → Case 授权／状态／期限 → 幂等键 → 领域服务 → 统一错误封套。
- **幂等**：`app/api/idempotency.py` 按 tenant + actor + 作用域 + 键锁定，请求体规范化后哈希；同键同内容回放、同键异内容 409。
- **测试**：只跑改动模块与直接调用链，例如 `cd src/backend && .venv/bin/python -m pytest tests/test_conversation_pipeline.py -q`。调用付费接口的测试标 `@pytest.mark.external` 默认跳过；真实前后端场景单独记录，不以夹具替代。
- **外部服务**：当前 `.env` 已切 `PARSER_ADAPTER=mineru`、`MODEL_ADAPTER=openai_compatible`（真实付费）。无 Key 环境改回 `deterministic_fake` 联调，产出须显著标注。
- **提交**：一切片可拆多次提交，简体中文 `类型：更新内容`；只暂存相关文件，`.env` 永不提交。
- **子代理并行**：按文件边界切分，写明「不许碰的文件」，完成后由主线复核再统一提交。
