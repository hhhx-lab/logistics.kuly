实施前约定：响应DTO按真实路由输出及前端消费逐组发布，固定业务字段使用明确模型，动态JSON Schema仅允许JSON值，不以Any/unknown代替业务结构；SSE、文件、204单独分类。与正在修改复核/管理/扩展业务的任务按文件和函数协调，路由最后仅补response_model，不覆盖业务实现。

部署提供锁文件驱动的Web/API/独立documents、conversation、maintenance队列镜像，完整编排、迁移与检查点初始化入口；秘密只在运行时env文件读取，不入镜像或前端构建。构建需要新镜像/依赖下载时本轮不执行，先校验编排与既有本机环境入口；镜像实际构建、生产TLS/KMS、外部部署不是本轮已验事实。运行回滚仅切回兼容旧图/数据库的已发布镜像；破坏性迁移不自动downgrade，数据库恢复先重放独立删除账本。

灾备工具限定运维身份及隔离目标：加密数据库与对象备份、最多7天轮换、独立连续删除账本镜像/校验、离线恢复及撤权/删除重放门禁。备份不是WAL/CDC替代品；生产连续复制、主存24h清理、KMS和7天连续调度SLA须另有部署证据。恢复演练用独立工程库/桶，不恢复到当前运行库，不打印密钥/连接串，不让恢复出来的旧Outbox自动重投未知供应商请求。

观测提供后台循环成功/失败/时间/最后成功心跳与消费者ping、队列延迟/重试/待核查/删除逾期指标；指标不含票据内容、ID、Key或原始异常。告警仅形成可操作本地结果/Prometheus规则，不向外部接收人发送；部署接收端需明确配置。组件health与循环活性分开，健康不能代替容量和业务准确性验收。

实际结果在每组验证后追加；不将仅静态文件或模拟输出登记为完整生产验收。

## 部署与观测实际交付

ops包含Web/API/三队列Worker/维护/监控、独立迁移身份、只读运行env注入、非root应用容器、SSE代理与健康。根基础设施与ops/compose.yml+compose.local.yml+compose.recovery.yml合并配置校验通过。部署env中数据库/Redis/S3必须使用容器内可达地址，S3公共端点保持浏览器可达；不能把本机127.0.0.1配置直接塞进容器。API身份与Worker受限身份需区分；本项目当前Worker需读取认证租户目录及SET ROLE logistics_worker，部署身份仅授这些必要权限，不可用superuser长期运行。迁移身份不得向Web/API公开。

/api/v1/ops/metrics为有ops_health权限的当前租户指标；同路径/prometheus为文本。独立monitor按全部署逐租户FORCE RLS聚合并ping规范命名Worker。cycle心跳含publish/recovery/retention/monitor，24h失败步骤、Outbox最老延迟、未决受理、过期Turn租约、超过24h删除。模型计量仅投影最近24h每租户最多1000步骤和1000会话账本：真实调用、token、缺usage、已知人民币费用、未知费用次数、调用耗时p50/p95；为有界样本，不能声称全量计费报告。真实读取13个非fake记录，43323tokens、3项缺usage、13项费用未知，旧报价未核实；不填假0总费用。旧本机Worker名字无法反推出队列，state=unknown；规范部署名字documents@/conversation@/maintenance@才可按队列报活性。

生产仍需真实镜像构建/签名、TLS反代、监控scrape与告警接收端、容量/并发证明。ops/alerts.yml提供本地可执行告警规则，无外部通知发送。后端镜像明确使用PGDG PostgreSQL16客户端，避免bookworm默认15客户端无法备份PG16；本机缺uv/python3.12/nginx所需完整镜像，本轮按约定未下载，不将compose config通过当作镜像启动通过。

## 加密备份与恢复实际交付

ops/disaster_recovery.py为显式运维工具，AES-256-GCM分块加密、认证终帧防截短、密文0600，密钥独立env。备份先停业务写入，PG custom dump与S3所有对象版本形成同一静止边界，含逐对象/DB校验和；无在线跨PG/S3原子一致承诺。精确保留原ACL/PUBLIC撤权，禁止统一重新授DML覆盖规则输入追加边界。最多7天备份轮换由独立小时循环执行。删除账本密文每5秒镜像到另一独立故障域；镜像校验seq/hash，不能替代零丢失WAL/CDC/KMS。两个目录只在逻辑上不同不证明物理独立，部署须提供故障域证据。

恢复只允许logistics_restore_*库与logistics-restore-*桶，目标须预建空库/私有版本桶；须与live不同。使用最新独立账本，旧备份不能覆盖新删除意图；先认证解密、校验DB/object摘要、恢复精确ACL、拒绝已删前缀和DeleteMarker旧对象复活，再重放撤权，始终service_opened=false。对象当前版本恢复成新S3版本ID，原备份中旧版本及版本ID保留在密文清单，但不会伪装成当前对象；若应用未来按S3版本ID读取需专门映射。

真实隔离演练通过：从live仅读取schema（不复制业务数据）到两新独立工程库，构造2张票及4份合成对象版本。备份后独立账本追加一张删除意图，恢复后只出现1份当前有效对象且字节等于latest；已删票状态为DELETING、对象不恢复，DeleteMarker隐藏的旧内容不复活；受限规则输入UPDATE拒绝、PUBLIC受限函数EXECUTE拒绝、cases SELECT正常。随后仅在恢复库调用真实execute_purge，已删Case物理移除，最小回执保留。工程库/演练桶/密钥/脚本均清理。本轮未在live恢复、删除或重投Run，未向供应商发送请求。

恢复库开放前必须再核对schema/检查点兼容、全部撤权项物理清理完成、签名/租约边界、旧Outbox及未知供应商受理，不能直接启动旧任务。生产24h清理SLA、完整业务数据恢复、连续复制故障切换、KMS与7天调度仍是外部验收门槛；本机合成隔离演练不能冒充生产证明。

## 部署操作

1. 按ops/deploy.env.example配置独立env路径、不可变镜像及账本/镜像/备份目录；目录0700、容器uid10001所需最小权限。数据库预建角色、扩展、连接/schema权限按迁移脚本，保持NOBYPASSRLS。
2. 已存在依赖无需重建时，docker compose --env-file 部署.env -f ops/compose.yml config验证；本机完整栈加-f docker-compose.yml放最前及-f ops/compose.local.yml。build在获准下载依赖/镜像之后执行，不将根.env复制进镜像。
3. docker compose ... up -d：migrate完成→三消费者/API→Web；GET /api/health/live与/api/v1/health/ready分别验证存活和组件。系统版本与冻结旧图不能不兼容，滚动更新先停止新入口并等待/安全续跑既有账本。
4. 回滚只切回兼容当前schema、冻结workflow/prompt/graph版本的既有不可变镜像，先核对Alembic版本；不自动downgrade有业务数据表。数据恢复一律走独立演练库、最新删除账本及撤权清理门禁；物理恢复后不开放旧Outbox盲重投。
5. 恢复编排-f ops/compose.recovery.yml独立启动ledger-mirror/backup-rotation。backup profile仅在运维已停写后手动docker compose ... --profile recovery run --rm backup，之后确认密文与摘要、恢复写入口；备份缺档或镜像stale须告警处理。生产在线不停写备份应改为经验证的数据库快照/对象复制及WAL一致边界。
