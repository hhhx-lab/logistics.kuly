## 3. 解析服务（MinerU）

### 2026-10-02 官方协议复核与修正

依据 [官方 API 文档](https://mineru.net/apiManage/docs) 和用户指定 handwriting-web 实现复核：v4 申请批次→PUT→查询批次→下载结果的原调用顺序正确，上传后官方自动启动解析，无须再次 POST 创建解析任务。原实现未传 `model_version`，按官网默认使用 pipeline；`language=auto` 不在当前官网语言表中，因此新请求改为显式 `model_version=vlm` 与 `language=ch`。这两项是已确认的配置缺口，尚无证据证明它们是原任务长期 pending 的唯一原因。下面 9 月 30 日的探测记录仅保留当时样本结论，不代表当前 vlm 或所有格式均通过。

`MINERU_BASE_URL=https://mineru.net/api/v4`，异步批量协议全流程走通：

1. `POST /file-urls/batch` 申请上传（`enable_table=true`，`language=auto`）→ 返回 `batch_id` 与签名 PUT 地址
2. PUT 直传原件字节（**该地址不接受额外请求头**，带 Authorization 会失败）
3. `GET /extract-results/batch/{batch_id}` 轮询 `state`：`pending` → `done`
4. 下载 `full_zip_url`，解包取 `*_content_list.json`

| 能力 | 结论 | 对锚点契约的意义 |
| --- | --- | --- |
| 认证 | 支持 | — |
| 签名直传 | 支持 | 原件字节不经过本服务内存 |
| 按 batch_id 查任务状态 | **支持** | 关键：Worker 崩溃后可凭请求键核查是否已受理，不必盲重投或转 `paused_reconcile` |
| 块级 bbox | **11/11 块均有** | 可满足 `precision=rect`，不必退到 `page_only` |
| `page_idx` | 支持 | 页级定位可靠 |
| Markdown 阅读副本 | 支持 | 作阅读视图，不作唯一事实层 |

内容块字段为 `type / text / text_level / bbox / page_idx`。结果包还含 `layout.json`、`model.json` 与 `origin.pdf`。

合成样件的表格是用文本行画的，因此 `table` 块数为 0，这符合预期；真实扫描件的表格识别能力须用获授权样本另测。

## 4. 尚未验证的事项

以下属于方案第 7 节「仍需真实输入才能最终验收」的范围，本次探测不覆盖：

1. **识别准确率与翻译质量**：需获授权且带字段真值的多格式样本，按样本组 A–E 分别评测。合成样件只证明协议可用。
2. **真实扫描件的表格与跨页续表**：需低清、手写、混排语言样本。
3. **模型费用与吞吐**：真实中转服务无可信报价，`RUN_MAX_MODEL_COST_CNY` 当前留空，仅执行保守 token／调用上限。工程已支持`MODEL_PRICES`冻结核实模型价；参与角色全部匹配时可启用模型人民币上限，缺价时拒接。OCR通过`OCR_PRICES`按页/任务及模式冻结估算；缺官方费用回执的实际OCR保持未知，不能声称精确总预算。
4. **法规规则包**：未审定，相关结论一律显示「未覆盖」。
5. **MCP 远端连接**：`MCP_ALLOWED_HOSTS` 仍留空（留空表示不允许新增任何外部连接），D6 联调 DeepWiki 时再填。
