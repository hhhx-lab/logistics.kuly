## 1. 交付边界与最短执行链

对话 Agent 是**受限的任务入口和解释器**。它从有权的业务视图取事实，用确定性程序判状态和数值，必要时让对话模型选择候选意图或组织自然语言；文件字节、整份 Markdown、OCR、字段真值、规则裁定、译本生成均由独立单证工作流处理。用户 Skill 只能引用已注册动作；MCP 必须经过真实客户端、逐工具授权和调用审计。外层模型无任意 SQL、文件系统、网络外发、字段写入、Issue 放行或直接登记导出的工具。

一条新消息的目标路径是：`鉴权冻结本轮引用及回合 → 宽松业务关联与受控意图 → 必要工具/工作流 → 事实与来源组装 → 模型正文增量作为待核验草稿显示 → 最终检查并原子定稿`。明确任务和状态查询不增加模型分类；模糊业务动作必须澄清或受限规划，不能因有文件标签就自动收费识别。自然解释采用同一次流式请求中的范围前缀及正文，不每轮额外调用领域模型。每轮最多两轮计划、四次逻辑工具调用，默认值来自 `.env`。2026-10-05本轮仅修订方案，现有代码仍先完整生成后输出；细则以[最终补全修复方案](最终补全修复方案_对话记忆与验收.md)的“宽松领域关联与增量答复”为准。

首版的 `read_index@1`、`translate_review@1` 是项目注册的固定工作流。主处理卡明确指定翻译流程；上传后仅问尚未解析文件内容时指定只读识别；用户自然语言仍可走相同路由。`prepare_task` **持久化可编辑 Task Draft**，做不收费的确定性校验并返回缺项、候选与草稿 ID；不调用 OCR／模型，也不创建 Run。用户删除未启动草稿时走 `DELETE /api/v1/task-drafts/{id}` 写内部撤销时间，已验收原件仍归 Case，撤销草稿不可启动；已启动草稿不能删除，只能对后续新要求另建草稿。只有文件成功接收、同票归属清楚、任务模式和必需参数齐全后，`start_run` 才消费草稿并冻结 Task Spec。翻译缺目标语言时追问，用户记忆里的常用语言只显示建议，不能暗中代填。已启动 Run 的文件集合、目标语言或范围改变时创建新 Run。

| `app/conversation/tools.py`、`evidence.py` | 固定工具白名单、DTO 校验、证据读取与 `AnswerDraft` 验证；链接到统一 `EvidenceTarget`。 | 让模型自报页码或拼接对象存储 URL。 |

| `app/api/` | `/api/v1` 认证、回合命令与回合事件、记忆建议/确认、会话生命周期的 HTTP/SSE 适配。 | 在 API 路由里写大段 Prompt 或散落业务规则。 |

建议只加上述直接需要的模块。数据库表、对象存储、RLS、Outbox 和通用接口语义由共享契约与数据/API 方案落实；这里的服务都通过仓储和领域命令调用，不从聊天处理器私建一套事实缓存。

## 3. 回合事务、状态和 LangGraph 落地

### 3.1 一轮如何开始与结束

1. `POST /api/v1/conversations/{id}/turns` 必带 `Idempotency-Key`，消息正文、已成功上传的文件引用及 Lexical 产生的结构化 `/ `、`@ `标签分开提交。服务器从登录会话取 `tenant_id/user_id`，验证会话属于本人、未结束、标签 ID/版本仍可用。原样文本 `/ `或`@ `不能伪造标签。
2. 在一个事务中按 `(tenant_id, conversation_id, idempotency_key)` 查重；同键同请求摘要回原 `turn_id`，同键不同参数返回冲突。同一会话另一非终态回合占有有效租约时返回 `409 TURN_BUSY`，不暗中排队；后台单证 Run 不占这个回合锁。事务内重新核验标签的 Case/版本归属并写一次不可变 `ReferenceSnapshot`，使本轮对话图读取的是已冻结引用，而不是重新按“最新”解析。
3. 与引用快照同事务插入用户消息与 `ConversationTurn(pending)`，记录图版本、`chat.system` 等所需 Prompt 版本/哈希、非秘密模型配置版本、引用快照 ID、回合序号和租约。`conversation_thread_id` 为服务端随机不透明 ID，在所属租户映射表中保存，不能由文件名或身份明文拼出。
4. 使用与锁定依赖版本相符的 PostgreSQL checkpointer 编译对话图，调用同一会话图线程。入口从数据库重新加载身份与回合；LangGraph 检查点只用于运行位置，消息、引用和审计以领域表为准。每个新回合**显式清空** `intent_candidate_id、tool_result_ids、evidence_ids、draft_id、decision、error_class、plan_rounds、tool_calls`，不能因 `TypedDict total=False` 的部分更新而沿用上一轮临时状态；SSE 游标和旧 `thread_id` 更不放入模型上下文。
5. 节点完成后先提交最终消息、证据关系、工具调用记录与终态事件，再让回合进入 `completed`；失败写 `failed` 或 `interrupted` 及可解释错误。最终回复只来自已提交消息；HTTP/SSE 断开不撤销已启动后台 Run。

首版 `ConversationTurn` 状态为 `pending/running/completed/interrupted/failed`。API 租约按心跳续期；扫描器发现过期时，若最终消息已落库就补记完成，否则原子标中断、释放会话占用。中断的半截模型草稿不可拼接为最终答复；用户重问产生新回合，已调用的写工具按原回合工具调用幂等键复用结果。同一原 `Idempotency-Key` 永远返回原回合，不因中断重开第二任务。

### 3.2 图状态和固定条件边

`ConversationState` 只保留 `conversation_id、turn_id、active_case_id、reference_snapshot_id、intent_candidate_id、tool_result_ids[]、evidence_ids[]、draft_id、decision、plan_rounds、tool_calls、error_class` 等短 ID。节点从有租户边界的领域表读真实数据，不能把上一次 checkpointer 中的身份或权限当成当前授权。意图候选、模型草稿和工具结果是带 owner、TTL 与版本的暂存对象；日志不存全文。图版本随回合冻结，部署新版本时在途旧回合用旧图完成或显式中断，不在恢复中途换边。

| 节点（沿用骨架） | 读取 → 写入 | 条件边/失败处置 |
| --- | --- | --- |
| `scope_and_freeze` | 读取 C04 事务已保存的认证主体映射、本轮 `ReferenceSnapshot`、活动 Case 与标签版本；再次核对当前访问权，不另写第二份快照或改其版本。 | 撤权、跨 Case 或引用缺失直接失败；同票多文件允许。无业务版的原件只冻结实际存在的 DocumentVersion。 |
| `fast_path` | 只对明确业务动作、状态、精确字段、结束服务及明显攻击走规则分支；范围允许材料相关补充知识，不用学科词黑名单。 | 明确动作到 `execute_tools`；缺项到 `clarify`；含糊动作到 `intent_and_plan`；一般解释在答复流内判断关联，不额外分类。 |
| `intent_and_plan` | 只给模型本轮授权范围、短上下文与可用动作 schema；产出结构化 `IntentCandidate`。 | 候选无效最多一次格式修复；仍无效则澄清/明确失败。最多两轮计划，不放任循环。 |
| `execute_tools` | 依据服务端白名单核对每个候选，按已冻结范围执行；只读查询可有限并发，写命令串行重新鉴权/查版本/幂等。 | 得到充分证据到 `compose_answer`；缺参数或冲突到 `clarify`；只有仍在预算内且确有新信息才重规划。 |
| `clarify` | 合并真正阻断下一步的条件，形成一条简短问题与选项；准备或更新 `TaskDraft`，或展示已有 Run 的活动 `InputRequest`。新 `InputRequest` 只由单证工作流在执行中创建。 | 回合完成；不启动缺参数的翻译，也不假报处理中。 |
| `compose_answer` | 精确事实优先用服务端格式化；复杂解释才调用 `chat.answer` 生成分段 `AnswerDraft`。 | 不在此节点写业务事实。 |
| `verify_and_emit` | 核验证据归属、版本、数值和输出边界，原子生成正式消息与来源卡，替换生成草稿。 | 正文增量可先标待核验；事实缺证据改为“无法确认”，不把草稿直接记成正式事实；推理/协议及未知占位符不显示。 |

`fast_path` 的精确匹配依据是结构化标签/卡片 action、现有 Run ID 与可识别字段键，不靠文件名猜历史 Case。自然语言的工作流建议仍交给 `prepare_task` 以已注册定义复核；`IntentCandidate` 不是 Task Spec，也不能直接调用收费步骤。工具最大次数计算**逻辑业务调用**，分页或一个工具内部查询不许变相绕过上限；超限说明需要缩小范围。

### 3.3 内部工具与前端接口连接

| 对话行为 | 内部受控服务 | 对外呈现与版本要求 |
| --- | --- | --- |
| 主卡开始翻译/自然语言发起 | `prepare_task` → `start_run` | `/task-drafts` 返回缺项/摘要，`POST /runs` 接草稿 ID 和幂等键；在任务卡显示真实 Run 快照/事件。模型不提交节点列表。 |
| 上传后问未解析文件内容 | `prepare_task(read_index)` → `start_run`；建立 `AssistantContinuation(status=waiting)` | 先给“正在识别以回答问题”的已持久化说明和 `run_id`；索引完成再产生证据答复，详见 7.2。 |
| 问进度、失败、疑点 | `get_run_timeline`、`list_issues` | 读取 `/runs/{id}` 和事件账本；状态回答引用 RunEvent 而不是伪造原文卡。 |
| 问字段、冲突及“为何标红” | `query_case_facts`、`query_provenance`、`list_issues` | 只返回本轮冻结版本的字段/规则/Issue 与来源；证据卡经 `/api/v1/evidence/resolve` 可打开侧栏。 |
| 问历史票据 | `search_authorized_cases` 仅用于 `@ `选择/显式管理台入口 | 未绑定时不按相似文件名自动取另一票；摘要仅用于候选排序，最终回查字段与原文。 |
| 手动选择 `/ ` Skill 或 MCP | `resolve_capability_selection` 核对 C09 注册 ID、启用版本、schema 哈希、用户授权与白名单动作 | 前端候选来自 `GET /api/v1/extensions/available`；用户 Skill 说明是单轮低信任资料，不能变成新系统工具。 |
| 执行已授权 MCP 工具 | `call_mcp_tool` 按 schema 构造参数、按 Case/片段限制外发、记调用审计；需要单次外发授权时建立 `MCPChallenge` | `GET /api/v1/mcp-challenges/{id}` 展示目标和数据范围，批准/拒绝分别走 `POST /api/v1/mcp-challenges/{id}/approve`、`POST /api/v1/mcp-challenges/{id}/reject`；批准后重验授权与 schema，结果只作外部资料，按 parent turn 追加后续消息，不占新用户轮次。 |
| 要求修订、裁定或正式导出 | `open_review` 提供目标和影响说明 | 跳到 `GET /api/v1/cases/{id}/review-view` 对应当前/历史视图；实际写入走复核独立业务命令、检查清单与人工确认。对话模型不能替用户执行放行。 |
| 用户记忆建议 | `propose_user_memory` 只建立待确认建议 | 设置页或对话卡点击确认后才写有效 UserMemory；系统提示词始终只读。 |

任务卡、校验区和管理台状态只读同一个 RunEvent/Run 快照；对话 SSE 负责本回合文本与工具卡，不替代后台 Run 的事件流。前端先取持久快照再订阅，按序号去重和补事件。

MCP 连接在调用前必须按服务端当前启用版与 `tools/list` schema 快照重新核对；schema 改变、授权撤销或连接失败直接停用这次调用。若工具要外发本票材料，挑战卡冻结目标主机、工具、参数摘要、文件／片段和数据级别；用户批准后再核验一次会话未结束、Case 权限及同一冻结引用，只发送获批的最小数据。原 Turn 以已持久化的“待授权”卡片完成并释放会话锁；获批调用由 Challenge ID 自身租约和幂等记录驱动，经独立续答写入器追加关联原轮的 continuation 事件，不恢复或并发写入后来 Turn 的图检查点。会话已结束或拒绝授权只记受限／拒绝状态，不追加外部事实答复，也不取消独立单证 Run。公共只读 MCP 联调样本只能证明协议可用，不能作为物流业务事实来源。

## 4. `@ `引用冻结与单票隔离

`@ `选择器可返回 Case、Run、固定原件或 Export Snapshot，发送时服务器逐层检查 `tenant → user/Case 权限 → Run/Document/Snapshot 归属 → 版本和解析/译文配对`，写不可变 `ReferenceSnapshot`。同一会话只能绑定一个 Case；第二票的标签返回“新建会话查看另一票”。未绑定的新会话只带系统策略与本人确认偏好，不扫描历史 Case。上传成功且归票明确可绑定当前 Case；上传中的文件仅供元数据展示，不能读正文。

| 标签 | 本轮冻结和问答范围 |
| --- | --- |
| Case 当前指针 | 发送时冻结当前业务 `revision_id`、参与原件及有效解析版本；未解析时只保存实际已有文件版本。只在这票内按问题查必要字段、Issue 和 Run。 |
| Run 指针 | 固定该 Run 的 Task Spec、参与原件版本；工作版问题发送时冻结本 Run 所用解析/业务版及有效译文；“导出结果”选择该 Run 最新成功快照并明示时间。 |
| 固定原件 | 永远固定 `document_id + document_version`；字段问题另冻结当时有效 `parse_artifact_id`。默认只问这张物理文件；跨同票材料核对须用户明示。混合 PDF 有多个可能区段时先请选节。 |
| 固定逻辑单据/区段 | 冻结所属物理原件版本与解析版、`logical_document_id + section_id`；仅在该区段内查字段/片段。旧解析版的节只作历史只读，不自动映射到新解析的相似节。 |
| Export Snapshot | 固定整个 manifest：源文件、解析、业务、各文件所属 Run/语言/译文、报告和导出时间。历史问答只读这份清单，不拼当前字段。 |

同一轮最多选择一个 Export Snapshot；若又选其清单中的固定 DocumentVersion/Section，Snapshot 仅提供历史版本语境，默认事实范围是所选文件/区段与快照的交集，而非整份快照文件的并集。用户明确要求同票其他材料比较时，工具才可在同一冻结快照内扩展到相应文件，并把所有来源分别标明；跨快照比较首版先请用户分轮查询。管理台文件行预置的“快照＋这张原件”因此能在刷新后恢复同一问答范围。

译文查询不能把固定原件误解为固定语言。明确指定 Run/译文版时先验证原件归属、业务/解析依赖与历史或当前有效配对；只指定语言时先查活动 Run 中含该原件的有效译文，再查该语言的其他有效结果；没有语言时优先活动 Run 的有效目标，若没有活动目标且只有一个有效结果才可用，多个语言或不可比较结果须澄清。译文过期时可以解释旧稿但必须标历史，当前问答只用原文和当前业务事实。`TranslationCompatibility` 必须由依赖与 QA 服务确认，不能凭时间最新或版本号大小推断有效。每个回复保存本轮使用的业务/译文/预览版本；后续修订只给旧消息加历史提示，不改旧文字。

关联 `/ `能力与`@ `同用时，先完成上述身份和版本冻结，再核对扩展 ID、启用版本、工具 schema、允许动作与数据范围；远端返回仅为低信任资料。用户自建 Skill 文本不写进全局系统策略，也不默认为下一会话可用。

## 5. 上下文装配、20 轮摘要与用户记忆

一个完整轮次＝一次用户提交及对此的最终 Agent 答复；工具事件、RunEvent、延迟答复卡不另计用户轮。每轮只装配：项目发布的系统策略、当前用户已确认偏好、当前消息及标签、当前 Task Spec（若有）、本会话最多最近 20 个完整轮次、本会话更早轮次的滚动摘要，以及按问题从本轮冻结 Case/Run/文件取的最少证据。**不自动加载过去会话的消息或摘要，也不自动加载其他 Case。**

摘要存 `conversation_id、covers_through_turn_id、source_message_hash、prompt_version、summary_text/object_id、token_count`。当第 21 轮将进入上下文或提前触发 token 限制时，对未覆盖的连续旧轮次增量压缩，再把直接窗口控制在 20 轮内；摘要只留任务目标、当前明确约束、待澄清点和稳定业务 ID/版本，不复制原件全文或把旧回答数字升为事实。摘要生成失败时仍按预算取较近轮次，必要时重问，不能借另一会话补齐。结束对话后摘要只供该会话历史查看；新会话查询条件绝不包含其 ID。

输入预算为 `min(CHAT_INPUT_TOKEN_BUDGET, 当前模型可用窗口 − RESPONSE_TOKEN_RESERVE)`。起始配置沿用 24,000/4,000 token；摘要至多 2,000，检索片段总计至多 6,000、最多 8 段，单段建议最多 1,000。优先模型官方 tokenizer，缺失时保守估算并用实际 usage 校准。超限顺序：移除重复工具文本 → 缩小低相关来源片段 → 增量压缩较旧本会话轮次；**系统策略、本轮请求、结构化引用、任务参数和证据 ID 不可截断**。仍超限则请缩小问题范围。

`UserMemory` 只存本人确认的长期偏好，例如解释语言、术语解释样式、常用译本语言建议。建议状态不进入模型；“这次翻成英文”不自动保存。确认/编辑生成新版本，删除令后续回合不可见；每轮冻结实际读到的记忆版本，当前生成中不受后来编辑影响。内容校验拒绝客户姓名地址、金额、原文、密钥和单票事实；偏好与当轮任务冲突时当轮任务优先，和系统/证据冲突时系统/证据优先。设置页的“查看本轮上下文”只公开版本标识、轮次范围、偏好数量和引用范围，不暴露系统 Prompt 全文。

身份隔离由数据库查询中的租户与 Case 授权、RLS、对象下载鉴权共同执行。图检查点和短暂候选也带租户/用户映射；缓存键含身份与版本。身份切换、权限撤销或删除后，旧来源深链重新鉴权并停止返回正文。任何查询都先过滤授权，再执行全文/摘要搜索；不能先检索再在结果层遮住别人的文件。

Case 到达 30 天期限或 owner 主动删除时，本会话若绑定该票即停止新 Turn 和 AssistantContinuation 的事实答复；正在生成的 Turn 在**每个已校验段落发流前及最终消息提交前**重查 Case `active` 与期限，删除赢得行锁后不得再发送单票正文。已产生的来源卡、摘要、消息与该会话图检查点随整票清理，不允许从历史对话缓存或已冻结 `ReferenceSnapshot` 重新读出。删除令 Case 立即不可读，物理清理由[数据存储与接口方案第 4.4 节](后端开发方案_数据存储与接口.md)执行。UserMemory 只保留与单票无关、用户已单独确认的通用偏好；与被删 Case 相关的待确认建议及来源指针清除。会话最长 20 轮规则只适用于仍有效的会话，不是删除后的数据保留豁免。

## 6. 项目统一 Prompt Registry

所有项目维护 Prompt 放在 `app/prompts/templates/<prompt_key>/<version>.md`，由 `app/prompts/manifest.toml` 明确注册；`registry.py` 读取包内文件、校验变量集合与 SHA-256、按 `(key, version)` 返回不可变 `PromptSpec`。使用标准库 `tomllib` 和严格占位符渲染即可，首版不要为了模板功能增加可执行模板引擎。既有版本文件发布后不得原位改字；调整要新增版本并在发布清单切换默认版，同时保留活动回合/批次所需旧版。启动时检查缺文件、重复键、未声明变量、哈希不符、缺少输出 schema，检查失败禁止该能力接单。Prompt Registry 由项目发布维护，普通用户没有编辑接口；用户 Skill 与 MCP 内容只能作为单轮低信任 `task_material` 附加。

| Prompt key | 模型角色/调用位置 | 主要输入和结构化输出 | 附加服务端校验 |
| --- | --- | --- | --- |
| `chat.system@1` | `CHAT` 每轮 | 服务范围、信任层级、记忆边界、工具限制、证据表达；项目发布的系统消息。 | 不把用户材料拼在 system 段；回合冻结哈希。 |
| `chat.intent@1` | `CHAT`，仅含糊意图 | 本轮问题、获授权标签、可用工作流/工具 schema → `IntentCandidate`。 | 只接受注册 workflow/action、可访问资源和额度内工具计划。 |
| `chat.answer@1` | `CHAT`，复杂解释 | 已验证的最小事实卡与问题 → 带 `claim/evidence_ids` 的 `AnswerDraft`。 | 来源和值逐段验证，禁止凭模型造坐标/已执行状态。 |
| `chat.session_summary@1` | `CHAT`，超 20 轮或预算 | 本会话待压缩轮次及旧摘要 → 限长、无业务真值断言的会话摘要。 | 不含其他会话；摘要事实仅存 ID/约束，绝不作证据。 |
| `document.extract@1` | `EXTRACT`，复杂字段/行 | 解析片段、类型和 schema → 字段候选/行/来源片段 ID。 | Pydantic、角色和来源归属检查；细则见工作流方案。 |
| `document.translate@1` | `TRANSLATE` | 片段 ID、原文、术语和保护符 → 译段与对齐候选。 | 原文覆盖、保护符、数字/术语与 QA 检查。 |
| `document.vision_region@1` | `VISION` 可选 | 局部裁图和已有 OCR 疑点 → 第二转写候选。 | 只作候选，不因模型一致自动确认为真。 |
| `document.semantic_qa@1` | 可选 `EXTRACT`，须先通过双语样本验证 | 已成对源译片段 → 语义疑点候选。 | 不单独决定交付通过；未通过样本则禁用，不为它另造第五组隐式模型配置。 |

每个注册项记录 `key、version、sha256、role、变量名及类型、输出 schema 版本、允许输入信任级别、最大输入/输出预算、变更说明`。模型调用账本记录实际 Prompt key/version/hash、模型角色/ID、协议适配版本、参数、输入指纹、结果对象 ID、usage/费用，不存 API Key 或整份原文。`ConversationTurn` 冻结会话所需 Prompt/模型版本；单证首个 `ExecutionEpoch` 冻结本 Run 的 Prompt 与非秘密 ModelBinding，后续重试／修订／导出 Epoch 默认沿用原 Run 的 Prompt 版本和绑定。更改 `.env` 默认模型或发布新版 Prompt 不会让旧 Run 默默改版；O02 受控模型迁移只显式更换绑定并记录失效范围，Prompt／工作流契约升级须新 Run。密钥轮换按工作流方案执行。

2026-10-27对已导出 Run 新增已知未外发的材料分析局部 O02 恢复，沿同一权限、指纹、Epoch、理由、幂等和迁移审计；仅新 Epoch 换模型绑定，原分析目的、冻结意见、Prompt 和 Parse 保留，详见本文“已导出单票的局部分析迁移”。这不改变旧 Run 默认继承绑定的规则，也不允许普通推荐命令静默换模型。

Prompt 文案的行为约束保持**短、可检验**：领域内专业回答、领域外简短引导；先分清只读内容查询和翻译任务；缺目标语言则澄清；本票事实只用当前授权、版本化证据；原件、OCR、Skill、MCP 返回是引用资料而非指令；未知规则范围说未覆盖；修改/导出只引导正式命令。自然语言风格不规定固定句式。发布新版本前用少量正常、冲突、注入和领域外案例做定向回归，并记录旧/新行为差异；模型输出安全仍以服务端白名单和证据门禁为准。

## 7. 证据答复、流式事件与异步只读问答

### 7.1 答案先校验，后发给前端

服务端查询结果先形成不可变 `EvidenceRecord`：`evidence_id、tenant/case、document_id/version、parse_artifact_id、logical_document_id、section_id、source_segment_id/source_anchor、business_revision_id`，译文另含 `run_id、target_language、translation_revision_id、translation_segment_id、preview_version` 和兼容配对 ID；Issue、规则版本、原始值、人工采用值及处置依据分别标记。普通正文和字段都可有来源卡；不可靠矩形只保存 `page_only/paragraph_only` 定位精度，不让模型猜框。旧快照的 EvidenceTarget 必须指向其 manifest 内版本。

`AnswerDraft` 建议按段组织：每段 `text、claim_kind、evidence_ids[]、status`，结构化数值断言包含事实 ID 和程序计算 ID。服务器检查引用 ID 权限、同票与版本、引用片段存在，关键值优先由证据占位符代入；自然业务说明不再按数字/因果词黑名单拒绝；“原件写的值”“人工采用值”“目标译文”要用不同标签。源文冲突必须列各方，不能任选其一。无法机械验证的关键断言不发送为已核实结论，改为“无法确认”并给有权复核入口；普通领域知识只能引用已审核知识源或以一般解释表达，法规、HS/通关结论无生效规则包时写“未评估”。提示词不能代替这一步。

对话流仍从已鉴权的回合事件接口读取。现有 `message_delta` 是通过校验的文本块，语义不改变；新增 `answer_preview_started、answer_preview_delta、answer_preview_reset` 专门承载待核验正文，避免旧客户端误把草稿当正式事实。预览逐块短事务提交后推送，同流最终 `message_final` 替换预览；失败 `message_error` 将已保存草稿标为中断且不进入记忆。断线按持久序号补齐，不再次调用模型。首次投放必须统一DTO、生成前端契约和消息渲染，服务端能力标记与客户端版本不匹配时维持旧完整答复模式。续答仍挂原 `parent_turn_id`，权限失效不追加原文；Run阶段事件独立，不受正文模式影响。详细协议与流式适配器验收见最终补全修复方案；2026-10-08真实供应商流及前端接入已完成，旧回合继续消费其冻结格式。

### 7.2 上传后只问内容：延迟答复不占住 API

当问句指向刚上传、未解析的有权文件，`fast_path` 必须先检查是否已有相同 DocumentVersion/解析配置的有效产物；有则直接查询。没有时，C04 已持久化的原 Turn 先经受控 `prepare_task(read_index)` 验证任务输入，随后在**同一个短领域事务**中按 Case→Run 的锁顺序创建或复用相同输入的只读 Run，登记 `AssistantContinuation(parent_turn_id、conversation_id、case_id、question、固定 source_versions、run_id、status=waiting、idempotency_key)`、首轮真实说明消息、`message_final/continuation_pending` 事件和 Turn `completed`；新 Run 的首条 RunEvent 与 Outbox 也归入该事务，不能先提交 Run 再补待答项。若所复用 Run 已 `indexed`，说明改为“识别已完成，正在核验来源”，同事务写续答 Outbox；否则说明“正在识别以回答此问题”。提交后才释放会话回合锁并允许续答消费者写事实消息；前端任务卡从 RunEvent 展示真实阶段，HTTP、SSE、LangGraph 回合租约都不跨 OCR 时长挂起。Run 的状态转移也锁同一 Run 行，防止 `indexed` 先于待答登记导致漏唤醒。

`read_index` 发布 `indexed` 事件的同一业务事务在 Run 行锁下写续答 Outbox；消费者以 `(assistant_continuation_id, indexed_artifact_set_hash)` 去重。它重新检查用户当前授权、会话仍可写、原件版本仍归属该 Run、索引产物及 `parse_artifact_id` 可读；冻结该 Run 产出的解析版和基线业务版，按原问题查询授权证据，再使用与普通回答相同的证据门禁生成一条**关联 `parent_turn_id` 的 `assistant_continuation`**。这是同一用户轮的后续消息，不算新的用户提交，也不调用 `start_run` 第二次。即使用户随后又发消息，后续答复仍挂在原问句下并显示“基于这次识别结果”；消息序号由会话消息事务分配，不能串入另一 Case。Run `failed_retryable` 时待答项变 `awaiting_retry`，`paused_reconcile` 时变 `awaiting_reconcile`，两者都有可见状态且保留原问题；W06/O01 安全恢复后回 `waiting`，同 Run 最终 `indexed` 才自动续答。`failed_final/cancelled` 以无事实通知终结。会话已结束时仅记录“索引已完成，需新会话追问”和入口，不追加事实答案；权限已撤销时只记受限状态；文件归属变化时停止事实答复。若用户明示新的业务版本已覆盖该解析结果，答复标注它引用的历史版本，不冒充当前稿。

续答使用 `assistant_continuation_id` 自身的租约、幂等键和独立 `continuation:{id}` 图线程／检查点，或等价的独立只读答复服务；只运行复用的 `query_case_facts → compose_answer → verify_and_emit`，读取原问题、原轮冻结引用、Prompt 与非秘密模型绑定，**绝不并发复用 `conversation_thread_id` 检查点**，也不读取后来 Turn 的消息、Skill/MCP 返回或新上传文件。`indexed` 恰逢本会话新 Turn 正在运行时，两者只竞争消息表的短事务序号分配，不共享图状态；新 Turn 上下文只读已提交消息。若原轮绑定的模型已不可用，精确字段可由确定性证据格式化器续答；复杂解释则记录“索引已完成，自动续答暂不可用”，保留用户重新提问入口，不静默切换未知模型。续答消息及 `continuation_final` 事件在同一会话消息事务按序追加；若原轮在中途被中断，先依持久 `AssistantContinuation` 和 Run 状态核对是否仍有合法续答资格，不拼接原轮未校验草稿。

## 8. 防注入、可靠性与速度

输入信任级别固定为：项目系统策略与业务工具 schema ＞ 本轮用户授权任务要求 ＞ 经服务端验证的业务事实 ＞ 用户确认偏好 ＞ 本会话摘要 ＞ 原件/OCR/Markdown/Skill/MCP 资料。OCR 区域可能写着“忽略上述规则”，它仍被引用为带来源的资料；模型工具计划不能把这段转为指令。所有工具请求都由服务器以认证主体重建参数和对象范围，客户端传来的 `tenant_id`、模型自称的管理员身份或自造的 EvidenceTarget 均无效。MCP 需要外发本票敏感片段时先由前端展示本次范围并经服务端记录授权，不能因为连接长期启用便默认外发。

性能优先级：状态和精确字段问答用快路径；鉴权、引用元数据和 Run 摘要可并行查询但统一版本核验；禁止每轮全文 OCR 或全票向量召回。真正流式目标是在供应商返回正文时提前展示待核验草稿，不用伪文字凑响应。外部`CHAT`请求对传输超时、断流、上游暂时不可用默认最多3次实际请求（含输出修复），中断退避2秒、4秒；单次冻结角色超时、整组最多600秒，受回合租约及调用/token/费用预算约束。每次中断独立记账，保留费用未知；已出正文重试前清空旧预览及JSON解析器，不能拼接旧回答。进程崩溃、账本失败、租约失效仍不自动重放。格式修复仍最多一次且受账本/预算控制，修复前重置旧预览；永久错误不重试。超时保留明确标中断的草稿，不发布为正式事实。摘要已移到正式回复后的持久Outbox和maintenance队列；独立租约（覆盖整组模型尝试总时限并另留30秒提交时间）、冻结来源与费用账本，不写对话检查点，现有20轮及token预算继续生效。发现同会话活动Turn时延迟2秒再投；已外发任务不可抢占，仍共享角色/租户模型许可，不能承诺新前台请求永不等待在途摘要。
