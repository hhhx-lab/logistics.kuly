## 1. 一次开发任务的固定输入与输出

每次开始编码前先读对应需求节、页面设计节、共享契约 ID 和本开发方案的当前切片；若四者有分歧，先同步文档再改代码。开发小任务的输入应明确 Case/Run/版本样本、要触发的页面动作和预期状态；输出应是一条可运行的前端动作→API→领域事务／Worker→持久事件→前端查询更新链，或明确写成仅后端基础切片。每次完成后回填对应开发记录的实际路径、依赖版本、验证命令／样本结果与已知限制，不能把计划文字留作“已实现”。

代码约束是最小改动：优先在现有 `src/backend/app/` 和 `src/frontend/src/` 骨架上扩展，抽公共层只为实际复用；不复制第二套 Case、Run、文件版本或进度状态。对话 Agent 不直接处理附件，单证图不直接写聊天正文；API 领域表是状态真值，LangGraph 检查点是恢复位置，Redis 仅投递／通知。所有模型和 OCR 配置来自 `.env`，用户 Key 不写代码或文档。项目独立 Python 环境、锁文件和前端锁文件在实施阶段建立；本轮不安装依赖、建库或假称完成探测。

D0–D7 是同一首版的依赖顺序，不是把租户权限、幂等或到期门禁推迟到 D7。D1 起每个读写接口就执行身份、Case 状态／30 天期限、版本和幂等边界；D5 完成主动删除 UI 与物理清理，任何接入真实单证的部署必须同时具备两者。D0 要用真实可授权样本测定并固定 `RUN_MAX_FILES/RUN_MAX_TOTAL_BYTES/RUN_MAX_TOTAL_PAGES` 与 Celery 软／硬时限、Redis visibility timeout；U02/W03 对超限材料给明确错误，不能让单条消息无界占用 Worker。异步 MinerU 若无法在受限图执行内完成，须以持久外部任务 ID 退出当前消息，后续按步骤账本和 Outbox 继续；若目标单票普遍超限，先实现显式按文件／阶段拆分和聚合栅栏再发布。D7 集中验证故障注入，不在末尾才补可靠性。D2 的只读 Run 已须持久检查点、StepExecution、Outbox 与事件。D3 的法规提示只有审定适用范围后启用；通用识别／翻译与跨单据一致性可覆盖多类材料，但“未覆盖／无法判断”不能变为绿色通过。首批线路专属规则以中国出口至欧盟的一般非危险消费品作样本验收，其他线路／货类照样可走通用链路。

### 2.1 首版样本覆盖与规则边界

下面是 D0 获取获授权脱敏样本、D2–D5 做定向验收的**计划矩阵**，并非已经取得样本或已通过测评。用少量案例覆盖路线、货类、语言方向和版式差异，不对路线×货类做无意义的全排列，也不把通用单据检查冒充海关或商品合规结论。每份样本需有原件、人工字段真值、预期语言、关键页／行锚点和预期疑点；不能获得真实授权材料时先用显著标记的合成件验证工程链路，模型准确率另测。

| 样本组 | 线路与货类 | 材料和重点 | 首版验收边界 |
| --- | --- | --- | --- |
| A：主闭环 | 中国→欧盟；一般非危险消费品（先用家居纺织品） | 图片箱单＋PDF 发票＋DOCX 补充材料，中文→英文，海运；正常版和植入数量／重量冲突版 | 完整识别、翻译、复核、逐源文件目标语言导出及一份报告；线路专项提示须等权威规则包审核后才能启用。 |
| B：格式与数值 | 中国→美国；普通机械零配件 | 原生 PDF 发票、扫描装箱单、英文运输单证；币种、单位、包装层级和 Seller/Shipper/Consignee 角色不同 | 通用字段与有前提的一致性检查；不作美国报关／商品监管结论。 |
| C：多逻辑单据 | 中国→东盟；不含电池的消费电子配件 | 一份混合 PDF 含发票与箱单、另附提单，中文→英文；跨页表格和 Notify Party | 逻辑单据拆分、单份物理源文件只生成一组译本、来源锚点和同票角色检索；无依据规则显示未覆盖。 |
| D：反向语言 | 东盟→中国；普通机电配件 | 英文原件与中文目标，图片／DOCX 混合，起运地、原产国、装货港不同 | 英→中、地址／编号保护、字段角色和历史快照；不同地理角色不因字符串不等被误报。 |
| E：边界样本 | 任一线路；食品、化学品或含电池货物各取一份脱敏／合成材料 | 文件可读但专项监管信息缺失，含低清页、手写或混排语言 | 能识别和翻译的内容照常处理，低置信度要求人工复核；相关法规／危险品结论标“未覆盖／无法判断”，绝不自动给放行判断。 |

每个开发切片仅取与改动直接相关的行和变体：D2 先用 A 的一份原件验证只读续答，D3/D4 用 A 的正常与冲突两版验证主闭环；B–E 用于对应的格式、语言、逻辑拆分和边界能力，避免每改一个按钮都重跑所有模型调用。规则适用性和模型准确率以样本记录、配置版本和人工真值单独评测；未经验证的字段、线路和货类要在页面显示覆盖边界。

## 4. 前后端衔接只允许一套真值

### 4.1 页面请求、缓存和事件

前端请求层由 OpenAPI 生成 DTO 和薄 API client 组成。TanStack Query 管**服务器状态**：Case、Run、复核视图、摘要、搜索和扩展；Zustand 只管当前身份内的面板宽度草稿、展开项、焦点返回位置、输入草稿等**界面状态**。任何 `Run.status`、Issue 数、`has_successful_snapshot`、业务／译文版本、Skill 可用性都不得由 UI Store 当业务真值。Lexical 的 `/ `、`@ `标签保存稳定 ID、版本和用户选择模式；选择器结果是候选，C04 再冻结并复核。PDF.js 只通过 U07 的授权 Range 读取原件；DOCX 阅读视图用 U08 净化结构；译段和正式产物各走其独立资源。

每个订阅组件先取包含 `last_seq` 的快照，再以 `after_seq=last_seq` 建 SSE；`UploadSession`、`Run`、`Turn` 各自存游标。收到事件只更新对应查询缓存的已知摘要或使查询失效；不可从事件文字自行拼一个新业务对象。消息流用户向上阅读时只显示新进度入口，不自动抢滚动；工作台原文／译文滚动只受显式 EvidenceTarget 或“同步定位”驱动。关闭右侧工作台、页面刷新或离开不取消 Run；权限撤销／切换身份时先清内容缓存和本地深链草稿，再重取可见状态。

所有写入按钮都遵循“本地表单校验 → 必要时 R07 影响预览 → 带 Idempotency-Key 和 expected version 的命令 → 服务端新版本／事件 → 重新读取受影响查询”。按钮禁用理由从 R02/R13 等后端 `allowed_actions` 和状态取得，前端可以提前提示，但最终门禁仍在命令事务中。版本冲突保留用户本地草稿，显示服务端当前值与本地拟值；不能静默覆盖。C05 的对话段落必须已通过后端证据门禁，前端不把模型原始 token 标成事实。旧证据卡、历史快照和已完成消息不随当前版刷新而改写正文。

### 4.2 后端模块边界和事务位置

FastAPI 路由只做会话／CSRF、Pydantic 验证、授权入口、幂等入口和 DTO 转换；业务命令在领域服务中检查当前版本并提交单一数据库事务。数据访问层用 PostgreSQL 的租户条件和敏感表 RLS 双重隔离，Worker 由受限 Run ID 查出真实租户后设置事务级 RLS 上下文，不用默认全局租户或广泛 `BYPASSRLS`。模型、MinerU、对象存储和 MCP 全部经独立适配层，路由和图节点不散写 `httpx` 请求。外部调用前写 `provider_request_key` 与提交中状态；可核查／幂等的瞬时失败才自动有限重试，受理不明转 `needs_reconcile`。

对话 LangGraph 只负责受限意图、澄清、路由和证据解释；文件字节不进对话图。单证 LangGraph 共用 `document_ingest` 子图，`read_index@1` 到索引即结束，`translate_review@1` 再做规则、译文、QA 和预览；人工等待由 Run/InputRequest/ReviewConfirmation 的领域状态承接。节点按实际输入指纹读已有 StepExecution／ArtifactDependency 后再调用外部服务；每一步先提交业务产物、RunEvent 和账本，再返回给图写检查点。Redis/Celery 至少一次投递需要数据库租约和 fence token，不能把图检查点当成唯一业务事实。

Prompt Registry 集中保存系统、意图、摘要、抽取、视觉复读、翻译与 QA 模板的不可变版本、变量 schema、输出 schema 和内容哈希；ConversationTurn、ExecutionEpoch 冻结所用版本，后续 Epoch 默认继承原 Run 的 Prompt 版与非秘密 ModelBinding。用户创建的 Skill 说明与 MCP 返回不进入系统模板注册项。模型角色按 `.env` 绑定 OpenAI 兼容协议，调用前做能力和预算检查，输出经 Pydantic／来源锚点／确定性规则复核；字段、算术、规则结论与导出门禁不能由模型文本直接决定。

## 5. 需专门联调的故障窗口

| 故障窗口 | 不变量与预期前端反馈 | 定向验证 |
| --- | --- | --- |
| 上传 PUT 成功而 U05 未返回 | 原件只在服务端验收后可入任务；前端可按 UploadSession 重查，未知字节不报完成 | 重放 U05 同键只得同一 DocumentVersion；同名不同用户不去重越权。 |
| W02 选区后同源重识别，再点 W03 | 草稿选区绑定 ParseArtifact；W03 返回 `TASK_DRAFT_PARSE_STALE` 和重新选区入口，不以同名 Section 静默建 Run | 先保存 `selected_sections` 草稿、执行 R11 得新解析版，再用旧 `draft_version` 启动；确认没有 Run/收费步骤产生。 |
| 多文件货描范围待确认或零候选重识别 | W05 每次只绑定一份 SourceVersion／ParseArtifact，R13 冻结逐源 `resolved_scope_refs[]`；零候选不得生成空译本，R11 同事务废止该文件旧请求 | 三份源文件中仅第二份货描不明：只出现一条活动请求；R11 与旧 W05 resolve 并发时旧请求被拒，新解析后再发至多一条请求；确认／导出包含三份源版的范围引用。 |
| `read_index` 终态恰逢待续答登记或可重试失败 | 首轮说明、待答项与 Turn 完成同事务；Run 行锁排序状态转移；`failed_retryable` 保留原问续答资格且页面不空转 | 并发投递 `indexed` 与 C04，答案不先于说明且只一条；另测失败→W06→`indexed` 后答原问。 |
| 领域事务已提交而 LangGraph 检查点未写 | StepExecution 指纹已有有效产物，节点重进时读取而不再收费 | 在节点提交后故障注入，恢复后产物、RunEvent 和费用记录各一份。 |
| 外部 MinerU／模型已受理而任务 ID 未保存 | 若供应商按请求键可查则核查恢复；否则 `paused_reconcile`，普通用户无重试动作 | 模拟超时／断进程，证明不会盲重投，O01 留审计。 |
| 修订提交后旧 Worker 返回 | 旧结果只归属旧输入版；当前业务／译文指针不回退 | 先修订后放行迟到响应，R02/R13 显示当前版需要的重算。 |
| 已确认后导出中发生修订 | 旧确认失效，暂存不登记为新 Export Snapshot | 导出前和快照登记前分别注入版本变化，M01 不出现“新成功”。 |
| 草稿 PDF 生成失败但双语 HTML 有效 | R13 仍可复核确认；R06 只禁草稿 PDF 预览／下载，正式导出仍独立渲染回检 | 注入 draft PDF 渲染失败，核对 `reading_html` 可定位、`confirmable` 不受该可选呈现影响。 |
| 失败导出换确认键或暂存文件被清理 | 同 Run 同指纹的失败 Attempt 不能绕开；可重试 AttemptItem 的已回检暂存受保护，复用前重验对象存在与哈希 | 导出 A 失败后用另一键调用 R14/R15 仍指向 A；删失暂存对象时同 Attempt retry 重渲染该项。 |
| SSE 断流、事件乱到或重复 | U04/W04/C05 按各自 seq 补齐去重；页面保留最后持久时间 | 在处理中断开网络并刷新，三页同一 Run 状态且无虚假百分比。 |
| 历史快照／当前版切换 | 历史 EvidenceTarget 只读且精确配对；显式“切当前”重新鉴权 | 历史筛选命中旧快照，来源、译文、下载与新会话 `@ `均指旧版。 |
| 用户退出或授权撤销 | 搜索候选、事件、字节 Range 和缓存不再暴露旧用户信息 | 另一用户直接请求已知 ID、旧链接及后续 Range 均被拒。 |
| 主动删除与迟到 PUT、Worker、内容流并发 | Case 先置 `deleting` 并撤权；U05、旧 SSE/Range/`@`、迟到图步骤均不得复活；隔离暂存签名过期后再扫 | 删除后补发已签 PUT、放行旧模型结果和继续读取已打开内容流，均无可读新字节／新 Snapshot；清理完成时对象各版本、检查点、会话与索引均为零。 |
| 从删除前备份恢复或删除账本确认延迟 | 独立账本须含已提交删除事务的连续序号，确认前不返回 `202`；恢复缺账本时停止对外服务 | 恢复一份删除前备份，先重放 tombstone 并清理再开放；人为截断账本时就绪检查失败，被删 Case 不可读。 |
| MCP 工具 schema／连接变化 | 停用受影响 grant，已插入 `/ `标签标不可用；不改变核心翻译 Run | 测试通过后改 schema/断连接，C04 调用失败但用户问题草稿仍在。 |

## 6. 测试与验收节奏

只对当前切片的变更及直接调用链做定向测试：schema/权限/幂等、图节点输入指纹和分支、前端状态机与关键交互、少量端到端样本。D0 的协议探测用脱敏样本；D2 用一份上传后只问字段的材料；D3/D4 用“图片箱单＋PDF 发票＋DOCX 补充材料”一票三件，同时含正常和故意冲突样本；D5 用同 Case 多语言／历史快照；D6 用一个自建受控 Skill 和一个实际只读 MCP 工具。规则包的正常差异和红项植入要分开验证，不能把所有角色／重量不同都判成冲突。前端视觉至少在 1440×900、1920×1080、1280 px 和 1024 px 窗口查看空态、处理中、红黄项、历史只读与成功导出；复核区需检查数字/日期可读、焦点返回、手动滚动取消旧定位和减少动态效果。

扩大测试范围仅限公共接口、权限层、检查点／租约或核心状态转换确实波及多个模块时；不要因为改一个按钮文字就跑全量 OCR/导出。每一切片提交前检查 diff 和相关文档、移除本次临时脚本与失败渲染产物，保留有价值的回归样本与真实失败案例；未执行的模型质量／性能测试不得写“通过”。接口和类型检查可在本模块完成后运行，业务样本评测与部署压测另有记录。原工程技术方案中的 p95 数字只是固定测量条件前的目标假设。

## 7. 仍需真实输入才能最终验收的事项

- 用户将填写 `.env` 中四角色 OpenAI 兼容模型服务与 MinerU Key；具体模型 ID、结构化 JSON、图片、限流、超时和价格需要在 D0 实测。未配置时相应工作流应显示不可用，不能用模拟成功状态充数。
- 需取得可授权使用且有字段真值的多格式样本，并为中国出口至欧盟一般非危险消费品的首批法规提示核实权威规则来源、有效期、适用条件和审核人；未审核的法规规则不得写成生效。其他线路／货类仍可走通用识别、翻译和一致性检查，专项结论明示“未覆盖／无法判断”。
- MinIO／S3 的浏览器可达公开上传地址、反向代理域名和 CORS 需在部署环境决定，并回填 `.env.example` 中文注释与部署文档；不能从本机 `minio:9000` 猜浏览器可达性。首版远程 MCP 的公共只读协议样本为 `https://mcp.deepwiki.com/mcp` 的 `read_wiki_structure`，只发公开仓库名，不传本票数据；上线时重新测试可用性。
- 单票原件、成功快照、派生内容和该票审计按最后一次实质性业务变更起 30 天保留；Case owner 主动删除或到期均先撤权再幂等清理。失败上传与无引用导出暂存可更早按独立生命周期清理，但普通孤儿清理不能误删仍被历史快照或运行中／可重试 ExportAttemptItem 引用的对象。真实客户材料接入前还须验证对象存储版本删除、备份恢复不复活记录及 MinerU／模型服务实际留存边界；详见共享契约 M06 与后端数据方案第 4.4 节。

本开发方案完成的判据是：F01–F34 都能沿“页面动作→具体接口→授权/事务→持久状态或事件→刷新后页面→定向验收”找到唯一实现路径，且没有把尚未接入的 OCR、模型、规则或 MCP 宣称为已完成。开发实施后再按实际代码路径和验证记录更新本组文档。
