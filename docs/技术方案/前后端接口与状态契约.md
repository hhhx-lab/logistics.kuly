## 1. 全局口径与不可变事实

1. 业务 API 统一前缀 `/api/v1`；现有 `/api/health/live` 只表示骨架存活。JSON 键统一 `snake_case`，ID 为不暴露内部顺序的 UUID 字符串，时间为 UTC 的 RFC 3339 字符串，金额和精确数量为十进制字符串，文件版本为正整数。前端按用户时区格式化时间，不改存储时间。所有接口按认证身份确定 `tenant_id/user_id`，请求体不得决定所属租户。
2. `Case` 是单票；一票可有多原件、多次 `Run`。`DocumentVersion` 固定原件字节，替换原件才递增文件版本；对同一版重新解析只新增 `ParseArtifact`。一份混合 PDF 可包含多个 `LogicalDocument` 与 `DocumentSection`，但正式译本按参与的**物理源文件版本**生成。`read_index@1` 无目标语言、译文、复核确认或正式导出；`translate_review@1` 才具备这些后半流程。
3. `Run` 固定服务端签发的 Task Spec、参与 `document_id + document_version` 集合、工作流类型／版本与任务发起人。翻译的目标语言或范围改变必须创建新 Run；`selected_sections` 的每个选区还固定 `document_id/version + parse_artifact_id + logical_document_id + section_id`，首 Epoch 与 Task Spec 使用同一解析基线。`goods_description` 在任务启动时冻结 `cargo_description@1` 范围选择器版本，解析后把实际命中的字段／行／源段写成不可变 `ResolvedTranslationScope`；候选模糊或零命中时用 `InputRequest` 请求确认，不能按标题猜或把一次重解析后的新候选默默扩入原范围。`ExecutionEpoch` 是同 Run 内的首次执行、修订重算或导出执行批次，不能在列表上伪装为新 Run。后续 Epoch 默认继承该 Run 已冻结的 Prompt 版本和非秘密 ModelBinding；配置文件或代码发布不使旧 Run 静默升级。O02 仅按受控记录显式迁移模型绑定，Prompt／工作流契约升级另建 Run。Run 当前状态与 `has_successful_snapshot` 是两条独立真值：旧快照已成功而当前工作版又待复核时，两者同时成立。
4. `Run.status` 首版为 `queued / processing / awaiting_input / awaiting_review / ready_to_export / exporting / exported / indexed / paused_reconcile / failed_retryable / failed_final / cancelled`。`indexed` 只属于只读识别；`awaiting_input` 表示分类边界、源语言或其他运行期必需条件待用户回答，尚未形成可复核译本；`awaiting_review` 表示翻译与草稿预览已产生、等待人工审核。`InputRequest` 有版本、目标来源、可选项和唯一活动态；回答不改变冻结的文件／翻译范围时，开启同 Run 的新 Epoch。不得用旧图的跨天 `interrupt()` 承载人工等待。导出 Attempt 的失败是独立状态：确认仍有效时 Run 从 `exporting` 回 `ready_to_export` 并显示最近失败尝试；W06 的 Run retry 仅处理非导出工作流步骤，导出走 R15 同 Attempt retry。确认失效则回 `awaiting_review`，外部受理不明则进 `paused_reconcile`。
5. `BusinessRevision` 只在本 Case 内定义业务事实／人工采用值的当前版；`TranslationRevision` 只在所属 Run 与语言内定义译文当前版。纯译文修订不能增加业务版。当前业务版与既有译文版只有依赖指纹、QA 和 `TranslationCompatibility` 记录有效时才可配对。字段、区段、问题或译文修订只能生成新版本／处置记录，不能覆盖原值、旧 Issue 或旧导出快照。Case 的 `review_state_version` 在字段审核、Issue 处置、规则检查或行匹配投影变化时同事务递增；工作版分页与该版本绑定，变化后返回 `PAGE_STALE` 并重取，历史分页绑定成功快照清单。
6. “复核完成”先在同一事务中建立不可变 `ReviewConfirmation`，冻结原件、解析、业务、译文、字段审核、RuleCheck、Issue 处置、行匹配、QA／预览、输出格式与确认人；“正式导出”是另一条命令。R13 计算的 Run 范围 `review_fingerprint` 覆盖这些实际相关 ID／版本；R14、R15 启动和快照登记时重算比较，相关复核事实变化即失效，不因同 Case 的无关 Run 变化而误失效。同 Run 同指纹只保留一个当前有效确认；导出失败的同指纹 Attempt 必须经 R15 原尝试恢复，换确认幂等键不得绕开。每份参与原件的所选 DOCX／PDF 目标语言译本和所选的逐源识别稿 PDF 全部生成并回检后，才原子登记 `ExportSnapshot`。失败暂存文件不出现在正式列表；旧成功快照在留存期内保持可读。
7. `Conversation` 一次只绑定一个活动 Case；同票可关联多文件。`@ `选择 Case/Run 的“当前版”只是输入标签，**发送该轮时**服务端冻结实际原件、解析、业务与需要的译文配对到 `ReferenceSnapshot`；固定 DocumentVersion 只冻结原件，不擅自选语言；Export Snapshot 始终冻结其历史清单。新会话不加载旧会话消息或摘要，只读取该用户确认过的长期偏好。每轮模型输入最多直接放本会话最近 20 个完整轮次，旧轮次摘要仅属于原会话。
8. 对话 `ConversationTurn` 采用 `pending / running / completed / interrupted / failed`，同会话同时只运行一轮。上传后只问尚未解析的文件内容时，首轮可完成“识别中”的真实说明并释放会话锁；`read_index` 完成后，由 `AssistantContinuation` 按 `parent_turn_id` 和原问题冻结引用产生续答，不增加一个用户轮次。续答使用独立的 `continuation:{id}` 图线程／租约或独立只读答复服务，不与新回合并发写 `conversation_thread_id` 检查点；只读取原问题及冻结引用，不装配期间新消息，落消息时才在短事务内争序号。`AssistantContinuation` 独立采用 `waiting / awaiting_retry / awaiting_reconcile / running / completed / failed / cancelled / restricted / closed`：Run `failed_retryable` 或 `paused_reconcile` 时保留原问题的续答资格并显示需重试／待核查，W06/O01 恢复后仍可在同 Run `indexed` 时自动答复；只有 `failed_final/cancelled` 才终结为无事实答复。续答前重验授权与来源；若会话已结束，记 `closed`、索引完成和新会话入口，不追加事实答案；授权撤销记 `restricted`。
9. 摘要和 `SearchProjection` 仅用于候选、排序和导航。本票问答必须回查有权限且版本匹配的 `FieldAssertion`、原文 `SourceSegment`、Issue 或 RunEvent。没有可靠来源时明示“无法确认”；原始单证、用户 Skill、MCP 返回均是低信任资料，不能改变系统策略或业务门禁。
10. **单票留存 30 天。** `Case.retention_expires_at` 以 UTC 按最后一次实质性业务变更时间加 `30 × 24` 小时计算；实质性变更仅包括原件验收／替换、任务草稿提交或 Run 发起、人工修订／处置／确认、成功导出，不包括查看、搜索、下载、对话提问、Worker 进度事件或失败重试。每次延长都在持有 Case 行锁的业务事务中更新 `case_version`、`last_material_event_at` 和期限；页面展示服务端期限，不能以本地时钟决定可访问性。到期与 Case 所有人主动申请删除走同一删除命令和清理链。删除以**整票 Case** 为单位，包含该票全部原件版本、Run、解析／译文／预览／正式快照、摘要索引、单票绑定会话与续答、扩展调用及该票业务审计；不能把某个 Run 行的“取消”当作删除。首版不设额外的单票审计留存例外。账户资料、其他 Case 和已独立确认且不含单票事实的用户偏好不随该票删除。
11. 删除命令先在事务中锁 Case、复核 owner 权限与版本，把 Case 置 `deleting`、提高执行栅栏、撤销 Case 授权并使所有业务读取／写入、搜索／`@` 候选、SSE、文件 Range 和新签上传失效；这是对用户可见的立即删除边界。已打开的内容流也须在下一段发送前复查栅栏并终止。随后独立幂等清理任务删除数据库关联行和对象存储**全部对象版本**，含失败上传、解析原始响应、Markdown、草稿、正式交付、暂存与可找到的孤儿对象；未完成时保持不可读，失败只允许受权恢复清理，不能回滚为可访问。清理完成只留不含单证正文、文件名、来源锚点或对象键的最小删除回执，供发起人核对状态和避免重复命令。队列迟到消息、图检查点、已签发但未到期的临时上传签名不得复活 Case；临时 PUT 只落隔离暂存区，签名过期后仍须二次清扫并由暂存 TTL 兜底。对象读始终经 API 代理，不能持有删除后仍有效的长期下载链接。最长 7 天加密备份恢复前须从独立于被恢复主库快照的最小删除账本重放删除记录并阻止已删除 Case 对外服务；外部解析／模型服务的留存及主动删除能力必须符合已披露边界，供应商无法满足时不得用真实单证宣称此策略已达成。

## 2. 通用传输、鉴权与错误

| 事项 | 统一约定 |
| --- | --- |
| 登录与会话 | 本地账号、Argon2id 密码哈希、服务端会话；Cookie 为 `HttpOnly/Secure/SameSite`。同源 Vite 代理或同源正式站点访问 API。读写均由服务端校验租户和 Case 权限；无权对象用不泄露存在性的错误。 |
| CSRF | 登录以外的 Cookie 鉴权写请求附 `X-CSRF-Token`；由 `/me` 返回或独立更新。浏览器直传对象存储仅使用限对象、限大小、短有效期的上传签名，不持有 S3 管理凭据。 |
| 幂等 | 产生业务动作的 `POST/PATCH/DELETE` 带 `Idempotency-Key`；服务端按用户＋方法＋路径＋请求摘要保存原始结果。相同键与相同请求返回同一 Case/Run/版本/快照，键复用但参数不同返回 `409 IDEMPOTENCY_CONFLICT`。关键命令记录至少保留至关联 Run 或快照不再可重试。纯查询型 `POST /evidence/resolve` 和 `POST /cases/{id}/change-impact/preview` 不消费幂等键。 |
| 版本前置 | 修订、裁定、分类、确认、导出等命令的 body 带相应 `expected_business_revision_id`、`expected_translation_revision_id`、`expected_parse_artifact_id`、`expected_issue_version` 或 `expected_confirmation_id`。服务端在事务中比较当前指针及依赖摘要，不信任前端禁用状态；冲突返回当前可见版与“重载差异”入口。 |
| 错误结构 | `{ "error": { "code": "STABLE_CODE", "message": "可显示中文", "details": {...}, "trace_id": "...", "current": {...} } }`。`401` 未登录，`403/404` 无权／不存在，`409` 版本或忙状态冲突，`413/415` 文件限制，`422` 参数不合法，`429` 限流／预算，`503` 外部服务暂不可用。不得把栈、Key、原文或内部对象键返回浏览器。 |
| 分页 | 大列表使用稳定排序和不透明 `cursor`、`limit`；响应 `{items, next_cursor, has_more, as_of}`。搜索条件变化后丢弃旧 cursor；列表新事件到来只提示刷新，不在当前页插行。 |
| 缓存 | 私有查询与字节流 `Cache-Control: private, no-store`；前端查询键含身份、Case/Run、业务／译文／快照版，切用户或授权撤销立即清理。下载、深链与回放每次重新鉴权。 |
| 模型与解析 | 模型从 `.env` 按 `CHAT/EXTRACT/TRANSLATE/VISION` 四角色读取 OpenAI 兼容协议地址、Key 与模型 ID；是否支持结构化输出／图片必须实测。MinerU 为首个扫描件解析适配器。Key 和个人 MCP 凭据不进入 Task Spec、提示词、日志或前端。 |

### 2.1 三条事件流与重连

`UploadSession`、`Run`、`ConversationTurn` 各有自己的持久递增 `seq`，不能共用游标。快照查询在同一数据库读事务返回 `last_seq` 与当前状态；浏览器首次订阅 `GET .../events/stream?after_seq=<last_seq>`，自动重连再带 `Last-Event-ID`。SSE 的 `id` 是该流的十进制序号，`event` 是稳定类型，`data` 至少含 `seq、occurred_at、status、stage、message`，有可靠分母时才含 `completed/total/unit`。服务器先回补 `seq > after_seq` 再订阅新事件；心跳不占序号。前端按序去重，发现缺号或收到 `EVENT_GAP` 时重新取快照并补订；离线只显示最后持久状态和时间，不猜进度。Redis 通知与 LangGraph 内部流不是 UI 历史真值。

上传的浏览器 XHR 字节事件只表示**当前连接实际传输的临时进度**；已完成文件数和对象存储验收后的字节数由 UploadSession 持久事件确认。刷新后未确认文件显示“待核验／需重新选择”，不把丢失的本地进度写成已上传。Run 的页数可在总页数可靠时显示比例；抽取、规则、翻译只显示阶段文字。2026-10-05答复目标调整为独立的待核验预览事件及正式答复事件：新增 `answer_preview_started/answer_preview_delta/answer_preview_reset`，逐块保存真实正文增量；原 `message_delta` 仍是已校验段落，`message_final` 与正式Message原子落库并替换预览。中断草稿明确未核验，不进入记忆或业务事实；重连仅回放已保存事件，不自动重发供应商请求。详细字段、兼容与实施前验收见最终补全修复方案。2026-10-08运行DTO、生成TS、SSE枚举和页面已统一实现，真实增量及定稿替换已验；offset按Unicode码点计数，来源卡可提前就绪，预览不进入正式上下文。

### 2.2 必须明确返回的共享结构

| DTO | 必有字段与作用 |

## 8. 三条必须端到端一致的时序

### 8.1 多文件上传、澄清与启动

1. 对话主卡、拖拽或管理台新建入口先读 S04。用户看见实际数据流向并选择同票归属后，调用 U01/U02；上传每个文件采用浏览器可达的短期 PUT，当前连接字节显示为临时进度。
2. 每份文件分别 U05 验收，只有成功返回的 `DocumentVersion` 可加入 W02；失败文件用 U06 重试或由用户明确排除。任务类型明确为翻译但缺目标语言时，W02 返回 `needs_clarification`，对话给具体问题，**不创建 Run**。
3. 已明确的文件集合、目标语言、翻译范围与输出格式经 W02 形成可见 TaskDraft；用户或受控路由调用 W03 后，前端拿 `RunView` 快照并订阅 W04。Run 的 Task Spec 冻结，重新处理不同文件或语言必须另建草稿和 Run。

### 8.2 只问原件内容与异步续答

1. 用户上传并验收文件后问某字段，C04 冻结原件版。若没有可用 ParseArtifact，受控 Agent 通过 W02/W03 启动或复用同输入 `read_index@1`。持 Run 行锁的登记事务同时写 `AssistantContinuation`、真实首轮说明、`message_final/continuation_pending` 与 Turn `completed`，再释放会话锁；Run 尚在处理时说明“正在识别”，已索引时说明“识别已完成，正在核验来源”并立即安排续答。用户仍可问进度。
2. Worker 解析、抽取、来源核验和索引写业务版本／RunEvent，W04 到 `indexed` 的事务唤醒全部已登记待答项；`failed_retryable/paused_reconcile` 时待答项分别变为“待安全重试／待运营核查”并保留自动续答资格，恢复后同 Run 最终 `indexed` 再唤醒；`failed_final/cancelled` 才以非事实通知终结。注册和各状态转移以同一 Run 行锁排序，既不漏唤醒，也不让事实续答先于首轮说明落消息。续答复用原问题与原源版，但冻结本次实际新产生的 ParseArtifact、业务版和证据 ID；重新鉴权、核对同票与会话状态，再在独立续答图线程／租约中构造经验证答复，不能复用新回合可能正在写入的 conversation checkpoint。
3. C05 以 parent turn 事件送证据卡和续答最终消息。若权限撤销则只标受限；若会话已结束则只记录“索引已完成，需在新会话追问”，不附原文事实。续答不从期间其他消息借事实或改任务参数，也不计第二个用户轮次。

### 8.3 复核修订、整组导出与历史追问

1. 任一来源卡先 R01，再 R02 和按需内容查询。`awaiting_input` 时只能 W05 解决运行必需输入；`awaiting_review` 时可 R07 预览影响并用 R08–R12 修订。保存成功刷新 R02/R03/R05、W04 与当前版卡；旧消息、旧快照保持原配对。
2. R13 展示真实门禁；R14 冻结 ReviewConfirmation；R15 启动导出并按 W04/R15 的事件与逐文件状态显示。只有全部译本和所选识别稿 PDF 回检成功后，R16 才返回新的 Export Snapshot 和可下载 artifact。
3. M01 的已导出行默认展示最新成功快照；历史筛选行展示最近命中快照。点击“查看本次”将该行 `displayed_snapshot_id` 传 R01/R02；点“向助手询问本次”将同一快照作为 C01 的固定初始标签；若入口是展开的某张原件，同时预置该 Snapshot 清单内的固定 DocumentVersion，默认只问这张原件的历史事实，同票跨文件比较须用户明确提出。历史只读与当前工作版之间只能显式切换；关闭工作台恢复管理台筛选、展开、滚动和焦点。

## 9. 接口冻结与定向验收

编码前先把本文 DTO 变成 Pydantic v2 schema、FastAPI OpenAPI 和生成的 TypeScript 类型；修改字段时以 OpenAPI 差异和这份契约一起评审，不让前端手写同名异义的类型。每个命令验收至少含成功、重复幂等、预期版本冲突、跨用户／跨 Case 拒绝和失败后快照不变；每类 SSE 验收快照＋补事件＋断线去重。正式文件接口验收逐 Range 请求鉴权、权限撤销后拒绝、下载失败不重导出。具体字段正确率、MinerU 定位、OpenAI 兼容模型的 JSON／图像能力、费用和规则效果要用获授权样本另测；文档中的“可调用”不等于已有 Key 或已通过样本验收。

开发与联调应按[工程技术方案](物流单证智能体_工程技术方案.md)的阶段顺序，优先从身份／上传／只读索引／真实事件闭环做起，并在此阶段打通当前 Case/Run/原件的基础 `@ `引用与结束服务；再进翻译／复核／导出；随后接管理台、历史快照 `@ `联动、Skill/MCP 和设置。每一阶段仅跑本模块及直接契约链的定向检查；发现公共接口或权限边界变化才扩大范围。下列输入尚未提供时可完成适配器代码、契约测试与禁用态，但不得在 UI 宣称外部能力真实可用：用户本地 `.env` 的四角色模型 Key 与 ID、MinerU Key、获授权的多格式业务样本、法规规则包的权威依据及审核记录。

## 2026-10-03 契约补齐与实现边界

OpenAPI全部JSON成功响应及嵌套对象已发布Pydantic DTO，并生成前端ApiResponses/请求参数供实际调用复用；SSE/原件及交付字节/204/Prometheus按各自专用类型。生成检查不替代真实写路径、OCR/翻译质量验收，具体结果见开发记录核验第12.3节。

- 受控规则事实：`GET /cases/{case_id}/rule-inputs`支持business_revision_id及snapshot_id；历史只读取manifest冻结rule_input_decision_ids，旧快照无此键返回空，不补后来决定。`POST /cases/{case_id}/rule-inputs`提交run_id、expected_business_revision_id/no、expected_review_state_version、kind、scope_key、payload、reason及basis；kind为party_mapping/packing_table/date_transport。鉴权/来源/适用口径/CAS通过后追加决定并形成业务新版、按依赖重算，不能覆盖原字段或原机器规则结论。
- 未决外部步骤：同Run任一Epoch的SUBMITTING/NEEDS_RECONCILE阻止新外发、完成发布、修订重算、字段确认及导出；只有同批且指纹一致的已知OCR原task续查例外。暂停业务版未发布时R02/R03只显示该Run成功解析步骤及冻结基线，不借Case最近解析/业务。页面明确只读原因，不显示完成结果。
