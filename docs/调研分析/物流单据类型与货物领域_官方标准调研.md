# 物流单据类型与货物领域：官方标准调研与实施目录

调研日期：2026-10-09；实施复核：2026-10-10。目录版本 `logistics-types@1`。本文区分实际读取的官方依据、工程提取建议、未完成的法规适用性验证；字段清单用于识别翻译复核，不是各国强制报关填制规则。

## 1. 结论和数据模型

单据类型是“发票、运单、证书”等文件用途，货物领域是“米面粮油、果蔬、矿物、金属、能源”等货物属性；一份文件可以选择多种货类，一张单票可以包含多个文件类型。不得创建“石油发票”一类膨胀枚举。货物的危险性、管制状态、证书义务必须由原件证据和经审定的具体规则包证明，不从货名关键词推定。

精细类型 code 与现有商业发票、箱单、提单、辅助、未知五种数据库基础类型兼容。机器精细候选和货类来源保存在解析布局清单的 JSON，不改写原件；人工确认保存在 `SectionAssignmentDecision.logical_document_type` 及 `cargo_profile_ids`，形成业务版本，后续抽取、检查、索引和翻译消费同一目录。未知类型先由用户确认用途，可选“通用物流单据”继续通用提取及全文翻译；继续保留“未确认类型”时仍需确认。不存在的空字段不生成，不把“未判断法规”当红项。

## 5. 货物领域多选与对应附加字段

米/麦/玉米/杂粮，面粉与谷物制品，油料/食用油，水果，蔬菜，肉乳水产，常温加工食品，冷链，金属/合金，重金属物质，矿石/矿物，原油/石油制品，天然气/LNG/LPG，化学品/危险品，武器/军品/两用物项文件，现金/有价凭证，以及通用货物。允许多选，例如蔬菜+冷链、金属+重金属、石油+危险品。每类只增加原件中可找到的批次、生产/有效日期、植物学名/品种、处理、温度、成分/纯度、浓度单位、样本/分析、数量单位、最终用户用途、现金种类等允许字段。

货类候选有原文片段ID，用户选择是业务偏好声明，并不补全实际事实。关键词只是候选检索，不等于归类；仅凭`USD`或`currency`不识别为现金运输，仅凭`lead time`不识别为铅，天然气不能因`gas`一词笼统归入。

## 6. 实施验收

1. API目录、人工类型确认和区段归属采用同一精细code；数据库保留基础enum兼容。
2. 类型与货类实际进入抽取schema及允许字段过滤，人物角色分别显示中文名称。
3. 同类来源混合、有标题但字段未提取、具体编号/单位/关键值识别异常只产生有位置依据的疑点。原件没有的字段不造空值；按实际证据区分“原件缺失”与“抽取遗漏”。
4. 类型专属检查使用可证明的原件标签/来源，不把“catalog建议字段”变成法定必填红项。危险品、军品、货币领域优先翻译与对照、不能给自动通关结论。
5. 新旧Run、业务修订、复核视图、摘要/检索投影保持精细code兼容；法规专项覆盖按既有审定发布体系。
6. 定向验证包含混合标题、模糊类型、中文角色标题、货类误匹配、schema差异、人工cargo冻结与迁移、可点击类型选择及API返回；真实外部模型效果单独说明，不伪称全面准确。

### 2026-10-10 实际代码验证

目录为36种用途类型、17种可选货物领域。`document.extract`按类型与货类生成允许字段、人物角色与检查重点；语义QA每对源译段携带精细type/cargo/focus，确定性检查只核对原件明示标签与抽取覆盖、同单位温度上下限，发票基础算术不因改选形式发票而丢失。角色联系人字段按“卖方地址／买方地址／收货人邮箱”等展示。人工类型/领域与当前业务版绑定，不取另一历史业务版的最新决定；历史快照保持其冻结决定。

W05、复核类型归属、管理台筛选与`@`高级筛选读取同一个认证目录接口，类型按领域分组，货物多选可折叠并搜索；W05仅呈现该次请求冻结的可选项，旧请求不会因新目录而提交非法选项。区段归属回显当前类型/货类，保存后走实际抽取/检查/预览重算。当前及历史复核视图都返回货类。新增JSONB迁移沿用既有租户RLS，不改变基础enum。

定向验证：既有抽取/预处理19项通过，新增目录/角色/schema/货物误识别/来源覆盖6项通过（包括MinerU拆分表格单元格只按同区段、同实际行、相邻列证明标签和值关联）；请求及响应TypeScript重新生成，前端TypeScript编译通过。服务端迁移与认证目录真实HTTP由主任务联调记录。官方未取到的完整地区填制细则、每种商品跨所有国家的监管义务、复杂OCR实际准确率尚不能声称完整覆盖。

最终联调补充：全屏与窄栏对已识别单据同样可“调整类型与货物领域”，未知保留确认入口；目录成功加载前禁止保存。新增真实PostgreSQL回滚HTTP验收一项通过，验证用途/货类保存→R02新业务版回显→局部重算批次冻结→旧CAS409，并执行生产抽取入口、截取Step调度，证明只重新抽取变更logical、schema包含新类型及冷链字段、无关logical字段保留。修复此前recompute复用旧字段的短路：当前section_assignment业务版与父版的type/cargo签名不同时重新抽取该logical；保留合法人工值，其余机器候选重抽，确定性检查按新业务版重新生成，语义QA按新profile/focus核对当前源译。

明细安全补充：类型/货类改变提取关注信息，不改变原件行结构和既有`LINE_COLUMNS`。重新抽取字段时，有旧解析明细行的logical复用整组旧行，禁止模型换一组源ID顺序后追加重复行；无旧行时才允许第一次生成。旧行及人工行匹配不删不改，规则用新类型针对同一组解析行核对；要修正原明细结构必须重识别产生新Parse。真实PG回滚用例执行生产抽取闭包、用替身网关返回反序源ID的同一行，实测仍只有一条原LineItem；没有真实供应商调用。

## 7. 与代码一一对应的完整字段及检查目录

以下由当前配置逐项展开；目录版本 `logistics-types@1`。字段只在原件有直接来源时提取，检查重点不是法定必填条件。每种类型同时消费公共字段、其人物角色字段及其专属字段；用户所选货物领域再追加其字段。

### 7.1 公共提取字段

运输参考号（`transport_reference`／transport）；柜号（`container_no`／transport）；封条号（`seal_no`／transport）；船名（`vessel_name`／transport）；航次（`voyage_no`／transport）；装货港（`port_of_loading`／transport）；卸货港（`port_of_discharge`／transport）；原件明确注明的起运地／出发地，不从主体地址、接货地、装货港、交货地或原产国推断（`origin`／transport）；承运人接货地（`place_of_receipt`／transport）；交货地（`place_of_delivery`／transport）；原产国（`country_of_origin`／goods）；货物描述（`goods_description`／goods）；原件注明的HS编码，字符串保留前导零（`hs_code`／goods）；数量（`quantity`／goods）；数量单位（`quantity_unit`／goods）；包装数（`package_count`／goods）；箱、件、托盘等包装层级（`package_unit`／goods）；净重（`net_weight`／goods）；毛重（`gross_weight`／goods）；重量单位（`weight_unit`／goods）；币种（`currency`／amounts）；单价（`unit_price`／amounts）；原件注明总额（`total_amount`／amounts）；贸易术语及地点（`incoterm`／transport）；运费（`freight`／amounts）；保险费（`insurance`／amounts）。

每个参与主体分别提取名称、地址、电话、邮箱、主体编号、税号和联系人，未注明主体角色的内容保留未明确，不将买方自动当收货人。

### 7.2 全部文件类型逐项配置

#### 1. 商业发票（`commercial_invoice`）

分类：贸易与结算；基础规则映射：`commercial_invoice`。

原件常见结构：抬头、角色信息、明细或声明、签署区。

人物角色：卖方、买方、签署人。

专属字段：发票号（`invoice_no`／document）；发票日期（`invoice_date`／document）；订单号（`order_no`／document）；合同号（`contract_no`／document）；可辨认签字文字（`signature_text`／document）。

疑点排查重点：发票金额/币种/贸易术语按原文；买方与收货人不等同。

附加字段：货物批次号（`batch_no`／goods）；生产日期（`production_date`／goods）；货物有效期截止日（`expiry_date`／goods）；原件等级规格（`product_grade`／goods）；原件货批号（`lot_no`／goods）；样品编号（`sample_id`／goods）；分析日期（`analysis_date`／goods）；检测项目（`test_parameter`／goods）；检测结果（`test_result`／goods）；检测单位（`test_unit`／goods）；检测方法（`test_method`／goods）；原件列明的检测限值或规格（`specification_limit`／goods）；材质牌号（`material_grade`／goods）；成分（`chemical_composition`／goods）。

疑点排查重点：牌号、成分、规格、重量和单位；元素符号原样。

#### 10. 重金属物质（`heavy_metal`）

附加字段：货物批次号（`batch_no`／goods）；生产日期（`production_date`／goods）；货物有效期截止日（`expiry_date`／goods）；原件等级规格（`product_grade`／goods）；原件货批号（`lot_no`／goods）；样品编号（`sample_id`／goods）；分析日期（`analysis_date`／goods）；检测项目（`test_parameter`／goods）；检测结果（`test_result`／goods）；检测单位（`test_unit`／goods）；检测方法（`test_method`／goods）；原件列明的检测限值或规格（`specification_limit`／goods）；成分（`chemical_composition`／goods）；CAS编号（`cas_no`／goods）。

疑点排查重点：具体物质/成分/浓度与单位，不能把lead time当铅或把材料浓度当食品限值。

#### 11. 矿石／矿物（`mineral`）

#### 12. 原油／石油制品（`petroleum`）
