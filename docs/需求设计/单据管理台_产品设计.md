## 1. 管理台要解决的问题

操作员应能回答四件事：某次处理用了哪几份原件；谁在何时发起、复核和确认导出；当时交付的是哪一版、哪些文件；现在能否回到原文与疑点继续核验。管理台是持久化业务记录的入口，不以聊天记录或模型摘要代替原始证据。

管理台默认显示**已成功导出的翻译处理批次**，一行代表一次翻译 Run，行内可展开此次参与的多份源文件及对应译本。页面另有“待复核／处理中／失败与取消／识别与索引／上传草稿”等状态筛选，保留未导出的原件和可恢复任务；“已完成”在正式交付语境中专指存在通过整组回检的 Export Snapshot。只读识别 Run 可以完成解析，但不会被标作“翻译完成”或拥有转换后文件。

### 1.1 记录的层级与不变量

| 层级 | 代表什么 | 管理台如何显示 |
| --- | --- | --- |
| Case（单票） | 一次货运／贸易业务的工作空间，可含多次处理、多份原件和多个目标语言。 | 批次行显示所属 Case；点击 Case 标识进入单票概览及完整时间线。 |
| Upload Session | 一次多文件上传，记录成功、失败、重试和归票情况；它不等于处理 Run。 | 上传草稿与文件接收记录中可见；失败文件不被算入已处理原件。 |
| Run（处理批次） | 一次固定 Task Spec 的执行，固定参与的 `document_id + document_version` 集合、任务类型、目标语言与范围。一次 Run 可以有多份文件。 | 主列表一行一个 Run；同一 Case 的不同语言或不同要求分成不同批次。未改变 Task Spec 的安全重试记在该 Run 的事件时间线中。 |
| SourceDocument / DocumentVersion | 一份物理上传原件及其不可覆盖的版本。原件可被多个 Run 引用，不因再次处理而复制或改写。 | 批次展开后逐文件列原件、版本、上传人和上传时间。 |
| Parse Artifact | 同一原件版本的每次有效解析结果有独立且不可覆盖的 `parse_artifact_id`；重解析不产生新的原件版本。 | 已解析文件标明当前工作版所用解析结果；历史来源与成功快照继续指向当时的解析版本。 |
| LogicalDocument / DocumentSection | 源文件在某个解析版本内的逻辑单据与区段；混合 PDF 可同时含发票和箱单，未解析原件可没有逻辑单据。 | 文件行展开后显示类型、原始页／区域范围、逻辑单据与区段；类型筛选命中逻辑单据而非给整份 PDF 贴唯一类型。 |
| Revision | Case 业务 `revision_id` 与对应 Run／目标语言的 `translation_revision_id` 分开递增，均不可覆盖。 | 当前工作版与历史版有清楚标签；历史结果不能默认为当前可导出。 |
| Export Snapshot | 一次整组生成并回检成功的冻结 manifest。记录 Run、业务／译文版本配对、逐源文件输出和所选逐源识别稿 PDF。 | 只有其正式 Export Artifact 进入“转换后文件”；同一 Run 再次复核导出可有多个快照，主行展示最近一次成功快照并可展开历史。 |

任务更换目标语言、文件范围或翻译范围时创建新 Run；字段修订或事实裁定产生新的 **Case 业务 `revision_id`**，纯译文编辑只在所属 Run／语言产生新的 `translation_revision_id`。同票其他 Run 若依赖被修订事实，其译文、摘要和当前可导出状态也须标过期并按依赖重算；已经成功导出的快照保持历史只读。若某 Run 已有成功快照，后来又修改工作版，它仍留在已导出列表，显示“有历史导出；当前工作版待重新复核／导出”，旧快照保持只读，不把旧译本说成当前稿。

## 2. 页面的理想形态

### 2.1 页面骨架与信息优先级

入口位于应用左侧导航“单据管理台”，打开后占中央主区。沿用对话页的克制视觉：浅色背景、清楚的表格字重、细分隔线、少量低饱和操作色；红黄只用于真实疑点。密度以操作员可快速扫过文件名、时间、处理人和状态为准，不做铺满大卡片的仪表盘。

| 区域 | 内容 | 交互重点 |
| --- | --- | --- |
| 顶栏 | “单据管理台”、当前搜索结果数、创建处理入口、最近一次刷新时间。 | 新处理返回对话页主卡片；结果数遵循权限过滤。 |
| 状态导航 | 已导出（默认）、待复核与可导出、处理中、失败与取消、识别与索引、上传草稿；可切换“全部”。 | 标签数量取当前用户可见记录；处理中是实时状态，已导出表示存在成功快照。 |
| 筛选条 | 搜索框、日期类型与区间、来源地角色、收件人角色、处理人、单据类型、目标语言、版本范围，以及“同一逻辑单据／同一批次任意文件”匹配范围；筛选条件以可删除标签展示。 | 多条件组合，保留查询条件；“重置”一次清空，输入时给出有权结果的建议。 |
| 批次列表 | 默认按最近成功导出时间倒序，显示一行一 Run；行内有 Case、目标语言、原件数、主要类型、处理人、时间、关键信息、疑点和版本状态。 | 点击行展开，不将“展开”误当成“开始复核”；主操作可打开记录、问助手或查看交付文件。 |
| 展开区 | 此次参与的源文件、逻辑单据、每张单据简要摘要、原件与译本对应关系、所选识别稿 PDF、快照和任务时间线。 | 点击原件／字段进入校验侧栏的确切版本；点击正式输出预览或下载该快照产物。 |
| 右侧校验区 | 默认收起，复用翻译校验工作台；窄窗口切全屏。 | 打开后保留管理台列表的筛选、页码、展开项和滚动位置。 |

示例结构（字段仅示意，不代表样本已经验证）：

```text
已导出  12    待复核  3    处理中  1    失败与取消  2    识别与索引  4
搜索文件、单票或单号  | 日期：导出时间  | 来源地：起运地  | 收件人：Consignee  | 处理人

▾ 票据 C-042 · 英文翻译与校验 · 3 份原件 · 处理人 张某 · 9 月 28 日 15:42 导出
   已导出 · 快照 E-2 · 当前版有新修订待复核 · 原件冲突 1 项（已裁定）
   ├ 发票.pdf v1      发票〔第 1–2 页〕     查看原件 | 目标语言 DOCX | 目标语言 PDF
   ├ 箱单.jpg v1      装箱单〔图片 1〕       查看原件 | 目标语言 DOCX | 目标语言 PDF
   └ 补充材料.docx v2 其他佐证〔段落/表格〕  查看原件 | 目标语言 DOCX | 目标语言 PDF
   识别稿 PDF（可选） · 查看本次摘要 · 历史快照 1 份 · 向助手询问
```

上例中一份混合 PDF 若包含两个 LogicalDocument，仍只占一个物理源文件行及一组对应译本；展开文件可分别看到内部发票、箱单与原页范围。预览稿和导出失败的暂存文件不出现在“目标语言 DOCX／PDF”列。

### 2.2 批次行、文件行与单票概览

批次主行展示 `Case` 名称／编号、Run 短编号、任务类型、目标语言、参与源文件数、最主要的逻辑单据类型、处理人、当前展示快照的导出时间、快照编号，以及“当前工作版状态”；通常展示最近成功快照，历史筛选命中时展示被命中的快照。字段、地点、收件人和疑点数来自**主行所指的成功快照及其冻结的业务版本**；若当前工作版后来变化，另列“当前版已变化”提示和入口，不把两个版本的字段拼在一行。尚未导出的状态页则显示该 Run 当前已持久化的工作版与“最后活动时间”，标签注明未形成正式交付。

批次展开后，每份参与的 `DocumentVersion` 有一行：原始文件名、格式／页数／大小、上传人和时间、文件处理状态、逻辑单据类型与页／区域、一个可展开的简要摘要、问题数、原件入口，以及与该源版本对应的输出格式入口。已解析内容注明其 `parse_artifact_id`；已导出行展示主行快照冻结的解析结果，其他状态行展示当前工作版，不把两者的字段与疑点拼接。译本按 `source_document_version + parse_artifact_id + run_id + target_language + translation_revision_id → ExportArtifact` 与所属快照映射，不能按同名文件或列表顺序猜配对。识别稿 PDF 按各源文件列出；不附所选识别稿 PDF。文件未解析或只有只读识别结果时，展示原件及已知元数据／来源；译文和导出位置显示“尚无正式译本”。

单票概览以 Case 为主线，列原件目录、所有 Run、目标语言、当前业务 `revision_id`、问题与人工裁定、成功快照及最新工作版。相同源文件参与多个 Run 时在各批次中显示其参与关系，但对象存储只保留对应原件版本一份。概览页的“重新处理”预填该票与所选文件，仍回到对话／任务要求确认；不在管理台暗中复用旧目标语言或创建新 Run。

### 2.3 点击与过渡

点击批次空白区域只展开／收起；点击文件名或“查看原件”才打开右侧工作台。点击摘要里的字段或疑点，打开同一侧栏并定位其原文及相应译段；点击正式译本打开该 Export Snapshot 的只读输出预览，下载按钮经服务端重新鉴权。历史快照、历史业务版和旧译文均明确显示“历史版本，只读”，允许返回当前工作版，但不会自动把所选锚点改投到新版本。

侧栏打开时先保持当前行可见，再展开右区并聚焦目标位置；列表宽度变小时可折叠次要列，不抹掉筛选与展开状态。关闭后焦点回原文件入口，列表滚动与输入内容保持不变。动画只用于帮助用户看出“这条记录打开了右侧内容”，可采用短时平滑展开与高亮；用户设置减少动态效果时直接切换。长文件按需渲染，打开侧栏不重新运行 OCR。键盘可完成展开、筛选、进入文件和关闭侧栏，状态不只靠颜色表达。

## 3. 时间、处理人和状态的精确定义

| 展示名 | 存储与解释 |
| --- | --- |
| 上传时间／上传人 | `DocumentVersion.uploaded_at`／`uploaded_by`，对应原件接收成功；多文件逐个记录。 |
| 处理发起时间／处理人 | `Run.created_at`／`initiated_by`。列表中的“处理人”默认指发起该次 Run 的真实登录用户，不取文件中的联系人，也不把自动执行器显示成人工复核人。 |
| 最近处理活动 | 最新 `RunEvent` 时间；用于处理中、待复核和失败列表排序。 |
| 复核人／复核时间 | 每次 Issue 处置、字段裁定及复核操作分别记录操作者和时间；多人参与时展示所有相关记录。 |
| 导出确认人／导出时间 | `ExportSnapshot.confirmed_by` 与整组回检成功后登记的 `exported_at`；已导出列表默认以此排序。 |

数据库统一保存 UTC 时间戳，界面按用户选定时区显示，首版默认中国标准时间。日期过滤把用户所见的本地日期区间转换为 UTC 的左闭右开区间，避免“9 月 28 日”漏掉当日深夜记录。筛选器明确当前日期字段：已导出默认“导出时间”；可切“上传时间、处理发起时间、最近活动时间、复核时间”。改变日期字段时页面立即说明列表排序依据，不能把上传日期和导出日期混作一个“时间”。

Run 的阶段状态（排队、解析、待复核、可导出、失败、取消等）来自持久化事件；“是否有成功导出”来自 Export Snapshot。两者独立展示，故“有历史导出、当前版待复核”是合法组合；状态导航也不是互斥分桶，同一 Run 可在“已导出”和“待复核”中分别以快照和当前工作版出现。某次导出任一必需译本或所选识别稿 PDF 回检失败时，本次不生成成功快照；确认仍有效的 Run 回到“可导出”，最近 ExportAttempt 独立标失败，主行显示“上次导出失败”，同时可出现在“失败与取消”和“待复核与可导出”页签。用户只在服务端允许时重试这次导出的失败步骤，不新建尝试绕过失败记录；失败步骤和时间可查。本次失败产物不进入转换后文件列；若此前已有成功快照，其正式文件仍保留并标为历史版本。

## 4. 检索与分类：先说明字段含义，再匹配

### 4.1 筛选维度和匹配范围

| 维度 | 页面选项与匹配规则 | 结果中如何解释命中 |
| --- | --- | --- |
| 日期 | 明确选择上传、处理发起、最近活动、复核或成功导出时间；支持区间与最近 7／30 天快捷选项。 | 显示实际命中的时间类型和时间戳。 |
| 来源地 | “来源地”是筛选组，须选语义角色：**起运地／Origin 或 Departure**、承运人接货地／Place of Receipt、装货港／Port of Loading、货物原产国／地区。默认查“起运地”；原件未明确给出时显示“未提取”，不从发货人地址、卖方地址、接货地或装货港静默推断。 | 行内写明命中的字段角色、原文值／规范值及所属逻辑单据；无该字段显示“未提取”，不猜测。 |
| 收件人 | 默认查运输单据的 **Consignee／收货人**；可改查商业发票的 Buyer、提单的 Notify Party。不同角色不能仅因名字相近就合并为一个“收件人”。 | 显示角色名、所属原件；若同票多个 Consignee 不一致，显示“多候选／有冲突”及各来源。 |
| 处理人 | 默认查 Run `initiated_by`；可切“复核人”或“导出确认人”，在当前有权用户列表中选人。 | 展示此次处理的具体角色和真实登录身份，不从文档正文搜索人名代替。 |
| 文件与单据 | 文件名、单票编号、原文单号、逻辑单据类型、文件格式；同一混合 PDF 可同时命中“发票”和“箱单”。 | 在批次行标“命中 1／3 份文件”，展开后突出对应 LogicalDocument 与区段。 |
| 处理结果 | Run 状态、目标语言、红／黄疑点、是否有历史导出、当前版是否过期、快照版本范围。 | 语言按 Run／Export Snapshot 匹配，不从 Case 上一个可覆盖的“当前语言”读取。 |

各维度之间使用 AND，同一维度多选使用 OR。目标语言、Run 状态和处理发起／最近活动时间按 Run 匹配；导出时间与确认人按所展示快照匹配；上传时间、文件名与格式按参与的源文件版本匹配；复核时间／复核人按关联该 Run 的人工记录匹配，并展示涉及文件。来源地、收件人、单据类型与原文单号属于单据条件，**默认要求这些条件由同一个 LogicalDocument 满足**；若同时筛选上传时间或文件名，它们也须属于该 LogicalDocument 的源文件。筛选条可显式切为“同一批次任意文件”，允许多份原件分别命中，但结果必须逐条件标出命中的源文件与逻辑单据，不能让用户误以为一张单据同时具备所有字段。搜索框可模糊匹配文件名、单票号、已抽取单号与简要摘要，但精确元数据条件始终先过滤。模糊搜索结果必须显示命中的具体文件／逻辑单据和版本，不只返回“相关单票”。用户输入“上周的英文箱单”时，可把“上周”“英文”“箱单”识别为本地日期、目标语言和逻辑单据类型筛选，再以文字相关度排序；解析不确定时把识别到的条件显示为可编辑标签，避免模型隐式扩大查询。

地点和人名的规范化只用于检索：全半角、常见空白、大小写、已确认别名可归一；原文写法仍保留。查询可以命中未确认候选，但结果必须标“识别候选／待复核／有冲突”，排序将已确认且来源清楚的结果放前面；提供“仅已确认值”开关。搜索命中某候选不等于系统认定它是真实来源地或收货人。对两个原件给出不同收货人的票据，列表显示冲突标志，点击进入并列原文，不能在列表里自动选一个。

默认“已导出”列表按每个 Run 的**最新成功 Export Snapshot**搜索其冻结字段；打开“包含历史快照”后，可命中同一 Run 的旧快照。列表仍每 Run 一行：若只有旧快照命中，主行标“命中历史快照”并展示该命中快照的字段与时间，展开区同时给出最新成功快照入口；多个快照命中时默认展示最近的命中快照。其他状态页以当前工作版搜索。切换范围时查询与展示都落到同一版本，不允许用旧快照的索引命中却打开新版事实。历史快照即使不是当前稿，也仍可按当时字段找回。

### 4.2 搜索过程与空结果

在搜索框输入时，前端短暂防抖后请求建议，先展示精确单票号／文件名命中，再展示摘要命中；建议项同时给 Case、文件类型、处理时间及版本，最多显示少量候选，更多结果进入分页列表。搜索和 `@ ` 选择器使用同一权限过滤与检索服务，只是管理台可显示更丰富的筛选条件。

无结果时展示已生效筛选标签，并提供“清除某项／清空全部”；若某字段尚未解析，说明该字段筛选不会自动从文件名猜值。用户没有可见记录时展示上传入口，不露出其他用户是否有记录。检索索引更新中时可用直接的元数据查询找回已存在记录，并标注摘要暂未更新，不把缓存空结果当作数据丢失。

## 5. 每次每张单据的摘要与 `@ ` 快速唤起

### 5.1 摘要的层级、内容和版本

| 摘要层级 | 最少包含 | 使用场景 |
| --- | --- | --- |
| LogicalDocument 摘要 | 类型、所属 `document_id/document_version + parse_artifact_id`、`logical_document_id`、区段／页范围、关键主体的原始角色、编号、日期、货物概述、已知缺失／冲突及对应字段或原文锚点。 | 从混合文件中快速确定要看哪张内部单据。 |
| SourceDocument／DocumentVersion 摘要 | 原件格式、上传时间；有解析结果时注明所用 `parse_artifact_id`、内部逻辑单据清单、可引用的主要字段与解析质量；未解析时只能写文件元数据和“尚未识别”。 | 管理台文件行及 `@ `原始文件选择。 |
| **Run × DocumentVersion 摘要** | 此次 Run 对该张原件的任务模式、目标语言／处理范围、识别与翻译状态、所用解析版本、关键字段、疑点数及状态、业务／译文版本、对应成功导出文件或失败原因。 | 满足“每次每张单据任务有简要说明”；同一原件在不同 Run 中有不同处理摘要。 |
| Run 摘要 | 固定 Task Spec、多份原件、处理阶段、跨单证疑点、审核与成功快照、处理人和时间。 | 主列表展开、“这次做了什么”的询问。 |
| Case 摘要 | 当前原件目录、最近业务版、未决问题、历次 Run／语言与成功快照索引；不把不同 Run 的译文混成一个当前译文。 | 单票概览和 `@ `单票后的导航。 |
| Export Snapshot 摘要 | 冻结 Run、业务版、逐文件原件／解析／译文版、目标语言、交付文件清单、审核记录、确认人、导出时间和当时未覆盖／已裁定风险。 | `@ `历史快照和审计回查。 |

摘要是**导航和检索辅助**。建议先从结构化字段、Issue、RunEvent 和快照 manifest 生成简短中文说明，同时保存摘要引用的字段／问题／原文 ID；必要时可用模型润色非事实性的语序，但模型不得补造金额、地址、收货人或结论。摘要长度按列表与选择器分别截取展示，完整数据按需展开。每条摘要记录其作用范围、所属 owner／Case、源文件版本；引用已解析内容时还须记录 `parse_artifact_id`、业务 `revision_id`，涉及译文时再记录 `run_id + target_language + translation_revision_id`，并保存生成时间、输入版本指纹和 `ready/stale/failed` 状态。未解析原件的元数据摘要不虚构解析或业务版本。

文件级疑点数表示“涉及这份原件的 Issue 数”；一项跨文件冲突可出现在两份文件的摘要中。Run 汇总对相同 Issue ID 去重，不把它算成两项独立问题。

原件重解析、字段或事实裁定修订、疑点处置、译文修订、导出成功后，只标记**受影响**摘要与搜索投影过期并重建。标记过期与业务提交同事务，避免新业务版已保存而旧摘要仍显示为有效。异步重建期间列表可显示“摘要更新中”，但原件、字段和 Run 仍可进入；问答直接查询当前有权的结构化证据，不等待摘要才能答。历史 Export Snapshot 的摘要冻结在该快照版本，不因当前工作版变化被改写。

### 5.2 从列表或 `@ ` 到问答的路径

1. 管理台的“向助手询问本次”在**新会话**预置该 Case 与当前行所展示的成功 Export Snapshot 的结构化关联：一般是最新成功快照；若该行因“包含历史快照”筛选而展示旧快照，则绑定这份旧快照。标签明确显示快照时间与版本，从而固定本次 Run、逐文件原件／解析／业务／译文版本和交付文件。未导出批次的询问只绑定 Run 及其原件范围，不暗示已有交付。原件行的“询问这张单据”预置固定 `document_id + document_version`；若入口位于已导出行，另固定该行展示的快照及其中的解析版本。此时快照只确定历史版本语境，默认事实范围收窄为这张原件；用户明确要求同票对比时，才在同一冻结快照内读取其他原件并逐一列来源。具体目标语言未指定且有多个有效译文时，后续译文问题由 Agent 询问选择，不默认取最近语言。
2. 对话中的 `@ `选择器可以通过 Case、处理批次 Run、原始文件和成功导出快照搜索。候选项先从有权索引、简要摘要和元数据快速定位；选择的是稳定 ID 与版本语义，不是把摘要全文粘贴进输入框。发送消息时重新鉴权，并把“当前版本”指针解析为当时明确的业务版本及逐文件有效解析版本；尚未形成业务版本的草稿原件只绑定原件版本。快照引用始终固定。直接 `@ `选择 Run 时固定其参与的源文件版本；工作版提问在发送时固定该 Run 所用的 Case 业务版、逐文件解析版和有效译文版，若译文过期则说明待重算。询问“导出结果”则在发送时绑定该 Run 最近一次成功快照并明示时间与版本，查看旧稿须选定具体快照。
3. Agent 仅在这轮问题的 Case／文件／Run 范围内读取小段摘要用于定位，然后通过 `FieldAssertion`、`Issue`、`RunEvent`、`Revision`、`ExportSnapshot` 与来源锚点回查需要的事实。回答涉及单据内容时显示原文短摘录、角色、状态、文件与具体版本，点击打开侧栏；摘要本身不能充当原文证据。
4. 若摘要与结构化字段不一致、被标过期或缺少来源，Agent 忽略摘要的事实断言，按当前证据回答“待确认／无法判断”，并给出重建或人工复核入口。未经本会话上传或用户显式 `@ `绑定，不把过去搜到的票据自动送进新会话上下文。

首版使用元数据和全文／关键词检索即可使 `@ `快速出现候选；检索结果数量和每轮证据片段都设上限，避免一次加载全票原文。需要同义词、跨语言或长文语义搜索，且有评测证明关键词不足时，再引入向量索引；向量结果仍须先按用户、Case 和版本过滤，并由原文字段回查后才能进入回答。

## 6. 侧栏深链与跨页面联动

管理台、对话证据卡和校验工作台使用同一组身份与状态。打开某张单据时，服务端先验证当前用户对 Case、源版本，以及请求中出现的 Run 与快照的权限，再核对解析版本属于该原件版本、逻辑单据和区段属于该解析版本，最后解析定位。尚未解析的原件，最低深链只需 `case_id + document_id + document_version`，进入只读原件预览；已解析的原文／区段定位另带 `parse_artifact_id`、`logical_document_id`、`section_id` 与可用的 `source_anchor`／`source_segment_id`，即使尚无业务版本也可阅读原文。字段或 Issue 定位再带业务 `revision_id`；译文定位增加 `run_id`、`target_language`、`translation_revision_id`、`translation_segment_id`、`preview_version`；问题增加 `issue_id`；历史交付增加 `export_snapshot_id`。这些都是受控 ID 与版本，不把原件路径或长期下载地址放入浏览器链接。

| 来源动作 | 侧栏打开结果 | 返回时保留 |
| --- | --- | --- |
| 批次行“查看本次” | 对应该 Run 和主行实际展示的快照打开总览、原件清单、疑点与译本；未导出批次打开当前工作版，历史快照只读。 | 批次展开、筛选、列表位置。 |
| 原件行“查看原件” | 固定 `document_version` 的原始页／段落；已导出列表还固定主行实际展示的快照及其解析／业务／译文配对，未导出列表使用当前工作版。未解析时只读原件；历史快照只读，对照当前版须显式切换。 | 所选文件行与页／区段。 |
| 摘要中的字段或疑点 | 按摘要冻结的 `parse_artifact_id` 打开 LogicalDocument／DocumentSection，再定位 `source_anchor`／片段；相关译文仅在版本配对及预览版本匹配时高亮。 | 摘要展开和命中位置。 |
| 正式译本或所选识别稿 PDF | 打开所属 Export Snapshot 的只读预览；疑点问题可再跳回具体原文。 | 快照选择及下载入口。 |
| 当前工作版入口 | 显式切换至当前有效的业务／译文配对；受影响译文过期时只定位原文并提示待重算。 | 历史与当前版的切换线索。 |

点击和滚动遵循校验工作台既定行为：定位前等待目标页渲染，先高亮触发项，再让原文与译文按片段语义对齐；新点击或用户手动滚动可取消旧的自动定位。PDF／图片使用可靠页码与坐标，DOCX 使用段落／表格／单元格；没有可靠坐标时只定位至可证实的页或段落并说明。旧 `preview_version` 不套到新译稿的坐标上。窄窗口切全屏复核，返回仍回到管理台原列表状态。

用户在校验工作台修订字段／裁定，只新增业务 `revision_id`，使依赖它的译文、预览、摘要与检索投影过期；纯译文编辑只新增该 Run／语言的 `translation_revision_id`，不改业务版。RunEvent、Issue 和版本事件同时驱动管理台行状态、对话任务卡和侧栏。导出只有整组成功才出现新的 Export Snapshot 与正式文件入口；旧快照不被替换。用户从对话任务卡“查看管理记录”打开相应 Case／Run；从管理台“向助手询问”走新会话，避免旧会话摘要被顺带加载。

## 7. 可实现的存储与索引方案

### 7.1 保存什么，放在哪里

| 保存层 | 内容与规则 | 理由 |
| --- | --- | --- |
| 关系数据库 | Case、UploadSession、Run／RunEvent、原件元数据、ParseArtifact、LogicalDocument／DocumentSection、FieldAssertion、Issue、两类 Revision、摘要元数据、索引投影、ExportSnapshot／ExportArtifact manifest、权限和审计。 | 支持按用户、版本、日期、任务、字段角色稳定过滤与事务更新。 |
| 受控文件／对象存储 | 原件字节、较大的解析原始响应、Markdown 阅读副本、按需渲染的预览、正式译本与识别稿；使用不可猜测对象键和文件哈希。 | 大文件不塞入关系表或工作流检查点；原件与成功快照不可覆盖。 |
| 可重建检索投影 | 对每个 Run、原件版本、解析版本内的 LogicalDocument、成功快照建 owner、Case、类型、时间、地点角色、收件人角色、处理人、文件名／单号、摘要关键词和版本状态索引；快照投影固定其解析版本，工作版投影指向当前有效解析。 | 管理台和 `@ `共用快速检索；投影损坏可从主数据重建，不成为事实源。 |

首版工程基线为 PostgreSQL 与 S3 兼容对象存储，本地演示当前使用 LocalStack S3（保持同一S3接口，见工程方案）；即使只有一名演示用户，也给所有记录、搜索投影和文件对象绑定 owner，并在服务端校验。团队协作界面可后续扩展，但 tenant／role 字段和隔离从首版保留。不要为了多次 Run 复制同一个原件；Run 记录参与的不可变 DocumentVersion 引用，导出产物按快照独立保存。文件哈希用于完整性与重复提示，不以跨用户去重泄露另一人的文件是否存在。

建议的关系与索引至少覆盖：`Run(case_id, initiated_by, created_at, status)`；`RunDocument(run_id, document_id, document_version)`；`DocumentVersion(owner_id, case_id, uploaded_at, hash)`；`ParseArtifact(document_version_id, parse_artifact_id)`；`LogicalDocument(parse_artifact_id, type)`；`ExportSnapshot(run_id, exported_at, revision_id)`；`ExportArtifact(snapshot_id, document_version_id, parse_artifact_id, format, translation_revision_id)`；按字段角色和解析版本建立的可搜索值与来源关系；以及 `RunEvent(run_id, seq)`。关系必须保证解析版本属于指定原件、字段与 Issue 属于该解析版本、译文版本属于指定 Run／语言且声明所依据的业务与解析版本，不能仅靠前端字符串关联。每个快照的 manifest 必须验证每份参与的源版本与所选格式都映射到成功回检的产物，另有恰好所选逐源识别稿 PDF；整组事务提交后才被列表读取。

日期、owner、Case、Run、状态、角色字段先走普通 B-tree 等值／范围索引；文件名和摘要的模糊查找在比赛规模可先用归一化文本及有界查询，必要时使用环境已具备的全文索引能力。中文分词、子串和不同数据库的索引行为须用真实文件名与地名测量后选择，不能假定英文 FTS 自动解决中文模糊检索。初版搜索结果采用稳定游标分页（时间戳加 ID 作为排序键），建议页大小 25 条；输入建议限制前 8 条，避免一次加载所有摘要和原件。游标需绑定身份、筛选条件与查询水位；新快照或状态变化使列表重排时显示“有新记录，刷新列表”，避免翻页途中静默挪行。记录量增大后再按评测引入三元组／中文全文索引或语义检索，不预设向量数据库。

### 7.2 一致性、缓存、删除

每个 RunEvent 有递增序号。页面进入时先读取持久化快照，再订阅事件；断线用最后序号补齐，重复事件去重，浏览器关闭不终止后台 Run。列表可缓存有限的查询结果，但缓存键必须包含身份、筛选条件和版本范围；业务 Revision、译文 Revision、Run 状态或快照成功时使相关缓存失效。不能把旧摘要或过期预览从缓存恢复为“当前已确认”。

一票 Case 的本地业务记录保留到**最后一次实质性业务变更后的第 30 个 24 小时**。上传验收／替换、任务草稿提交或 Run 发起、人工修订／处置／确认和成功导出会刷新服务端到期时间；查看、搜索、提问、下载、后台进度与失败重试不会延长。单票概览和删除确认层显示准确到期时间及其所用时区，不写“永久保存”。到期自动删除；Case 所有人也可在单票概览、管理列表或上传草稿主动删除整票，列表默认浏览模式无复选框，右上角点击“批量处理”才显示多选与全选工具条，退出、换身份、筛选或页签清空选择；上传草稿和宽窄列表统一，支持按Case去重批量删除；先看到将一并删除的原件、Run 和成功快照数量及不可恢复说明，再明确确认。删除的对象是**整票**，而非当前列表的一条 Run：其原件、识别与翻译中间件、草稿与正式产物、所有历史快照、摘要／索引、绑定该票的会话与单票业务审计都不再可用；其他票和不含该票事实的用户偏好保留。列表里的“取消处理”只停 Run，不是删除。

删除请求提交成功后，该票立即从管理台、`@ `候选及计数中消失，旧侧栏、对话证据、下载与事件流停止提供内容；页面可凭不含原文的删除回执查看“清理中／已删除／清理失败待处理”，清理失败也不重新开放该票。后台随后幂等清理数据库、对象存储和图检查点，主存清理目标 24 小时内完成；加密备份最长 7 天轮换删除，恢复前必须从独立于主库恢复快照的最小删除账本重放删除记录，不能把已删票据重新开放。已签发的短期上传地址即使收到迟到 PUT 也不得恢复原件，签名到期后还需复扫隔离暂存。原件与正式快照只在未到期、未删除且仍有权时可查；用户此前已下载到设备或转发给外部的副本不属于系统可远程收回的范围，确认层需如实说明。外部 OCR／模型服务的实际保存及删除能力要在隐私文档如实说明，若无法满足 30 天边界或主动删除要求，真实客户单证不得作为已符合该策略的材料接入。

## 8. 权限与可审计性

搜索建议、数量、摘要、文件预览、导出下载、深链和对话 `@ `在服务端按 tenant／user、Case、Run、源版本和快照鉴权；即使知道 ID 也不能读取其他用户材料。团队权限后续可区分只读查看、处理发起、字段修订、事实裁定、导出确认和管理删除；首版至少区分真实用户与系统后台执行者。签发或法律效力不因文件进入管理台而获得保证。

审计记录至少能串起：谁上传哪版原件、谁以哪份 Task Spec 发起 Run、每个阶段何时发生、哪条原文产生字段和疑点、谁依据什么证据作了人工采用值、哪个业务／译文版本进入哪次 Export Snapshot、谁下载过正式文件。列表摘要或 Agent 回答若称“已裁定”，须可打开裁定记录与补充依据；原件锚点只证明原件写了什么，不证明人工改值正确。第三方解析／翻译服务、模型和规则版本的记录用于追溯处理，不把密钥或整份敏感原文写入普通日志。

## 9. 异常、空状态和边界

| 情况 | 管理台表现 |
| --- | --- |
| 上传只成功两份、第三份失败 | 成功原件可在草稿 Case 与后续固定 Run 中看到；失败文件留在 Upload Session 的失败记录，不计入“3 份已处理”。 |
| 尚未明确目标语言 | 有草稿与原件，但无翻译 Run 和转换后文件；从管理台继续任务时回到对话澄清。 |
| 只读识别 Run 已完成 | 在“识别与索引”可查原件、字段来源及摘要；目标语言、译文和导出位显示“不适用／尚无译本”。 |
| 翻译 Run 处理完但待人工复核 | 在“待复核”显示真实问题和最后活动时间；仍无正式输出。 |
| 某一文件或所选识别稿 PDF 导出回检失败 | 保留 Run、原件和失败事件，提示重试失败步骤；不生成部分成功快照，不展示临时输出为转换后文件。 |
| 历史快照成功后又修订 | 旧快照留在已导出列表并标历史；当前工作版另显示待重算／待导出，不混用两套字段。 |
| 一个文件有多张逻辑单据 | 文件行可展开多个类型与页／区域；按类型搜索命中具体逻辑单据，导出仍按物理源文件一份译本。 |
| 收件人或来源地相互冲突 | 列表显示多个候选和冲突，筛选命中说明候选来源；点开侧栏并列原文，不自动择一。 |
| 摘要生成失败或过期 | 文件与任务仍可由元数据找到；详情显示“摘要待更新”，问答回查结构化来源。 |
| 用户失去访问权 | 搜索候选和文件入口消失；旧深链重新鉴权并拒绝正文与下载，不依赖前端隐藏。 |
| 单票到期或主动删除 | 该票全部 Run、原件与快照从列表和 `@ `候选移除；旧深链、Range、SSE 拒绝，原发起人可凭最小回执查看后台清理状态。 |
| 历史预览坐标失效 | 可用历史只读预览则打开；不可用则定位原件并提示，不用旧坐标跳到新版译文。 |

## 10. 功能实现安排

| 阶段 | 页面和服务的最小交付 | 进入下一步的验证 |
| --- | --- | --- |
| A：数据契约与基础记录 | 锁定 Case／Run／DocumentVersion／ParseArtifact／LogicalDocument／Revision／Export Snapshot 的所属关系与权限；上传、任务事件、原件和逐源文件导出 manifest 持久化。 | 一次 Run 含三份源文件；同一原件重解析与替换上传产生不同版本关系；同一 Case 两次不同目标语言的 Run 不互相覆盖；整组导出失败不产生快照。 |
| B：比赛闭环管理台 | 默认已导出 Run 列表，其他状态筛选，批次展开与逐文件映射，日期／来源地／收件人／处理人过滤，关键词搜索、短摘要及过期标记、游标分页、成功快照下载、校验侧栏深链与 `@ `预置；进入页面从持久化状态恢复并按事件序号补齐。 | 刷新后能找回原件、任务、疑点、确认人、快照及来源；修订后旧摘要不冒充当前事实，权限与版本不串票、不串文件。 |
| C：可靠性与体验 | 摘要与索引异步增量重建、大列表分页与查询性能优化、历史版本对照和中英文检索样本优化。 | 长列表在新增记录和并发状态变化下不重复或漏行；历史快照仍可查，摘要更新期间原件可检索。 |
| 后续增强 | 团队协作角色、批量归档、保存筛选、已验证有必要的跨语言／语义检索和容量迁移。 | 由使用量、真实查询失败案例与权限评估决定，不把占位入口写成已实现功能。 |

实施顺序不意味着 B 才开始做身份隔离；从 A 的数据模型、对象键和查询接口就必须带 owner／tenant 与稳定版本。具体表结构、索引 SQL、接口和保留策略落在 `docs/技术方案/`，开发后按真实实现回写本设计。

## 11. 验收场景

1. 一票三份原件启动英文翻译 Run 并成功导出后，已导出列表只出现**一条处理批次**；展开后分别有三份固定原件版本与各自所选 DOCX／PDF 目标语言译本，另有所选逐源识别稿 PDF。每个输出可反查对应源版本、解析版本、Run、业务版和译文版。
2. 同票随后启动中文翻译 Run，列表增加第二条批次；两种语言各自的 Export Snapshot 与译文版独立。原件对象无须复制，按目标语言搜索只命中对应 Run／快照。
3. 同一 Run 成功导出后修正一个数量，历史快照仍只读可下载；当前工作版及相关摘要标过期。局部重算和审核结束后若再次成功导出，Run 行显示最近快照并能打开旧快照；旧版字段不冒充当前字段。
4. 一份混合 PDF 中有发票与箱单两个 LogicalDocument：按任一类型都能命中该文件并显示对应节与原页范围；物理文件只对应一组目标语言译本，不多生成伪原件。
5. 分别以“起运地”“承运人接货地”“装货港”“原产国／地区”筛选同一票得到可解释的不同结果；系统不把发货人地址或接货地当起运地。Consignee、Buyer 与 Notify Party 的筛选相互独立，冲突候选有来源和状态。
6. 处理人筛选命中 Run 发起人；切到复核人或导出确认人后按该角色重新过滤。导出日期、上传日期和最近活动日期切换后，命中的时间戳与排序一致。
7. 失败 Run、取消 Run、只读识别 Run 和上传草稿可从相应状态找到原件与事件；它们在没有成功快照时不显示正式转换文件。整组导出任一产物失败时不会出现“部分已导出”。
8. 从文件摘要点击疑点，侧栏定位指定 `document_version + parse_artifact_id + logical_document_id + section_id + source_anchor`；涉及译文时核对 `run_id + target_language + translation_revision_id + preview_version`，旧预览不会误跳。返回列表后筛选、展开项、滚动和键盘焦点保持。
9. 管理台点击“向助手询问本次”新建会话并固定相应快照；提问“为什么箱数被改”时，Agent 通过 Issue／人工裁定和两侧原文回答，列出处理人、时间、理由与来源，不仅复述 Run 摘要。`@ `原件有两种有效语言且没有活动目标时先选语言。
10. 修改字段后受影响的 Run × DocumentVersion 摘要和索引不再被标为有效；摘要更新中仍能由原件元数据找到文件，回答通过结构化事实回查。两个用户上传同名文件后，搜索建议、计数、预览、深链与下载都不能泄露另一用户数据。
11. 同一 Run 的文件 A 命中起运地、文件 B 命中 Consignee、文件 C 命中箱单类型时，默认“同一逻辑单据”组合筛选不返回该 Run；切换“同一批次任意文件”后可返回，但分别标明 A、B、C 的命中来源。已导出行若因历史快照命中，点原件与“询问本次”均保持该快照冻结的原件／解析／业务／译文版本；未解析原件可凭 Case／文件版本打开只读原件预览，不要求虚构解析或业务版本。
12. 对同一原件重解析后，当前工作版的逻辑单据边界、摘要、检索投影与字段来源指向新 `parse_artifact_id`，受影响的旧结论标过期；既有 Export Snapshot 的列表字段、点击定位、`@ `问答与正式译本仍指向旧解析版本。替换上传才新增 `document_version`，两者不会混同。

以上是页面和数据链路的功能验收，不构成识别准确率、检索时延或存储成本承诺。对这三类指标应使用代表性授权样本、预期数据量和实际部署环境建立基线。


### 管理删除补充（2026-10-05）

Run列表和上传草稿支持复选、全选已加载、清空选择及批量删除；按整票Case去重，同票多条记录联动。行/卡片菜单也可直接“删除整票”，先预览确认再提交。批量确认逐票列名称、短号、原件版本/Run/快照数量及权限，明确删除全部历史、草稿和产物；输入“删除N票”确认，逐票提交，显示成功与失败，不删除未选的其他票。失败保留可重新读取/核对入口，不自动重投未知结果。完整上传但未建Run的会话继续属于草稿，包含过期而可管理的无Run上传；已有Run的完整上传在处理列表管理。此补充取代仅在单票概览提供删除的入口限制，整票删除语义与30天策略不变。


### 同票核对管理联动补充（2026-10-14）

一票继续绑定一批业务货物，容纳不同语言、版式、用途和运输阶段的多份原件。`checked`作为只核对任务终态加入处理列表，与译文待复核和已导出区分，不显示不存在的译本。概览增加最新核对摘要、范围与过期提示；逐Run统计以该Run绑定批次为准，成功快照读取冻结依据。

“查看同票对比”打开工作台矩阵，“向助手询问”冻结当前Run或所选成功快照，加载其原件、译文、字段、疑点、核对和处理记忆。材料／主体／货批／航段／匹配决定改变会提示依赖过期；点击重核对追加新Run，旧Run和快照继续可查。管理台不能用当前Case的最新处置覆盖旧快照摘要。读取、Worker轮询与失败重试不续期，30天留存和整票删除仍按原约定执行。
