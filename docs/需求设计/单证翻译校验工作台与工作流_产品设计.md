本文细化**单证翻译任务、人工校验工作台及其页面联动**。当前最先完成的交付闭环是：一票材料经识别、抽取、核对和翻译，为每份成功处理的源文件产生可逐处核验的目标语言译本，并提供可选的逐源识别稿 PDF，经人工确认后整组导出。统一模板商业发票／装箱单属于可选的后续扩展；翻译件和业务草稿不得呈现为承运人或其他有权主体重新签发的有效原件。本文的界面尺寸、规则和分期是实施建议；解析效果、坐标能力、译文质量和性能门槛须用真实授权样本确认。

## 1. 产品目标与责任边界

单证校验工作的核心问题是“读到了什么、从哪里读到、哪里有疑点、人工采用了什么值、译文是否忠实、这一版能否交付”。工作台应让用户从疑点直达原件，也能从译文返回原文；每次修订都产生可追溯版本，而不是在页面上盖掉旧值。

| 角色或部件 | 在翻译校验流程中的职责 |
| --- | --- |
| 外层对话 Agent | 判断用户要做翻译还是提问，补齐任务要求，通过受控路由技能启动工作流；读取 Run 事件、Issue 和授权字段解释状态。它不直接处理原件、不自行确定货物事实，也不编造处理进度。 |
| 单证工作流 | 接收 Task Spec，解析原件、建立证据与字段、运行规则、翻译、生成预览及导出文件，保存每一步结果和事件。工作流可使用 OCR、视觉模型和翻译模型，但运行不依赖聊天上下文。 |
| 校验工作台 | 展示同一业务 Revision 及其对应的译文 Revision 的来源、字段、译文、问题和历史；承接人工修订、裁定和最终导出。所有写操作经业务接口校验权限与版本。 |
| 证据与版本存储 | 保留不可覆盖的源单据、解析产物、字段原值、人工采用值、原译对应、Issue 处置、Run 事件和 Export Snapshot。 |

沿用现有产品文档的单位：**Case** 是一票业务，**Upload Session** 记录逐文件上传，**Run** 是一次处理执行，**Revision** 是不可覆盖的工作版本，**Export Snapshot** 是成功生成并回检后的冻结交付文件组清单。字段、识别修正与事实裁定只递增业务 `revision_id`；纯译文修改只递增对应 Run／目标语言的 `translation_revision_id`，不改业务版。译文版记录创建时所依据的业务版本；业务版变化时先按实际依赖判断。若译段所依赖的原文、字段、解析和术语未变且 QA 仍有效，以可审计的 `TranslationCompatibility` 将原译文版与新业务版配对，不制造内容相同的新译文版；若依赖变化，受影响译文和预览先标过期，复用未变片段、局部重译及 QA 后形成新译文版。其他语言历史译文保持原版本，待需交付时也按同一规则建立有效配对。同一原件的多语言译文可以并存，新增语言不会覆盖已有结果。一个 Case 可以有多份单据和多次 Run；聊天会话结束不删除 Case，也不改变它的审核状态。

源 Document Version 在解析成功后至少包含一个 **LogicalDocument**；未解析的原件暂时可以没有。每次解析产物有不可覆盖的 `parse_artifact_id`，同一原件重新解析产生新解析版本，不改变原件版本。混合 PDF 可在同一物理文件中识别多个发票、箱单或其他逻辑单据。每个 LogicalDocument 有在所属解析版本内稳定的 `logical_document_id`、类型及一个或多个 **DocumentSection**；每节有 `section_id`、所属原件与解析版本、原件页码／区域范围和顺序，允许同页不同区域或跨页续表。类型不确定的节标“未分类”，先请用户确认，不能把整个 PDF 错判为一种类型。字段、明细行、Issue 的每个来源、源译片段和来源卡片均引用同一解析版本下的逻辑单据与节 ID；类型专属规则作用于逻辑单据，跨单证规则也可比较同一文件内的两个逻辑单据。人工改正类型或区段归属属于业务修订，需重算依赖规则并使受影响译文过期；重解析改变边界时保留旧版映射，无法可靠映射的字段与规则结果标过期。

首版建议覆盖中文／英文、商业发票、装箱单、提单和标为“其他佐证”的文件，输入为图片、PDF、DOCX。具体目标语言、贸易线路、样本类型和可用模板仍须在实施前锁定。对其他语言或格式不作隐含支持承诺；无法解析时保留原件并清楚说明。

## 2. 任务发起：先确认要求，再进入翻译作业

### 2.1 对话、主卡片与直接上传走同一入口

用户可点击对话框上方的“单据翻译与转换”卡片、把文件拖进对话区，或发送“把这票材料翻译成英文并核对”。三种入口最终填写同一份任务要求；卡片和对话只是不同的入口，不创建不同的翻译流程。上传动作可以先建立草稿 Case 与 Upload Session，但**翻译要求未明确前不启动翻译 Run**。用户不需要在各入口重复回答相同问题。

外层 Agent 将意图分成至少四类：新建翻译任务、继续当前审核、询问单证／任务、其他受支持的领域问答。只有新建翻译任务并具备必要参数时才调用翻译路由技能。像“帮我看看文件”可能是摘要、翻译或审核，先问用户希望得到什么。若用户上传后仅问“这份提单的 Consignee 是谁”，但尚无解析产物，可启动使用相同分类、解析、抽取能力的**只读识别／索引 Run**，再按来源回答；它不需要目标语言，不执行翻译、正式校验裁定或导出，也不创建翻译 Run。已有有效解析产物时直接做授权查询，不重复识别。

| 任务要求 | 判定与提问方式 | 可否先做 |
| --- | --- | --- |
| 文件与归票范围 | 至少一份上传成功；多份文件是否同一票不确定时让用户分组或确认。已选中的 Case 不再重复询问。 | 不明确时只能保留上传草稿。 |
| 操作意图 | 明确是翻译、单纯识别、问答，还是翻译并核对。若用户只说“处理一下”，给出简短可选动作。 | 未确认翻译意图不启动翻译 Run。 |
| 目标语言 | 翻译任务中用户必须明确指定；可给“译成中文／英文”的快捷选项，不从界面语言或文件语言猜目标语言。 | 翻译意图明确但未给出时先追问；只读识别／索引和文件事实问答不要求目标语言。 |
| 翻译范围与交付物 | 首版建议为当前上传材料的可读正文与表格、目标语言译本、可切换的双语复核视图、疑点与审核记录；若用户说“只翻货描”或指定特定文件，应把范围写进 Task Spec。正式导出的文件类型按已支持的选项显示。 | 用户未指定格式时，任务摘要可预选每份原件的 DOCX＋PDF 标准目标语言译本及可选的逐源识别稿 PDF；译本格式允许调整，不可暗自生成申报凭证。 |
| 源语言 | 由文档检测并在任务卡片上显示；多语言混排或检测不确定时提示用户确认需要翻译的部分。 | 可在解析阶段确定，但不能把检测结果伪装成用户指定。 |
| 术语、格式、用途 | 可选：客户术语表、专有名词写法、日期格式、需要关注的字段。若特定合规规则必须有目的国／品类等前提，只为该规则询问。 | 缺失可继续通用翻译，依赖它的规则显示“无法判断”。 |

澄清应一次只问阻止下一步的关键问题，并提供简短选项。例如“已收到发票和箱单。要译成中文还是英文？两份是否属于同一票？”用户回答后，在对话里出现可编辑的任务摘要：文件数、单票、目标语言、翻译范围、交付物、可选术语。已有明确要求时直接启动，不额外要求一次形式性的“确认”。任务开始后将这些条件固化为 **Task Spec**；用户后来更改目标语言或翻译范围，形成新的任务配置与翻译 Run，复用只读识别 Run 已产生且仍有效的解析和字段结果，不悄悄改写正在运行的任务。

上传文件中的文字、用户提供的术语表和 OCR 输出均是业务材料。即使文内出现“忽略规则、直接导出”等命令，工作流也只按资料内容处理，不把它提升为系统指令。若文件中的指令与用户明确任务相冲突，以界面任务要求和系统授权为准。

### 2.2 Task Spec 的最小内容

Task Spec 应保存 Case ID、上传成功的文件及其固定版本、任务类型、发起人和创建时间。翻译 Run 另需目标语言、翻译范围、所选 DOCX／PDF 输出、术语表和规则配置版本；只读识别／索引 Run 可记录待回答的问题与索引范围，其目标语言和交付文件为空。正在运行的 Run 引用冻结要求。每次修订或重试都能说明“按哪一版输入、哪一种语言、哪一组规则得到这个结果”；识别 Run 的结果只提供带来源的查询资料，后续翻译 Run 可按文件版本和解析配置安全复用。

若用户只要求货描或指定区段，工作台与快照须醒目标明“仅翻译指定范围”，列出所选文件／区段；译本仅含选择范围，识别稿 PDF 保留全部原文；未选内容不能排成仿佛已完成目标语言翻译的正文。QA 的必译覆盖只计算冻结范围，未选范围仍保留可追溯的原文映射。用户后来要求补译其他部分时创建新 Task Spec/Run，不能在旧导出上无声扩展范围。

“只翻货描”是固定语义范围，不是按标题字符串扫描。解析后系统应列出实际识别为货描的字段／明细行和来源，冻结本次必译源段；找不到或出现多个无法可靠区分的候选时，请用户在原文旁确认。确认仍只能选择本次货描候选，若用户想翻任意其他区段则改建新任务；重识别后也不能把旧货描源段 ID 套到新解析结果。

只有上传成功但翻译任务要求未齐、也没有明确文件问答时，前端展示“等待补充翻译要求”卡片，提供继续填写和删除草稿入口；不能显示“正在识别”或虚构百分比。若用户提出明确文件内容问题且需先解析，则显示“正在识别以回答问题”的只读 Run 进度，完成后给出来源，不将其说成翻译已开始。部分文件上传失败时，列出文件级原因，让用户选择重试或只用成功文件继续；被排除文件不会默默进入后续校验。

## 3. 校验工作台的页面形态

### 3.1 从哪里打开、打开后保持什么

校验工作台默认收起，以下入口打开同一页面状态：

1. 对话中的 Run 卡片“查看并校验”：打开当前有效的业务／译文版本配对，默认选中第一项未处理的高风险疑点；无疑点时打开原文／纯译文对照总览。若译文已过期，先打开固定原文和待重算状态，不拼接旧译文。
2. 对话回答底部的来源卡片：携带 Case ID、业务 Revision ID、Document ID、Document Version、Parse Artifact ID、LogicalDocument ID、DocumentSection ID、source anchor、source segment ID；涉及译文时另带 Run ID、目标语言、译文 Revision ID、translation segment ID、preview version，指向疑点时再带 Issue ID。先校验权限和版本，再打开右侧工作台并定位具体页、区域、段落或单元格；普通正文译段也能按源译片段 ID 双向定位，不限于已抽取字段。若引用是历史版本，显示“历史版本，只读”及返回当前版入口。
3. 单据管理台：从 Case 概览、批次行、源文件、疑点或 Export Snapshot 打开；已导出批次默认加载列表行所展示的快照，若该行命中历史快照就保持这份历史版。历史快照只读，首版提供显式“切换当前工作版”入口，修改始终针对当前工作版本；历史与当前版并排比较列入后续体验增强。关闭后恢复管理台的筛选、展开项和滚动位置。
4. 疑点列表里的项目：定位对应 Issue、两个或多个来源以及相关译文；保留回到疑点列表的位置。

右侧工作台是可拖拽宽度的面板。打开时可折叠左侧导航，为聊天和复核区保留基本阅读宽度；窗口过窄时改用全屏复核页，保持相同操作和定位。拖动时只更新布局，不重新请求 OCR 或清空当前选中的字段。面板边缘还应有“展开／收起”和键盘可操作的宽度调节控件，拖拽不是唯一方式。打开后键盘焦点移到工作台标题或目标疑点，焦点框清楚可见；关闭后焦点返回原来的来源卡片或“查看并校验”按钮，用户可继续按键盘浏览聊天。用户显式点击管理台文件、疑点或快照深链时，以该深链的目标版本和位置为准；只有没有显式目标时，才恢复该 Case 最近选中的版本、文件、Issue、视图模式、缩放和滚动位置。若选中对象已有新版本，保留当前历史视图并提示用户显式切换，不能自动跳到另一个值。

### 3.2 理想视觉结构与信息优先级

风格沿用对话主界面的克制感：浅色背景、细分隔线、紧凑但清楚的状态标签；把颜色留给需要注意的问题与当前定位。避免长期占满页面的红框。工作台内部建议按以下层次排列：

| 层次 | 固定或滚动内容 | 用户第一眼要看见的东西 |
| --- | --- | --- |
| 顶部固定栏 | Case 名称／编号、任务类型、目标语言、当前业务与译文 Revision、Run 状态、关闭／全屏按钮 | 目前看的是否为当前工作版，能否继续审核 |
| 概览条 | 源文件数、已解析页、待处理红项、待确认黄项、规则无法判断项、上次保存时间 | 当前最需要做什么 |
| 文件与视图导航 | 文件切换、原件／双语对照／字段／疑点／记录标签，问题筛选 | 在哪些材料和哪种视图之间移动 |
| 主工作区 | 原件渲染、结构化字段、目标语言译本或目标预览，按所选问题联动 | 原文到底写什么，系统读成什么，译成什么 |
| 顶部固定操作栏（标题下方） | 版本状态、未解决阻断数、保存草稿／复核完成／导出 | 重要操作常驻可达，窄宽可换行；正文/字段独立滚动，历史只读沿用禁用门禁 |

默认首先展示“疑点优先”的对照视图：顶端有红、黄、无法判断数量；点开问题后出现原文与译文，旁边呈现相关字段。宽面板或全屏可同时显示“疑点列表｜原件｜译文”三栏。中等宽度时问题列表改为可收起抽屉，原件和译文双栏；更窄时用“原件／译文／字段”标签切换，问题条固定在上方，不能把三个栏压成读不清的细条。布局阈值以原件可读和可操作为准，由前端样机验证，不把单一像素值写死为业务要求。

页面内各阅读区拥有独立滚动容器；固定栏不会随着长单据滚走。文件选择器按“源文件 → 逻辑单据 → 区段”展开，显示文件名、每节类型与页／区域范围、原语言和待办数；类型筛选作用于 LogicalDocument，不能把混合 PDF 整个归为发票或箱单。表格可横向滚动，但关键列（行号、货描或字段名）保持可见；长译文折叠后仍能展开全文。零疑点也要显示“已执行哪些检查”和“哪些规则未覆盖”，不只出现一枚笼统的绿色勾。疑点、字段、文件切换和修订按钮都能按键盘顺序操作，并显示清晰的焦点框；焦点移动不会擅自改动字段。

### 3.3 原文、译文、字段与疑点的双向定位

工作台以稳定的 **LogicalDocument ID、DocumentSection ID、source anchor、source segment ID 和 translation segment ID** 连接页面；段落、表格单元格等普通正文译段也记录这组对应关系。来源卡片或疑点点击后，先选中指定业务 Revision、对应 Run／语言的有效译文 Revision、Document Version 与区段，核对 preview version，等待对应页面完成渲染，再将原文所在区域滚至可见范围的中部，聚焦该字段或正文片段；随后定位相应译文片段和字段行。先高亮被点击的卡片，再在目标处保持同一选中标识，让视线有连续线索。一次点击只有一次程序滚动；新点击或用户手动滚动可立即中断旧定位，不能让多个滚动监听互相拉扯。原文和译文按片段语义对应，不按页面像素比例强行同步滚动。用户手动滚动任一侧时，自动跟随暂时停止；下一次明确点击字段、来源或“同步定位”才恢复。

| 用户动作 | 页面应发生的事 | 不满足时的反馈 |
| --- | --- | --- |
| 点击疑点 | 选中 Issue，展开原因、规则、原值和建议动作；原文与译文同时定位并短暂高亮；跨文件冲突展示 A、B 两个来源切换入口。 | 如果某一来源没有坐标，跳到最接近的页／段落，显示“无法精确框选”。 |
| 点击字段行 | 原件定位该字段来源，译文定位同一 segment；字段行显示原值、规范值、人工采用值和状态。 | 多个候选并列展示，不让点击动作等同于选择真值。 |
| 点击原文高亮区域 | 选中该区域对应字段或片段，字段区和译文区出现同一选中标识。 | 一个原文区域对应多个字段时弹出简短字段列表供选择。 |
| 点击译文片段 | 反向高亮对应逻辑单据／区段的原文与字段，显示所属 Run／语言的译文 Revision 和翻译状态。 | 无可用来源时显示“该段未建立可靠对齐”，纳入疑点。 |
| 点击“修订” | 打开该字段或译文的编辑区，保持原件与译文可见；保存后按编辑类型显示新的业务或译文 Revision 与受影响项，并回到同一区段。 | 版本在编辑期间已变化时展示差异，禁止用旧表单覆盖新版。 |

定位框采用：红色＝高风险或阻断，黄色／橙色＝待确认，蓝色＝当前选中，绿色＝已确认；始终配图标、文字标签与问题说明，不能只靠颜色。普通文本不铺满高亮。目标预览中的框必须来自**该预览渲染版本**的坐标；编辑后旧预览先标“过期”，preview version 与请求不符时禁止跳到旧坐标，改为定位仍有效的原文并提示重新生成译文预览。新预览完成再恢复译文定位。定位过渡可采用短时平滑滚动和轻微框线强调；系统启用减少动态效果时直接跳转。长表或多页 PDF 使用按需渲染，切页与缩放时保留选中锚点，不要求浏览器一次加载整票所有页面。

PDF／图片优先使用页号和映射回原图的矩形区域；经过旋转或裁切的派生图不能使原图坐标失真。DOCX 优先用段落、表格、单元格定位，不能编造稳定的“原件第 3 页”；若提供渲染 PDF 的页码，必须绑定该次渲染版本。解析服务没有返回可靠坐标时，显示页／段落级定位和“无法精确框选”，不让模型猜矩形。

### 3.4 字段面板如何组织

顶部先给一张简要信息卡：源文件、选中 LogicalDocument／DocumentSection 的类型与页／区域范围、原语言、目标语言、文件版本、OCR／解析状态、是否有不完整页面。下方按选中逻辑单据的类型展示相关字段：

| 分组 | 字段例子 | 显示注意点 |
| --- | --- | --- |
| 主体与联系 | 发票 Seller／Buyer；提单 Shipper／Consignee／Notify Party；通用发件人／收件人、地址、电话、邮箱 | 显示单证原有角色名及中文解释，不把 Seller 自动改称 Shipper；主体和联系信息可各自有不同来源。 |
| 单号与引用 | 发票号、订单号、合同号、提单号、柜号、铅封号、货物行号 | 保留前导零、字母大小写及符号；格式异常单列。 |
| 运输与日期 | 起运地、承运人接货地（Place of Receipt）、目的地、装货港、卸货港、运输方式、船名／航次、签发日期、装船日期 | 起运地与接货地分开标注来源角色；明确日期类型，不能要求不同用途日期一律相同。 |
| 货物与包装 | 原文货描、译文、数量、单位、件数、箱数、毛重、净重、体积、可用的 HS 原值 | 逐行显示行项目、包装层级和单位；HS 只给格式／已有证据风险提示。 |
| 金额与贸易条件 | 单价、行金额、总额、折扣、运费、保险费、币种、Incoterms | 说明金额口径；不同币种未指定汇率来源和时点时不作强比较。 |
| 翻译与质量 | 源译段落、术语、受保护数字／编号、漏译、表格对齐、目标预览 | 每个译文有对应的源片段、状态和可点击来源。 |

每个字段都显示“原件写法 → 规范值 → 人工采用值（如有） → 译文”，并有来源入口与状态。默认折叠低价值的普通字段，先显示有疑点、被修订和与导出有关的字段。结构化表格与 Markdown 阅读副本同时可用，但 Markdown 是阅读检索层，不作为唯一事实层。

## 4. 翻译校验工作流与产物

工作流按固定职责执行，允许基于结果进入人工复核或局部重算；不把 OCR、翻译、审单各自做成一个可自由决定业务真值的 Agent。下面的阶段是用户可理解的产品状态，不要求物理上拆成同样数量的服务。

| 阶段 | 输入与动作 | 持久化产物与可见反馈 | 暂停／失败分流 |
| --- | --- | --- | --- |
| 0 要求与文件接收 | 在草稿 Case 中上传并校验文件真实类型、大小、页数、哈希、权限、重复文件及归票；识别问答或翻译意图明确后分别冻结对应 Task Spec。 | 原件、Upload Session、逐文件结果；成功文件与草稿 Case 关联。 | 全部上传失败不创建 Run；翻译目标语言缺失时只等待翻译要求，明确的文件问答仍可创建只读识别／索引 Run。 |
| 1 分类与预处理 | 按页／区域识别发票、箱单、提单或其他佐证的候选边界；检查旋转、裁边、反光、模糊、文字层和混合页，产生派生识别图。 | 待确认的类型／区段候选、质量说明、页面处理路线，原件永不覆盖；尚未成功解析时不创建正式 LogicalDocument。 | 区段类型或边界不清请用户指定；关键页不可读提示重拍或补件。 |
| 2 解析与证据建立 | 原生 DOCX 与可用 PDF 文字层先直接解析；扫描页／嵌图走 OCR。MinerU 精准解析是候选，需与备选引擎用样本比较实际结构 JSON、表格和定位；在本次有效解析结果内确定 LogicalDocument／DocumentSection 边界。 | 不可覆盖的 `parse_artifact_id`、所属原件版本、逻辑单据与区段 ID／范围、原始解析响应、区段内页块／表格／行、源锚点、Markdown 阅读副本；逐页完成事件。 | 缺页、表格错位或关键区域不清时记录具体页。多模态模型只针对疑难局部给出第二候选，不将候选自动写成事实。 |
| 3 抽取与规范化 | 按所属 LogicalDocument 的类型映射主体角色、编号、日期、地址、电话、货描、行项目、金额、重量等；单位与数字作确定性规范化。 | 带 `parse_artifact_id`、logical_document_id／section_id 的字段、行、原值、规范值、候选和来源锚点；首次建立结构化字段时形成基线业务 `revision_id`，不代表人工确认。 | 多候选／低可信关键字段进入待复核；不能识别的字段保留空值。 |
| 4 业务校验与疑点生成 | 按逻辑单据类型运行材料完整性、格式、单据内算术和语义；跨逻辑单据做关系核对和有限规则包检查。 | Issue 引用一处或多处逻辑单据／区段来源，并保存规则归属、版本、风险与建议动作。 | 真正的原件冲突交人裁定；区段类型或规则前提缺失显示无法判断，不显示通过。 |
| 5 翻译与译文 QA | 以逻辑单据／区段内的源片段和字段为单位调用受控翻译模型，应用术语表并保护数字、编号、金额等；运行源译对齐、漏译与一致性检查。 | 译文草稿、带区段 ID 的源译映射、翻译 QA Issue、术语版本；逐文件阶段事件。 | 有高风险未决字段可生成带“待确认”标识的草稿译文，用于发现问题；不得因此成为正式交付值。 |
| 6 双语预览与人工校验 | 原件、字段、译文和疑点在工作台联动；人工确认、纠正识别、裁定事实或编辑译文。 | 字段／裁定修订产生新业务 revision_id；纯译文修订产生所属 Run／语言的新 translation_revision_id，并记录理由、受影响项。 | 按两类版本各自的依赖失效和重算；问题仍在时保持等待复核。 |
| 7 冻结与导出 | 锁定已确认的业务 revision_id、所属 Run／目标语言的有效 translation_revision_id 及术语／规则／模板版本；按每份成功处理的源 Document Version 生成所选格式的目标语言译本，按导出选项生成各源文件的识别稿 PDF，整体回检。 | 各源文件对应的 Export Artifact 及其文件哈希；全部通过后登记含映射 manifest 的 Export Snapshot。 | 任一源文件缺有效业务／译文版本配对，或任何应交付文件／识别稿 PDF 回检失败时，不登记成功快照。 |

只读识别／索引 Run 复用第 1—3 阶段，建立原件锚点、必要字段和检索索引后结束；“只读”指不改写原件或已确认业务事实、不做人工裁定和导出，允许保存解析产物。它不进入第 5—7 阶段，不形成译文、人工审核结论或 Export Snapshot。用户之后明确提出翻译时，新翻译 Run 根据固定 Document Version 与解析配置复用有效产物，过期或失败的部分才重做。原始证据、业务字段、阅读检索必须分层保存。**原始证据层**保留原件、解析原始响应和来源位置；**业务字段层**保留字段、明细行、来源、规则、译文、人工采用值与状态；**阅读检索层**保存 Markdown 和摘要。Markdown 中合并单元格、跨页续表、页坐标可能丢失，因此不能从它单独重建业务真值。多模态二次识别只在文字层和 OCR 仍存在具体疑问时对局部区域使用，界面并列展示候选及来源；两个模型一致也不能证明原件真实。

业务字段至少能区分原文转写、规范值、人工采用值和目标译文，并保留所属 Document Version、`parse_artifact_id`、LogicalDocument／DocumentSection。原文转写与原件锚点不可被后续修订覆盖；人工采用值必须保存操作者、时间、原因和补充依据。金额运算使用十进制定点，HS、单号、箱号等作为字符串保留前导零。明细行拥有所属 Document Version 与解析版本内稳定的行 ID；跨逻辑单据匹配可一对多或多对一，并保留匹配依据与人工确认状态。同一原件重新解析产生新 `parse_artifact_id`，替换上传才产生新 Document Version；两种情况下旧区段与旧行关联都要映射或标为待复核。

### 4.1 翻译策略与首版交付形态

翻译模型负责语言表达，业务事实来自字段与原文证据。任务按段落、表格单元格与字段组织，不用整票原文让模型自由改写一份新单据。公司名、地址、电话、邮箱、单号、柜号、铅封号、HS、日期、币种、金额、数量与单位分别配置保护或专门转换规则；需要音译、单位换算或目标市场习惯写法时，保留原值并明示转换依据。术语库可以约束“件／箱”“净重／毛重”“收货人／通知方”等高风险术语，同一术语在同票内应有一致提示。

**首版正式输出**按上传的 Source Document 文件拆分：任务范围中每份成功处理的源 Document Version 各生成一份逐段／逐字段可回指来源的目标语言译本，DOCX／PDF 按用户所选格式生成，默认两种格式都选；每份源文件可选同时生成识别稿 PDF；跨文件疑点和人工处置在工作台与冻结审核记录中查看，不单独导出报告。一个 PDF 内即使有多个 LogicalDocument，首版也只为这个物理源文件生成一份译本；译本内沿用识别后的页、段落、表格行列与合并格、横线结构，原始页／区域来源保留在工作台及快照映射，不承诺自动拆为多个正式文件。工作台和对话完成卡片列出每份原文件及对应可点击译本，不能只给一个不说明内容的打包下载。左侧默认识别后的结构原文，右侧默认纯目标语言译文，可切换双语或导出预览。保留表格、合并格、横线和源分页边界；译文变长允许单元格扩展或字体适度调整，不承诺扫描件的像素一致或最终页数完全相同。原件若是提单、证书或其他需有权主体签发的文件，输出需标为“翻译件／供业务复核”，不复制签章制造有效原件的外观。统一模板发票／箱单可在后续基于已确认字段生成，仍须区分“业务草稿”和实际签发文件。

## 5. 校验矩阵：吸纳竞品能力，控制误报

竞品报告中，PaperEntry 强调发票／箱单明细、必填、金额、HS、国家和主体信息；合合 DocFlow 强调原文坐标和跨文档审核；iCustoms、Digicust 强调同票合并和规则／缺证；Smartcat、Phrase 强调数字、标签、术语、空译和源译一致性；贸易金融审单工具强调规则依据、专家裁定与审计。下表将这些能力转为本产品的检查项，**并不表示它们已经被实现或已在本项目样本上验证**。

| 检查组 | 首版检查与疑点示例 | 判定前提及边界 | 初始处理 |
| --- | --- | --- | --- |
| 材料完整性 | 文件损坏、漏页／重复页、混合 PDF 扫描页漏读、表格截断、跨页明细漏行、关键区遮挡。 | “原件疑似不完整”与“解析遗漏”分开；页数只能对已知文件做覆盖检查。 | 关键材料不可读标红；非关键残缺标黄，指明页。 |
| 字段必填与形式 | 指定单证的必要编号、主体、数量、金额、日期缺失；电话／邮箱、日期、币种、编码和单位格式异常。 | 必填项随文件类型、任务和目标模板变化；HS 六位与国别扩展码不是同一校验长度。 | 影响翻译和交付的缺失标红；格式疑问标黄。 |
| 发票内部算术 | 数量 × 单价与行金额、行金额合计与总额、折扣／运费／税费的计算关系。 | 只按明确存在的费用口径计算；货值与含运保费总额不可盲比，容差需有规则配置。 | 确认口径下不一致标红，并列计算依据。 |
| 箱单内部逻辑 | 明细件数／箱数汇总、同口径下净重不应大于毛重、包装层级与汇总数。 | 件、箱、托盘不能机械相加；分批与混装应先确认范围。 | 已知同口径冲突标红；口径不明标黄／无法判断。 |
| 同票行项目关系 | 发票与箱单货描、数量、单位、包装对应；数据模型允许一行货品分多个箱、多个明细合并运输。 | 首版只自动判断有明确依据的一对一或同口径汇总；复杂一对多关系交人工确认，第二阶段再增加自动匹配。 | 高可信且同口径的数量冲突标红，未匹配行标黄或红取决于必需性。 |
| 跨单证运输关系 | 箱单／提单的件数、毛重、柜号、起讫地及运输参考号核对。 | 必须限定同一运输批次、同一包装层级；毛重与净重不直接要求相等。 | 真冲突标红，批次不明标无法判断。 |
| 主体与联系关系 | Seller、Buyer、Shipper、Consignee、Notify Party 的名称、地址、电话变化和角色映射。 | 不要求不同角色字符串相等；HBL／MBL 关系也可能不同。先确认是否被业务规则认定为同一主体。 | 疑似同主体冲突标黄，确认角色映射后的关键冲突标红。 |
| 日期与地点 | 发票日期、装船日期、签发日期及起运地、装货港、卸货港之间的关系。 | 日期用途不同，只有明确规则才能判断先后；原产国、发货国和出口国不可混同。 | 条件已知的违反标红／黄；条件不足显示无法判断。 |
| HS／证书风险 | 已出现 HS 编码的形式、货描与编码的明显不一致候选；首版锁定一条贸易线路和一类货物的经核验小规则包，检查该范围内的一项必要证书是否缺失。 | 规则包记录权威来源、有效期、目的国、品类、触发条件与审核人；不自动最终归类或宣称普遍合规通过。范围外或前提缺失明确显示“未覆盖／无法判断”。 | 在适用条件已满足且证书明确缺失时标红；不适用的例子标“不适用”并列依据；未覆盖单列，绝不显示通过。 |
| 翻译保护与完整性 | 金额、数字、币种、日期、单位、单号、箱号被改写；空译、漏段／漏行、表格错位。 | 原样保留字段与合法单位转换要区分；OCR 原文有疑点时译文同时标待确认。 | 关键标识被改写、漏译重要行标红。 |
| 术语与语义 | 主体角色错译、毛重／净重或件／箱混用、同票术语不一致、明显语义反转。 | 语义模型可提示候选，但要让审核人回看源文；不凭模型自报置信度自动放行。 | 影响业务理解标红，风格／一般术语标黄。 |
| 输出回检 | 译本漏字段、漏明细、页边界溢出、乱码、公式或表格不可读、PDF 文本不可抽取。 | DOCX／PDF 应与冻结的有效业务／译文版本配对、各 DocumentSection 的翻译段落数及模板版本对照；复杂页必要时人工检查。 | 交付完整性失败标红并阻断快照登记。 |

上表是完整目标检查清单，首版优先落地材料覆盖、关键字段形式、发票金额算术、箱单计量、明确同口径的跨单证数量／重量核对，以及数字、编号、单位、空译和漏行等翻译 QA。为覆盖赛题的目的国证书／HS 要求，首版还应在锁定线路与货物后做一个**经核验、范围很小**的规则包。用该包中实际核验的一项证书要求准备三份测试材料：条件全部满足但未见证书，显示“缺证”及依据；货物类别不满足该规则条件，显示“不适用”及理由；目的国或品类超出规则包，显示“未覆盖”，不能显示通过。这些是测试情形，不预设某国某货物真实需要哪种证书；没有适用依据时不运行泛用法规判断。复杂一对多自动匹配、更多角色语义规则和更多目的国／品类规则留到后续；尚未实现的检查不得在界面显示为“通过”。

每条规则要保存适用逻辑单据类型与 ID、字段、比较口径、阈值或容差、严重度、版本、依据和无法判断条件；跨单证规则列出参与的各 LogicalDocument／DocumentSection，不能因同属一个物理 PDF 就跳过核对。不同文件“看起来一致”只表示已检查范围内一致，不证明现实货物、单据真实性或合规。签章是否检测到、签章文字是否可读、是否疑似被改动、是否具有法律效力属于不同层级；首版不将视觉检测结果当真实性鉴定。

## 6. 疑点清单与人工修订

### 2026-10-10 字段与疑点分离及统一五动作（本节最新口径）

字段是从单据提取的关键业务信息，疑点是识别、信息完整性、翻译、布局或同票关系中具体需要处理的问题。两者可关联但不是同一个对象：一条漏译段落的疑点可以没有字段；一个售出方地址字段可以没有疑点。字段标题必须完整表达原件角色，例如“售出方地址”“买入方地址”“发货人电话”“收货人邮箱”“通知方名称”；不得用“地址／名称”两条同名行再让用户猜英文 role。售出方不自动视为发货人，买入方不自动视为收货人；起运地、交货地、原产国也独立。

字段页只显示该字段确实关联的未解决疑点，已解决和其他字段／整文件无关疑点不挂在行上。用户可确认有原文依据的非空字段，确认业务值不等于解决该页其他翻译或布局问题；缺来源、空值、版本冲突、历史只读仍明确解释。定位原文／译文保留字段标签与选中行，在旁侧阅读面板切换原文／译文并定位，窄屏使用可返回字段的阅读页，不丢当前字段与滚动。

每条疑点卡片按固定顺序展示且只展示五个处置入口：

| 按钮 | 实际行为 | 不适用／未完成时 |
| --- | --- | --- |
| 修订译文 | 人工编辑有关译段，保存本语言新译文版本并更新相关 QA／预览；不改原始 OCR 与业务事实 | 无对应译段也保留按钮，禁用并说明“当前问题无可编辑译段” |
| 忽略并记录 | 明确忽略此项，保存操作者、时间、原风险、选填理由；不改机器原结论 | 历史只读或权限不足禁用；理由留空不阻断提交 |
| Agent处理 | 所有疑点均允许输入处理意见；Agent 在本项授权证据范围内判断，产生局部修改或具体建议 | OCR不可读／原件缺失时建议补证，不编造原文；未完成修改或检查不自动结案 |
| 应用推荐修改 | 已有明确可写入的局部修改方案时调用受控操作，保留审计和版本 | 泛泛“请检查”不能作为可应用方案；无具体方案时按钮仍在但禁用并提示 |
| 补充上传 | 打开针对本疑点的补充材料入口，可上传文件／图片或明确替换原件，保留关联 | 新材料不直接解决旧问题；固定输入发生变化需新任务，复核新结果后结案 |

每条疑点说明必须包含：具体问题、发生在何文件／页／段／格、原文与译文证据（可用时）、影响、推荐方式、哪些前提无法判断、当前状态。标题不能只写“质量问题”。点击来源先解析授权与固定版本，再按真实锚点定位并以蓝色高亮当前选择；无坐标时定位到可核验段／单元格或页面，并告知精度，禁止画猜测框。蓝色仅表示“当前所选位置”，红／黄仍表示问题等级。

内部疑点 Skill 统一识别 OCR 模糊／缺页／漏行、缺失关键资料、术语／角色／语义误译、漏译／数字单位错译、版式错位、跨单证冲突、专业规则前提不足。红项只用于有足够证据且影响关键交付的未解决问题；黄项用于可交付但应注意的事项；无法判断用于证据或规则前提不足。只有未解决红项硬阻断疑点门禁，黄项与无法判断不硬阻断；权限、版本、文件真实存在与交付完整性检查保持实际必要约束。默认只列未解决问题，已处理保留在处理记录／已处理筛选。

旧裁定／接受／不适用数据仅用于历史审计，当前疑点交互统一使用以上五动作；忽略理由选填。文件类型和货物领域独立：票据类型决定基本角色字段与核对逻辑，货物领域补充批次、检疫、危货等适用字段，未知类型走通用路径；不能因选中某货物就宣称通过国内外全部法规核查。

### 6.1 疑点卡片的内容和状态

每项 Issue 至少展示：标题、红／黄风险、问题类别、涉及的源文件版本及 LogicalDocument／DocumentSection、原文值／规范值／译文值、触发规则与版本、实际差异、可点击的来源位置、建议动作、创建时间和当前处置状态。跨逻辑单据冲突即使发生在同一个 PDF 内，也要并列给出两个原文，不用一个“推荐正确值”覆盖另一个。信息不足时清楚写“无法判断的原因”，与通过状态分开计数。

| 状态 | 触发与界面表现 | 后续动作 |
| --- | --- | --- |
| 待处理 | 新疑点进入待办，红项排在前，显示涉及文件与原文入口。 | 点击定位查看证据；通过上述五个统一入口处理。 |
| 处理中 | 用户进入编辑或工作流正在按新业务／译文版本配对重算；保留旧问题记录。 | 新结果出现前不显示“已通过”。 |
| 已自动消除 | 修改后的规则重算通过；旧 Issue 归档并指向新结果。 | 可查看旧值、触发原因与变更。 |
| 已人工裁定 | 有权限的复核人根据可核验原文或补充证据选择采用值，填理由并留名。 | 原件规则结果仍记“冲突”；依赖重算和翻译 QA 完成前，不能据此解除交付阻断。 |
| 已确认可接受／不适用 | 一般提示经复核接受，或规则条件确实不适用；保存理由。 | 审核记录仍列出提示／不适用依据。红黄疑点均允许用户显式忽略，理由选填；原风险级别与规则结论仍保留，忽略不表示自动检查通过。 |
| 无法判断／过期 | 缺证、规则未覆盖或引用过期的业务／译文版本；标识原因和所需信息。 | 与“通过”分开展示；信息缺失只有形成未解决红项才作为疑点阻断；过期版本或无法生成有效文件仍需恢复。 |

每项冲突分开保存三个判断：**原件规则结果**（通过／冲突／无法判断／不适用）、**人工处置**（未处理／已修订／有依据裁定／接受提示／已忽略）和**当前业务／译文版本配对的交付门禁**（阻断／可导出）。例如发票与箱单数量不一致，修订采用值后原件规则结果仍为冲突；显式忽略也只关闭该疑点待办并留下操作者、时间和选填理由。审核记录保留两侧原值、推荐方案、实际采用值与完整处置链。所有疑点允许忽略，但权限、版本有效配对、真实模型产物、必要译段非空、覆盖完整及产物可读取的技术检查不能通过忽略绕过。

红项代表关键事实、重要译文或输出完整性风险，未处置时阻断确认稿；黄项代表需要查看或记录接受理由的提醒。疑点仅按当前严重度与处置状态决定阻断：只有未解决红项阻断，黄项及其他提示不阻断；不以模型分数直接决定。仅用于合规提示、但缺少已审核规则的“无法判断”不会阻止输出**翻译件**，审核记录必须注明合规未评估；翻译所必需的源文若不可读，则属于阻断，不能借“无法判断”绕过。

### 6.2 四类常用处置

1. **纠正识别。** 原件清楚但 OCR／抽取写错时，用户在原文旁填入正确转写，确认它与原件可见内容一致。保留原 OCR 值及修订记录；保存时只增业务 `revision_id`，让依赖该字段的译文与预览失效，不立即增译文版。
2. **裁定业务事实。** 两份原件真实矛盾时，有权限的复核人选择采用值或输入新值，附理由及可核验的补充材料／业务依据。页面同时展示“原件 A 写什么、原件 B 写什么、人工采用什么”；原件锚点不被当作人工值的证明。保存裁定只增业务 `revision_id` 并触发受影响规则与译文失效，不能在保存按钮点击后立即宣称已可导出。
3. **修改译文。** 用户仅调整当前 Run／目标语言的译文或局部术语写法，源字段和事实裁定不变；保存时只增该 Run／语言的 `translation_revision_id`，保留所依据的业务 `revision_id`，重跑相关翻译 QA 和预览，不重新 OCR、抽取或业务算术。
4. **补件与重识别。** 模糊或缺页时可上传补充文件、替换原件或申请重识别：补充文件建立新的 SourceDocument，替换既有原件才新增其 `document_version`；同一原件重识别只新增 `parse_artifact_id`。补充文件加入或替换原件版本改变已启动 Run 的固定输入集合时，应按新 Task Spec 建新 Run；首版重识别至少支持按文件重跑，页／行级局部重识别在下一阶段实现。新解析版本导致相关业务字段与区段、行匹配和译文过期，不能继续显示旧“已核验”。

保存修订时显示简明影响范围，如“数量变更将重算发票合计、箱单对照、相关译文、摘要和导出预览”；只改译文则显示“重查本语言的术语、数字和预览，不改变业务字段”。服务端按编辑类型校验当前版本：字段／裁定编辑只创建新 `revision_id`；有实际依赖变化的译文先过期，局部重译和 QA 后形成新译文版，依赖未变的旧译文版可凭兼容记录与新业务版配对；纯译文编辑只创建该 Run／语言的新 `translation_revision_id`。页面保持选中 Issue 与滚动锚点，完成后更新卡片和双语预览。重算尚未完成时相关区域标“更新中／旧预览已过期”，不把旧内容和新字段混在同一确认视图。多用户协作时若任一相关版本变化，阻止旧表单直接覆盖新版本，提供差异查看与重新应用；首版即使只用单用户演示，也应按用户／团队权限隔离所有读取和写入。

## 7. 流式进度、失败恢复与页面联动

“流式输出”展示真实的 Upload Session 和 Run 事件，而不是让对话模型按预定句式假装正在处理。事件持久化后由事件通道推送，聊天任务卡、校验工作台顶部和单据管理台从同一状态源读取；断线按事件序号补齐，重复事件只显示一次。上传字节、已处理页数这类有明确分母的工作可显示百分比；模型抽取和翻译不编造“完成 87%”。

| 状态或事件 | 对话任务卡 | 工作台及用户动作 |
| --- | --- | --- |
| 等待翻译要求／上传中 | 显示翻译任务缺少的目标语言或逐文件上传字节、失败原因。 | 可补参数、重试失败文件；仅上传且无明确文件问题时不出现虚假解析进度。 |
| 只读识别／索引中 | 文件事实问题尚无解析产物时，显示当前文件及真实解析阶段，不显示“正在翻译”。 | 可查看已建立的原文和字段来源；完成后回答问题，保持译文与导出入口关闭。 |
| 排队／分类／解析 | 显示当前文件、阶段和已处理页数。 | 可查看已完成文件的原件；字段与疑点尚未完成时标为暂不可用。 |
| 抽取／校验／翻译／预览 | 显示实际完成的文件与阶段，必要时显示发现的疑点数。 | 可逐步查看已持久化的阶段结果，但未完成的内容标“处理中”。 |
| 等待人工复核 | 卡片显示红、黄和无法判断数，按钮“查看并校验”。 | 打开疑点首项；复核、补件或修订，处理后只重算受影响项。 |
| 外部请求待核查 | 显示受影响步骤、发生时间和“等待运营核查”，不显示可直接重试的按钮。 | 有运营核查权限者可查看请求键、供应商凭据并记录已执行／确认未执行／仍无法确认／终止；普通用户只能查看状态和联系处理人。 |
| 可导出／导出中／已导出 | 显示冻结版本、目标语言、生成与回检进度；成功后给下载入口。 | 提供最后确认清单；成功快照可反复下载。 |
| 失败／取消 | 显示出错文件、步骤和可执行的恢复动作。 | 解析失败处理文件；翻译 QA 失败重译相关段；导出布局失败只重生成输出。 |

浏览器刷新、切到管理台或关闭校验工作台不能让后台 Run 消失。重新进入时先读取持久化状态，再接实时事件；没有新事件时显示最后已知状态及时间。发生供应商超时或网络故障时，系统先查询已保存的外部任务 ID／幂等结果再安全重试，不能无边界重复提交收费任务。取消处理不删除原件、历史问题和既有 Export Snapshot。旧业务版或旧译文版的处理结果若较晚返回，必须留在其原版本下，不能覆盖当前有效配对。

聊天来源卡片、疑点卡片与工作台的联动契约至少包含 `case_id`、`revision_id`（业务版本）、`document_id`、`document_version`、`parse_artifact_id`、`logical_document_id`、`section_id`、`source_anchor`、`source_segment_id`；涉及译文时再带 `run_id`、`target_language`、`translation_revision_id`、`translation_segment_id`、可选 `translation_compatibility_id` 与 `preview_version`，指向疑点时另带 `issue_id`。工作台先校验用户／团队访问权，再核对逻辑单据与区段属于指定原件和解析版本，译文版属于指定 Run／语言，且创建时直接依据该业务版本或通过有效兼容记录与该业务／解析版本配对，预览也对应同一有效配对；旧 `preview_version` 已过期时只定位所引的历史原文并提示译文预览需重建，不能落到另一版译文的相似坐标。对话中的“这处为何标红”查询引用业务版及其有效译文版的 Issue 与规则；回答可以自然表达，但必须引用来源和版本。前端点击引用可打开右侧具体逻辑单据／区段的字段或普通正文片段，不能只停在文件首页。工作台修订或导出后，通过业务／译文版本事件更新对话卡片和管理台；旧对话回答仍标明当时引用的版本，不自动篡改历史措辞。

## 8. 确认、导出与管理台留存

“复核完成”前显示一张检查清单：任务目标语言与范围、源文件与逻辑单据／区段、红项是否已解决、黄项的接受记录、无法判断与未覆盖规则、人工采用值、译文 QA、目标文件类型和确认人。用户确认的是**冻结的业务 `revision_id` 与所属 Run／目标语言的有效 `translation_revision_id` 配对**，需要时连同 `TranslationCompatibility` 依据一起冻结。确认操作产生不可变 `ReviewConfirmation`，记录清单摘要、版本、确认人和时间；后续相关修订使当前确认失效，旧确认仍可审计。字段／裁定变化只先产生新业务版，译文变化只产生本 Run／语言的新译文版，再执行各自受影响的 QA 与导出，不覆盖旧快照。

确认稿的导出条件如下：

- 当前版本未解决红项必须已通过实际修复或显式忽略退出待办；历史裁定仍可读取。每种处置记录操作者、时间和版本，忽略理由选填。补充上传本身不关闭疑点。修订触发的 QA 与预览必须完成；忽略保留原风险和结论。权限、版本、空译、必译覆盖、非真实模型产物等技术错误仍阻断。
- 黄项、无法判断与未覆盖规则均不阻断；用户主动忽略时记录确认人与选填理由，未解决提示在审核记录中清楚保留，不出现“已合规通过”的暗示。
- 对每份交付源文件，译文版均属于所选 Run／语言，创建时直接依据当前业务 `revision_id`，或有经依赖与 QA 验证的 `TranslationCompatibility` 与当前版配对；相关译文与预览均未过期，源译片段、LogicalDocument／DocumentSection、关键字段和行数可追踪；生成文件通过内容、可抽取文本和版面回检。版本不成有效配对时导出被阻断。

工作流先在暂存位置逐个生成并回检所有输出。**Export Snapshot 是冻结的 manifest／文件组**：列出 Case ID、Run ID、`review_confirmation_id`、业务 `revision_id`、目标语言、规则／术语／模板版本、确认人、生成时间；每条文件映射列出源 Document Version、所用 `parse_artifact_id`、该 Run／语言下的有效 `translation_revision_id`、必要时的 `translation_compatibility_id`、其内部 LogicalDocument／DocumentSection 清单、输出格式、Export Artifact ID、文件哈希和受控下载地址，按原件列所选识别稿 PDF。导出启动与快照登记时均重新核对确认清单及当前版本；选定范围内每个源文件的所选格式及所选识别稿 PDF 全部回检成功后，才原子登记整个 Snapshot；某一份译本失败时只重做失败产物，但整组仍未成功，不在管理台出现部分“已导出”。若确需排除失败文件，用户须明确调整 Task Spec 的任务范围并形成新 Run，任务记录列明排除原因，不能静默少交文件。管理台的“转换后文件”**只列成功快照中的产物**，按原文件展示对应可点击的 DOCX／PDF 和所选识别稿 PDF；失败产物和处理中预览不进入正式列表。已经成功生成的文件即使浏览器下载中断，仍可下载同一快照。历史快照只读保留，新业务或译文版出现时标明旧快照不是当前版。原件、Run、Issue 与裁定历史在有效保留期内继续可查；单票自最后一次实质性业务变更起保留 30 个 24 小时，到期或 Case 所有人主动删除时按整票清理；详见[单据管理台产品设计](单据管理台_产品设计.md)第 7.2 节。

页面允许查看双语复核视图，或按权限下载醒目标为“待确认／草稿”的纯目标语言预览供讨论，但不能把它放进“确认稿”或“成功导出”列表。若高风险问题仍未解决，正式导出按钮显示阻断数量与可点击原因，直接带用户回到第一项阻断疑点；不能只给一个灰色按钮。

## 9. 权限、来源与可审计性

所有 Case、文件预览、字段、Issue、Markdown、摘要、翻译、来源卡片和导出下载都按用户／团队权限过滤；不能因知道某个 Case ID 或深链锚点就访问另一用户的材料。将来做团队协作时记录操作者与权限角色；单用户演示也要从认证身份取得确认人，不使用“系统自动确认”冒充人工。第三方 OCR／翻译服务的使用集中在隐私与数据处理说明中告知，上传处不再增加服务节点和额外确认，日志避免记录大段原文、密钥和敏感联系信息。

校验记录需要能回答四个问题：哪份原件的哪一处引出该字段；应用了哪条、哪个版本的规则；谁基于什么依据改成当前采用值；目标译文和 Export Snapshot 属于哪一版。外层 Agent 读取这个业务视图回答，而不能把聊天里曾说过的值当权威字段。法规、目的国证书、HS 归类和能否通关的结论，只有经过专业审核且有生效范围的规则包才能作有限提示；没有覆盖时说“未评估／无法判断”。

首版验收建议以具体路径检验，不用模型“准确率”自述代替结果：

1. 用户只上传文件没说语言且未提问时，系统停在翻译要求澄清；若随后只问“收货人是谁”且尚无解析产物，可启动只读识别／索引 Run 并以来源回答，不启动翻译。之后用户给出目标语言和范围才开始翻译 Run，能复用有效解析产物且不会重复创建相同收费工作。
2. 一票的图片箱单、PDF 发票和 DOCX 补充资料都保留原件；PDF／图片的关键字段可回页，DOCX 可回段落或表格。不能精确定位的字段明确显示定位级别。
3. 测试材料中预置的数量冲突、行金额错误、箱号改写或漏译，分别进入对应红／黄疑点；Seller 与 Shipper 角色不同、净重与毛重不同等合理差异不能一律报错。
4. 从对话来源卡片点击后，校验工作台打开指定原件／解析／业务／译文版本配对及其 LogicalDocument／DocumentSection 和原文位置，键盘焦点落在工作台标题或选中项；关闭后焦点回原触发项。普通正文段落与已抽取字段都能按源译片段 ID 双向定位；从疑点点修订后，原文、字段、译文仍围绕同一区段。新点击可中断旧定位，手动滚动不会被自动同步拉回；旧 preview version 不会跳到新版译文的错误位置。
5. 修正数量后只新增业务 `revision_id`，金额和跨逻辑单据规则重算，受影响译文与预览先标过期；局部重译及 QA 完成才形成可配对的新译文版，未受影响的原件和 OCR 不重复运行。仅修改一处译文时只新增当前 Run／语言的 `translation_revision_id`，业务 `revision_id`、其他语言译文和业务算术不变。旧 Issue 与旧快照仍可查，任何不成有效配对的版本都不能导出。
6. 同票原件存在数量冲突时，有权限的复核人提供可核验补充依据、写明理由并选定采用值；依赖规则和译文 QA 在有效业务／译文版本配对上重算完成后，交付阻断才解除。报告和工作台仍显示两份原件的冲突及裁定链，不将原始规则结果改写为“通过”。
7. 对同一冲突，用户可修订或显式忽略（理由选填）；忽略后原风险与原始规则结论仍可审计。忽略不得绕过空译、覆盖缺失、版本过期或权限等技术门禁，按钮显示真实缺口与可点击的原文位置。
8. 锁定线路／货物的小规则包各有“适用且缺证”“不适用”“规则未覆盖”测试样例；每项分别展示规则来源和适用条件、为何不适用或为何未覆盖，未覆盖不得显示“合规通过”，HS 风险不被包装成最终归类。
9. 三份成功处理的源文件选 DOCX 和 PDF 时，各得到对应的目标语言 DOCX／PDF，另可选逐源识别稿 PDF。把发票与箱单放入同一混合 PDF 的样本应产生两个有类型、页／区域范围与 ID 的 LogicalDocument／DocumentSection；字段、行、Issue 和源译片段各指向正确节，类型筛选与发票／箱单规则分别命中正确逻辑单据，但导出仍只为这个源文件生成一份内部分节的译本。完成卡片可逐文件点击；任何一项文件生成或回检失败，都不登记整组 Export Snapshot。下载中断可再次取得同一成功快照。
10. 任意深链、来源卡片、文件预览和导出下载都验证访问身份与版本；跨用户尝试不能读取材料，历史引用不能冒充当前版。
11. 从管理台历史快照的文件或疑点进入时，侧栏优先打开该快照冻结的业务／译文配对及对应原文，清楚标为只读；“切换当前工作版”是显式动作，不能让恢复上次位置覆盖此次深链。未解析原件只显示可读取的原件预览及解析状态；关闭侧栏后管理台的筛选、展开项与滚动位置保持不变。
12. 对同一原件申请重识别时产生新 `parse_artifact_id`，保留原 `document_version`；逻辑单据、区段、字段与疑点的旧锚点仍能用于历史快照。用户重新上传替换原件才新增 `document_version`。两种变动都不能把旧区段、行项目或译文未经映射与复核直接套到新工作版。

以上验收范围应结合样本制定可测门槛，并区分字段正确率、行项目完整率、真实错误检出率、正常差异误报率、人工复核用时、译文关键标识保持率和可用导出率。固定测试集里的植入错误不应漏检；这只是对该测试集与已实现规则的要求，不构成对未来所有材料的准确性保证。

## 2026-10-05 补充验收：版式复原与智能疑点处理

### 页面与导出

对照页左侧默认展示识别后的原文结构，可切回原文件图；右侧默认仅目标语言译文，无“原文/译文”前缀。右侧提供纯译文、双语对照和导出预览切换。原文中的表格（含行列/合并格）、横线、标题和显式分页进入统一布局数据，预览和导出共用，不能将表格展平为段落。用户已确认：译文变长可扩展单元格或适度调字号；保持源分页边界并清楚标注实际溢出页，不能裁掉文本。OCR布局坐标不可靠时按已识别结构复原，公开展示缺失信息，不能宣称像素一致。正式导出只输出译文，源文及双语用于复核；疑点报告独立。已有历史成功快照不改写。

### 智能疑点操作

每个疑点展示中文类型、触发证据、问题具体位置、影响、当前内容、推荐处理方法及可采用替换内容。分类至少含：翻译语义/角色/术语、识别漏缺/不清、关键字段缺失、数值/单位/跨票冲突、规则范围未覆盖。提示不得笼统以规则ID代替业务描述。

- 应用推荐修改：对具体、可定位到唯一授权译段的完整候选追加修订版本；没有方案时保留按钮并禁用说明，缺失源信息不得猜值。
- 修订译文：打开对应译段供人工编辑，保存后展示新版；业务字段修订单独在字段页进行。
- Agent处理：输入处理意见，只送当前授权来源、译段和本项疑点给局部处理流程；异步账本/Outbox执行。无可写译段时分析资料并建议补证，未实际修复不自动结案，不整票重译，不让对话Agent直接改数据库。
- 补充上传：保留原单票及疑点关联，补充文件或图片；经实际验收后追加处理记录。旧任务固定来源不变，新材料需进入新处理任务，不自动关闭旧疑点。
- 忽略：所有红黄及未覆盖疑点均可由有复核权限用户明确忽略，记录人/时间/版本，理由选填。忽略解除该条人工疑点待处理状态，但不更改规则原结论，也不能越过源文件权限、实际空译漏段/输出不可读等技术完整性检查。
- 任一编辑只影响依赖项；更新时保留锚点并显示更新中，已处理风险保留可回查原始证据。
