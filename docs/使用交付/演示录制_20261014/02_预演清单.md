## 4. 主线预演操作门槛

### 4.1 对话与识别

- [ ] Q1 物流概念回答自然、可连续追问，首字与后续流式内容连续，无“意图识别不可用”等报错。
- [ ] Q3 仅解释操作，不实际发起一个缺材料任务。
- [ ] 上传后若需类型、语言或分段边界确认，先答完当前必要输入；不能对灰色按钮反复点击。
- [ ] Q4 涉及主体/路线/货物的结论来自本票；没有因上下文预算遗漏而错误声称已存在信息缺失。
- [ ] Q5 说明初版400/390的分歧；没有将托盘数、箱数、商品净重、总毛重混为一谈。
- [ ] 来源默认紧凑可收起；展开是这票的原件/译本/字段及处理依据，不把所有内部块显示成几十个文件。
- [ ] 点击来源后准确到页/位置并出现蓝色高亮；关闭侧栏后对话滚动位置合理。

### 4.2 翻译及工作台

- [ ] 当前目录确有四文件相应单据类型；不存在采购订单类型时记录并选通用，不能强行选报关单。
- [ ] 翻译要求明确中文、全文、DOCX＋PDF；界面语言不会偷偷改变任务目标语。
- [ ] 本次首次识别使用原生PDF，旁白称“识别/解析”，不说已经验证了MinerU扫描OCR。
- [ ] B02 源文和纯译文有完整3页；页面能够平滑滚动，不锁住背景或把弹层内滚动传给错误容器。
- [ ] 预览按钮实际为「导出预览」，不是不存在的独立“预览页面”。
- [ ] 字段「主体与联系」里发货人/收货人的名称、地址、电话、邮箱角色可辨。
- [ ] 「确认无误」展开确认表单后还要点「确认此字段」；状态确实改变，不能只录第一次点击。
- [ ] 「定位译文」保持字段页，右栏切译文且目标高亮；不是导航离开字段页。
- [ ] 不相关字段不显示其他疑点；当前字段有疑点时才展开关联情况。
- [ ] 复核工作台顶部操作区可用、主体阅读空间足够；总览、字段、疑点、处理记录切换不抖动。

### 4.3 同票核对与疑点五种操作

先锁定预演中真实出现、适合演示的疑点；记录 ID 仅用于定位，正式录制要重读当次结果，不硬套旧 ID。

| 操作 | 适合的疑点 | 成功信号 | 不可采用的替代行为 |
| --- | --- | --- | --- |
| 修订译文 | 有对应译段的地址表述、仓库团队称呼等 | 当前段保存、预览更新、留下修订记录 | 将390的原件事实直接改成400 |
| 应用推荐修改 | `can_apply=true`且推荐文字合理 | 建立真实修订，疑点按新结果更新 | 无建议时改DOM启用按钮、只点按钮就宣称成功 |
| Agent处理 | 有清楚具体修改指令或核查问题 | 请求完成、内容发生合理变化或给出真实处理结果 | 把排队当完成；让Agent编造缺失当事人 |
| 忽略并记录 | 人工确认不影响交付的提示 | 可空理由、已处置可追溯 | 把真实数量冲突忽略后宣称所有单据一致 |
| 补充上传 | B02初版数量及依赖重量差异 | B02 v2解析、重新核对和新翻译全部完成 | 当新第五份独立货物上传，或旧矩阵直接显示成新结果 |

- [ ] 比较范围确认同货批 `SHIP-DEMO-B-2026`、完整材料、瓦伦西亚→上海同一海运阶段。
- [ ] 草莓 `FRA-8` 和蓝莓各自SKU/批次匹配，候选关系有需确认时先确认。
- [ ] 分别展示400与390来源；蓝色高亮不是只打开文件第一页。
- [ ] 真实数量差异保留至补件完成；其他低影响项可适当演示忽略，余下提示无需逐条长讲。
- [ ] 修订译文后等待局部重算与预览完成，避免马上点下一写操作造成版本冲突。
- [ ] 应用推荐与Agent操作后重新读取最新状态；切「已处置」能看到处理记录。
- [ ] 补件后仍4个原件，B02是同Document v2；其他三份解析不丢失。
- [ ] 新矩阵与当前范围一致；草莓400、蓝莓200、合计600，总净4200/毛4520kg。
