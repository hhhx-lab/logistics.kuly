# 本地一键启动与停止

## 入口和实施约定

项目根目录提供 `一键启动.command`，macOS 双击后打开终端，也可执行 `./scripts/start-local.sh`。统一启动前端5173、API8000、documents/conversation/maintenance三个独立队列和运维监控；使用既有 `src/backend/.venv`、前端node_modules及根目录.env，不安装依赖、不拉取镜像、不输出Key、不调用模型/MinerU。

启动器在前台持续监督进程，Ctrl+C或关闭终端停止本次启动的应用进程；Worker采用暖停止，不强杀正在执行的任务。PostgreSQL/Redis/S3及启动前已有的应用进程保留。重复点击复用本项目已有应用进程；其他项目占用端口时报错，绝不杀占用者。锁文件阻止同一入口重复启动。子进程退出时停止本次其他进程，返回失败和日志位置。

依赖镜像必须已经存在；需要时仅通过 `docker compose up --pull never --no-build -d` 启动已有依赖容器，确认健康后再启动应用。全新应用启动时先执行Alembic迁移及LangGraph检查点初始化；存在旧API/Worker时只核对当前迁移版本，若落后则停止启动，要求先停止旧应用再执行启动，避免运行中迁移。启动后检查API就绪和前端HTTP响应；就绪仅证明依赖准备，不代表模型速度或业务流程已验收。

日志及进程记录存放在根目录 `.runtime/local/` 并加入Git忽略。不会把临时进程数据提交。Node优先使用现有Conda环境，其次使用既有PATH；只对本次启动的子进程补充命令路径，不修改用户全局PATH。Python始终使用项目.venv入口。

## 使用

```bash
./scripts/start-local.sh
```

就绪后打开 http://localhost:5173；API为 http://127.0.0.1:8000，日志在 `.runtime/local/`。脚本在macOS尝试打开默认浏览器；可用 `./scripts/start-local.sh --no-browser` 仅启动服务。开发种子账号demo/demo、demo2/demo；已有账号以当前部署为准。

停止首选在启动终端按Ctrl+C，或从另一个终端执行 `./scripts/start-local.sh stop`；后者仅给持有启动锁的监督进程发SIGTERM，由它清理自己启动的子进程，不停止复用服务。任务暖退出较慢时保留日志提示，不自动SIGKILL。已有手动启动服务应在原启动终端停止。
