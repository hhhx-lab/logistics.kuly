每组的原始PDF和DOCX是同一份单证的两种格式，**选其中一种上传**。不要把PDF和DOCX都当作独立新单证。第一轮用三份核心PDF；需要展示DOCX解析时，以对应DOCX替代同名PDF。

## 2. 第一组：顺畅交付演示

### 2.1 先核对，再翻译

1. 新建对话，上传A01、A02、A03。可以改用A01的扫描备选来展示OCR，但首次汇演建议先用原生PDF。
2. 在任务卡选择“同票核对”；确认同一货批`SHIP-DEMO-A-2026`、完整材料、同一海运阶段，明确卖方／发货人、买方／收货人与通知方的角色。
3. 核对三条SKU和批次：`SRV-400 / FR-SRV-2610`、`VLV-25 / FR-VLV-2610`、`SNS-T8 / FR-SNS-2610`。若自动匹配是候选，在“货物对应”里按这三个键确认，不按行号硬配。
4. 打开矩阵，展示原件值与人工采用值两条口径，点击数量或重量来源，观察准确定位与蓝色高亮。
5. 启动翻译校验，目标语言在列表选“中文”；展开左侧识别原文与右侧纯译文，展示横向商品表、纵向主体表、横线和三个页面的结构。
6. 处理实际出现的疑点，复核完成后导出译本DOCX／PDF和识别稿PDF。导出不包含复核报告。

建议话术：

> 这三份单证属于同一票货物。先只做同票核对，比较商品数量、外包装、批次、收发货人和运输路线，不要启动翻译。

> 把这票单据翻译成中文，保留表格、横线、分页和编号。商品件数与木箱数要区分；需要我确认的地方请说明。

### 2.2 @问答与连续追问

在管理台关联同票或成功导出快照，再问：

> 介绍一下这票货物：谁从哪里发给谁？三种货物各有多少，净重和毛重是多少？请附来源。

> 120件和12个木箱为什么不同？装箱明细是否把同一批货物计算了两遍？

> 发票上的52 500,00欧元怎么组成？请分别说明商品、运费和保险费。

商品总额为51500 EUR，运费900 EUR，保险100 EUR，应付52500 EUR。外包装附表分配的是同一批木箱，不能再加一次商品数量。

### 2.3 三语互译安排

三语源文件演示时，增加A04中文采购订单。按当前产品的实际交互，每个翻译Run选择一个目标语言：

- 中文Run：法语／英语材料 → 中文；中文采购单如选择翻译则保持中文含义。
- 英语Run：法语／中文材料 → 英语。
- 法语Run：英语／中文材料 → 法语。

可只选择需要翻译的文件，已有目标语材料留作核对。每种目标语言分别生成和导出，不在一个Run里用聊天文字假装同时配置多个目标语言。互译结果由模型实际执行，交付包内不放预生成译本冒充运行成果。

## 3. 第二组：差异发现、解释与补件演示

### 3.1 上传初版并确认比较边界

1. 新建独立对话／单票，只上传B01、B02初版、B03。不得与第一组混票。
2. 确认货批`SHIP-DEMO-B-2026`、完整材料、瓦伦西亚至上海同一海运阶段；确认草莓与蓝莓各自SKU／批次相配。
3. 查看同票对比和疑点。期望发现的事实是发票／提单草莓400箱，初版箱单390箱；蓝莓均200箱。风险项数量和颜色由真实规则决定，不预先写死界面一定出现几条红项。
4. 点击对应差异来源，展示原始400与390、总箱数600与590，以及重量的各自来源，不能只打开文件而不定位。

建议话术：

> 同票核对这些文件。它们是同一货批的完整材料，请按相同SKU和批次比较，不要把托盘数与箱数混在一起。

> 请说明草莓数量为什么对不上，列出各文件实际写的值、相关重量和建议核查的材料。先分析，不改原件，不自动忽略。

### 3.2 预置差异清单

| 项目 | 发票／提单／中文订单 | 初版装箱单 | 差额与来源位置 | 建议演示动作 |
| --- | --- | --- | --- | --- |
| 草莓`FRA-8`数量 | 400箱 | 390箱 | 少10箱；B01第2页、B02第2页、B03第2页 | 来源定位 → Agent分析 → 补件后重新核对 |
| 总商品箱数 | 600箱 | 590箱 | 少10箱；B02第2页汇总及第3页第08托盘分配 | 说明这是完整材料，不误当分批运输 |
| 草莓净重 | 3200 kg | 3120 kg | 少80 kg，与每箱8 kg相符 | 对比净重，不与毛重交叉比较 |
| 草莓毛重 | 3440 kg | 3354 kg | 少86 kg，与每箱8.6 kg相符 | 对比毛重，解释依赖数量的差异 |
| 总净重／毛重 | 4200／4520 kg | 4120／4434 kg | 少80／86 kg | 保留原件各自事实，不静默采用某一份 |
| 收货人邮箱 | `receiving@freshway-demo.example` | `receving@freshway-demo.example` | 初版漏一个`i`；B02第1页 | 通常需人工判断；不把可疑邮箱自动当作确认错误 |

温度设定+2 °C、现场记录+2.1 °C，均落在0 °C至+4 °C的产品要求内；这不是预置温度冲突。草莓每箱8 kg、蓝莓每箱5 kg，也不应该互判重量异常。

可以在译文中手动改善“托盘／箱／件”的表述，或者给Agent具体译文意见；未经证据不能把原件390直接改成400。邮件拼写也应先看其他原件或补件，不能仅凭模型猜测改成已核验事实。

### 3.3 展示五个疑点动作

- **修订译文**：只修译文措辞，原件事实继续保留。
- **忽略并记录**：可空理由，也可填“汇演测试：已人工判断，保留原件差异”。这只是人工处置，不表示原件相同。
- **Agent处理**：提出具体分析或局部译文修改意见；不授权它编造缺失的物流事实。
- **应用推荐修改**：先看实际建议与影响范围；没有可执行的推荐内容时不假造自动修改成功。
- **补充上传**：从“补件”目录上传B02修正版，明确它替换初版并对应同一货批。修正版修正数量、依赖重量和邮箱，不是额外增加400箱。

复核导出门禁只硬拦当前适用且未解决红项；黄项与无法判断继续作为提示保留。无译文、缺文件、版本过期等技术缺口仍必须修复。

补件后保存新范围／替换关系，并发起重新核对。旧Run、旧矩阵和旧快照保留历史结论；新核对使用修正版。不要同时把初版与修正版都纳入“当前有效的两份独立商品清单”。

## 5. 汇演前准备

1. 先以原生PDF排演，再使用扫描备选验证MinerU；文件上传和模型调用由真实服务运行，首次耗时包括队列、OCR与模型处理。
2. 确认网络、模型与MinerU配置可用，先登录并打开管理台；不得预录一份固定回复冒充现场完成。
3. 现场展示主线可只做第一组中文翻译与第二组差异定位；英语／法语／西语互译可在排演时完成，现场从真实历史记录展示不同目标语的导出结果。
4. 预置差异是真值，不保证模型或当前规则全部识别。未判断、待人工匹配及未覆盖规则要如实展示。
5. 本包已做文档级结构、页数与排版检查，未在制作阶段调用真实模型或MinerU，不能称为新样例的Agent验收报告。
